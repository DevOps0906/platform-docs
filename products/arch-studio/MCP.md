# Arch Studio MCP

공통 규칙 정본은 `../_platform-core/MCP_BASELINE.md`. 이 문서는 Arch Studio의 도구와 수치만 적는다. 표기: "제안"은 근거 문서에 없어 이 문서가 정한 값, "미확인"·"확인 필요"는 확인 전. 상태: **1차 초안(2026-10-23)**.

## 1. 노출 목적과 대상 에이전트

**결론: MVP에서는 원격 MCP를 열지 않는다. 노출하는 도구는 0개다.** 이 제품은 서버 API를 에이전트에 얹을 만한 제품이 아니라서, 억지로 도구를 만들지 않는다.

이유:

| # | 이유 | 근거 |
|---|---|---|
| 1 | 프로젝트·3D 모델·판정·도면·건축주 정보의 정본이 **데스크톱 로컬 SQLite**다. 서버에는 사용자가 클라우드 기능(렌더, 클라우드 검토, 공유)을 실행할 때 필요한 부분만 올라간다. 원격 MCP가 읽을 프로젝트 데이터가 서버에 거의 없다 | `README.md` 5절, `05_DATA_MODEL.md` 2.16절 |
| 2 | 서버에 남는 기능은 라이선스·결제·크레딧 AI 작업(렌더 3~5, 클라우드 검토 15, 제안서 10, STT)·업로드 서명이다. 모두 금전·자격에 닿거나(W2) 도면·모델 일부를 올리는 일이라 도구로 만들지 않는다 | `04_API.md` 2.1·2.2절 |
| 3 | 건축사의 의뢰 자료는 기밀일 수 있다. 도면·3D 원본, 건축주 연락처는 상용 AI 제공자로 보내지 않는다는 원칙이 이미 있다. 에이전트(외부 AI)에 프로젝트 내용을 넘기는 새 경로를 MVP에서 열지 않는다 | `01_PRD.md` 6장 국외 이전 범위, `05_DATA_MODEL.md` 2.17절 |
| 4 | 데스크톱이 Bearer로 서버를 부르는 경로 자체가 코어 요청 T-C1 반영 전에는 열리지 않는다("그 전까지 데스크톱은 Supabase 직접 조회 범위(RLS)만 쓴다"). 원격 MCP의 인증 선행 조건이 아직 없다 | `04_API.md` 1절 인증 행 |

**이 제품에서 에이전트가 의미 있게 읽을 수 있는 것은 "지금 열려 있는 프로젝트의 법규 판정 기록"** 정도이고, 이는 서버가 아니라 로컬에 있다. 그래서 **원격이 아니라 로컬(stdio) MCP가 맞는 모양**이다. 단 문서에 로컬 MCP 구성(앱 Rust가 겸할지, 별도 프로세스가 SQLite를 열지. `CLAUDE.md` 7절은 사이드카 동봉을 금지하므로 별도 프로세스를 번들에 넣는 방식은 이 금지와 충돌한다)이 없으므로 아래는 후보이고 결정은 8절에 둔다.

| 대상 | 시키는 일 | 단계 |
|---|---|---|
| 건축사·시공사 대표의 AI 비서(사용자 PC에서 도는 MCP 클라이언트) | "이 프로젝트 마지막 판정에서 FAIL이나 WARN이 뭐였는지", "프로젝트 목록과 수정일" | 후보(로컬 stdio, 미결정 D-M1) |
| 원격 에이전트 | - | MVP 없음. 필요가 생기면 `GET /api/rule-packs`(규칙 팩 버전·적용일·개정 제목)와 `GET /api/license/list`(라이선스 상태, 시리얼 끝 5자) 같은 계정 수준 읽기 2개만 검토(D-M2) |

**노출하지 않는 것:**

| 기능 | 이유 |
|---|---|
| 도면·3D 모델·시트 원본 읽기(`model_revisions.design_model`, `sheets`, `cloud_projects` 사본, 대지 경계 좌표) | 기밀 가능성이 가장 큰 자산. 좌표는 로그에도 남기지 않는 규칙(`01_PRD.md` 421행 근처, `04_API.md` 1절 로그 행) |
| 건축주 이름·연락처(`projects.client_name`, `client_contact`), 주소·PNU(`site_label`, `parcel.pnu`, `address_label`) | 로컬에만 두는 개인정보. 클라우드 사본에서도 제외 옵션이 기본 켜짐 |
| 렌더·클라우드 검토·제안서·의도 추출·STT 실행(`POST /api/ai/*`, `/api/voice/stt`) | 크레딧 선차감(`arch.start_ai_run`)과 도면·입력 업로드가 따른다. 준비 도구도 MVP에 만들지 않는다(예상 크레딧은 앱 화면이 보여 준다) |
| 라이선스 활성화·해제·갱신·시리얼 조회(`/api/license/activate`, `deactivate`, `refresh`), 결제(`/api/checkout`) | 자격·금전. 시리얼 전체는 발급 메일에만 있고 서버에도 해시와 끝 5자뿐이다 |
| 내보내기 파일 쓰기(DXF·PDF 등), 파일 시스템 접근 | 로컬 파일 쓰기는 앱 Rust `fs.rs`만 한다. 에이전트에게 경로 쓰기 권한을 주지 않는다 |
| 로컬 DB 직접 수정(`local_settings`, `license_store`) | 로컬 값이 권한을 정하지 않는다는 규칙(`05_DATA_MODEL.md` 2.16절). 읽기 도구도 이 표들을 열지 않는다 |
| 업데이트 설치, 규칙 팩 다운로드(`/api/updates/*`, `/api/rule-packs/{version}/download`) | 서명 URL을 주고 앱이 서명 검증 후 적용하는 흐름. 에이전트가 끼면 안 된다 |

## 2. 도구 목록

**MVP 노출 도구: 없음.** 아래 두 개는 로컬 stdio 후보이며 8절 D-M1이 결정되기 전에는 구현하지 않는다. 호출 대상은 앱 Rust의 `local_db_*` 명령(화면이 SQL을 쓰지 않고 이름 붙은 명령만 쓰는 구조, `02_ARCHITECTURE.md` 2.1절)이어야 하는데, 구체 명령 이름은 문서에 없다(**확인 필요**).

| 도구 | 등급 | 한 줄 설명 | 호출하는 것 | 출력 필드(허용 목록) | 제외 필드 | 단계 |
|---|---|---|---|---|---|---|
| `arch_local_list_projects` | R1(로컬) | 로컬 프로젝트 목록 | 로컬 SQLite `projects` 읽기. 명령 이름 확인 필요 | id, 프로젝트 이름, 수정 시각, 클라우드 사본 있음 여부(true/false) | `site_label`, `client_name`, `client_contact`, `cloud_project_id`, `cloud_version`, `deleted_at`이 있는 항목(휴지통) | 후보 |
| `arch_local_get_judgment_record` | R1(로컬) | 프로젝트의 마지막 판정 기록 | 로컬 SQLite `judgment_snapshots` 최신 1행의 `result`(JudgmentResult). 명령 이름 확인 필요. **현재 화면 판정이 아니다**(화면은 매번 재계산, 이 표는 내보내기·제안서·클라우드 검토 시점 기록) | rev, 기록 시각, rule_pack_version, application_date, engine_version, items(key, verdict, value, limit, unit, basis의 law·article·effective_from), pending_changes, "기록 시점 값이며 현재와 다를 수 있음·최종 확인은 설계자" 문구 | 프로젝트 이름 외 식별 정보(주소, PNU, 건축주), 대지 경계·모델·시트, `basis`의 `ordinance` 외 내부 값 | 후보 |

**만들지 않는 도구:** `arch_render_*`, `arch_review_*`, `arch_make_proposal`, `arch_activate_license`, `arch_checkout`, `arch_export_*`, `arch_write_file`, `arch_get_model`, `arch_get_site`, `arch_update_*`, `arch_delete_project`. 필요해지면 06장에 별도 작업으로 올리고 승인 흐름을 먼저 설계한다.

## 3. 인증과 scope

로컬 stdio 후보에는 OAuth가 없다. 신뢰 경계는 "사용자 PC에서 사용자가 직접 켠 MCP 클라이언트"다.

| scope(제안) | 도구 | 비고 |
|---|---|---|
| `arch:local:read` | `arch_local_list_projects`, `arch_local_get_judgment_record` | 앱 설정에서 사용자가 "에이전트 연결 허용"을 켠 경우에만 서버 프로세스가 뜬다. 기본 꺼짐(제안) |

- 전송은 stdio만. HTTP 리스너를 열지 않는다. 열어야 한다면 127.0.0.1에만 바인딩하고 Origin을 검사한다(M7).
- 이 프로세스에는 서버 키가 없다. `SUPABASE_SERVICE_ROLE_KEY`, LLM·fal 키, 서명 개인키는 데스크톱 번들에 두지 않는 규칙 그대로(`CLAUDE.md` 2절). 서버 호출도 하지 않는다.
- 라이선스 상태에 따른 허용 여부(체험 만료 후 열람 전용 상태에서 도구를 줄지)는 미결정이다. 단 로컬 값이 권한을 정하지 않으므로 허용 판정은 `license.rs`의 서명 파일 검증 결과를 따라야 한다. 8절 D-M4.
- 원격 후보(D-M2)가 생기면 사용자 세션으로만 읽고(`requireSession('arch')` 동일), 인증은 T-C1 반영 후다.

## 4. 제한값

| 항목 | 값 |
|---|---|
| 호출 레이트 리밋(로컬) | 60회/분(제안). 앱 안에서 세므로 서버 `rate_limit_hit`을 쓰지 않는다 |
| 응답 건수·크기 | 프로젝트 목록 최대 20건, 판정 항목은 `key` 9종 전부(최대 9건), 응답 8,000자(제안) |
| 동시 연결 | 1개(제안) |
| 로그 | 도구 입력·출력 본문, 좌표, 표제란 값을 로그에 남기지 않는다(`01_PRD.md` 로그 규칙). 호출 시각·도구 이름·결과 코드만 |
| 토큰 만료 | 해당 없음(로컬). 원격 후보는 접근 토큰 1시간 이하(제안) |

## 5. 제품 고유 위협

| # | 위협 | 대응 |
|---|---|---|
| MT1 | **의뢰 기밀 유출**: 도면·모델 좌표, 대지 주소·PNU, 건축주 이름·연락처가 에이전트(외부 AI)를 거쳐 AI 제공자로 감 | 해당 데이터는 어떤 도구에도 없다. 판정 기록도 식별 정보를 제외하고 값·조항만. 출력 스키마 테스트로 필드 고정. 로컬 도구는 기본 꺼짐 |
| MT2 | **로컬 서버 노출**: 같은 PC의 다른 프로그램·웹 페이지가 MCP 서버나 SQLite에 접근(DNS 리바인딩, 파일 직접 읽기) | stdio만 사용, HTTP 없음. 별도 프로세스가 `app_data_dir`의 SQLite를 직접 열면 "화면은 `local_db_*` 명령만" 원칙을 우회하므로 앱 Rust가 서버를 겸하는 쪽을 우선 검토(D-M1) |
| MT3 | **로컬 값으로 권한 판정**: 도구 출력(예: 라이선스 상태)을 근거로 기능을 열거나 닫는 코드가 생김 | 라이선스·플랜·크레딧 값은 도구에 두지 않는다. 판정 입력은 `license_store` 서명 파일뿐(`05_DATA_MODEL.md` 2.16절) |
| MT4 | **판정 결과의 오해**: 에이전트가 "법규에 적합합니다·허가 통과" 식으로 단정하거나 오래된 기록을 현재 값처럼 말함(`01_PRD.md` 6장 금지: 인허가 보장, 완전성 보장) | 출력에 기록 시점, 규칙 팩 버전, 적용일, "최종 확인은 설계자" 문구를 항상 넣는다. 평가셋에 단정 금지 문항 |
| MT5 | **프롬프트 인젝션**: 프로젝트 이름·메모·판정 `basis` 텍스트에 든 지시문 | 프로젝트 이름은 untrusted 표시 + 길이 제한. 쓰기 도구·파일 쓰기 도구가 없어 지시가 따라져도 피해가 제한됨 |
| MT6 | **도구로 크레딧 AI를 호출해 비용 발생** | 크레딧을 쓰는 도구가 없다. 원격 AI 경로(`/api/ai/*`)는 어떤 MCP 도구도 부르지 않는다 |
| MT7 | 에이전트가 사용자 몰래 데이터를 반복 열람(휴지통 포함) | 기본 꺼짐 + 켠 동안 앱에 표시. `deleted_at` 항목 제외 |
| MT8 | 도구 설명 변조(M5) | 설명은 소스 코드 상수, PR 리뷰 대상 |

## 6. 승인 흐름

해당 없음. 쓰기·준비 도구가 없다. 크레딧 AI 실행, 내보내기, 라이선스 변경은 모두 앱 화면에서 사람이 한다.

## 8. 미결정·확인 필요

| ID | 항목 | 상태 |
|---|---|---|
| D-M1 | **로컬이냐 원격이냐**: 로컬 stdio 후보(위 2개)를 만들지, 아예 만들지 않을지. 만든다면 앱 Rust가 서버를 겸할지(권장), 별도 프로세스가 SQLite를 읽을지(사이드카 동봉 금지와 SQLite 직접 접근 금지 원칙에 걸려 번들에는 넣을 수 없고, 사용자가 따로 설치하는 형태만 가능). 문서에 로컬 MCP 구성과 `local_db_*` 명령 이름이 없음 | 미결정, 확인 필요 |
| D-M2 | 원격 MCP를 언제 열지. 후보는 계정 수준 읽기 2개(`GET /api/rule-packs`, `GET /api/license/list`)뿐이고 가치가 작다. T-C1(Bearer 검증) 반영 후 재검토 | 미결정, 보류 |
