# 03 화면과 UX: Floria (website-floria)

작성일 2026-10-12. 공개 사이트(방문자)와 운영 콘솔(초대받은 운영자)로 나뉜다.

2026-10-13 개정: 방문자 AI 상담 위젯(텍스트·음성), 브랜드 지식 위키 화면, 콘솔 AI 화면, 디자인 시스템 항목(3.7절), 3D 히어로(4.8절)를 추가했다. **히어로는 사용자 결정(2026-10-13)으로 사진 중심에서 3D 온실 구조물로 바뀌었다**(`docs/products/_design-guide/HERO_3D.md:91`). 공개 사이트는 `DESIGN_PRINCIPLES.md` + `HERO_3D.md` + `REFERENCES.md` website-floria 절을 따르고, B2B 레퍼런스(Primer 등)는 운영 콘솔에만 쓴다(`docs/products/_design-guide/DESIGN_SYSTEM.md:53-55`).

## 2. 사용자 플로우

### 2.1 방문자의 문의 접수

| 단계 | 화면 | 사용자 행동 | 시스템 동작 | 실패 분기 |
|---|---|---|---|---|
| 1 | `/` 문의 CTA 또는 `/contact` | 종류 선택, 이름, 이메일, 내용, 동의 체크 | 폼 로드 시각 기록(작성 시간 측정), 허니팟 필드 숨김 렌더 | JS 비활성: 서버 렌더 폼이 `/api/inquiries`로 일반 POST(제안) |
| 2 | 같음 | 제출 | Route Handler: 본문 크기, Origin, Turnstile, IP 레이트 리밋 → `submit_inquiry` RPC | 429: "잠시 후 다시 시도해 주세요(N분 뒤)". CAPTCHA 실패: 위젯 재시도. 422: 필드별 오류 문구 |
| 3 | 같음 | 접수번호 확인 | 응답 `{ok, reference}` | 서버 오류(5xx): "접수하지 못했습니다. 입력한 내용은 그대로 있습니다. 다시 시도해 주세요." 입력을 지우지 않는다. 오류를 성공으로 위장하지 않는다 |
| 4 | 운영자 알림 | - | 워커가 1분 안에 알림 메일 | 메일 실패해도 콘솔에는 보인다(`notified_at` 이 비어 있어도 목록에 표시) |

### 2.2 뉴스레터 구독

| 단계 | 화면 | 사용자 행동 | 시스템 동작 | 실패 분기 |
|---|---|---|---|---|
| 1 | `/` Footer/CTA | 이메일 입력, 수신 동의 체크, 제출 | Route Handler → `subscribe_newsletter`. 응답은 항상 같은 문구 "확인 메일을 보냈습니다. 받은편지함을 확인해 주세요."(계정 열거 방지) | 429: 안내. 허니팟: 같은 성공 문구, 저장 안 함 |
| 2 | 이메일 | 확인 링크 클릭 | `/newsletter/confirm?t=<token>` 로드: 토큰 서명/만료 검증만 하고 버튼을 보인다 | 만료: "링크가 만료됐습니다. 다시 신청해 주세요."(메일 보안 스캐너가 GET으로 링크를 미리 열어도 구독이 확정되지 않도록 GET은 상태를 바꾸지 않는다) |
| 3 | 같음 | "구독 확인" 버튼 | `POST /api/newsletter/confirm` → `confirm_newsletter` | 이미 확정: "이미 확인된 구독입니다."(멱등) |
| 4 | 이메일 | 해지 링크 | `/newsletter/unsubscribe?t=` → 버튼 → `POST` → `unsubscribe_newsletter`. 메일 클라이언트의 원클릭 해지는 `List-Unsubscribe-Post` | 없는 구독: 같은 완료 문구 |

### 2.3 운영자 초대 → 첫 문의 처리 (가입 → 부트스트랩 → 첫 사용 플로우)

| 단계 | 화면 | 사용자 행동 | 시스템 동작 | 실패 분기 |
|---|---|---|---|---|
| 1 | 이메일 | 플랫폼 관리자가 보낸 초대 메일의 링크 클릭 | Auth Admin `inviteUserByEmail`(메타데이터 `signup_app=site`)로 만든 사용자. 가입 트리거가 프로필, 개인 조직, owner 멤버십을 만든다(invite 앱이라 엔타이틀먼트는 만들지 않고 운영자가 service_role로 `site` 엔타이틀먼트를 부트스트랩한다) | 만료된 초대: 관리자에게 재발송 요청 |
| 2 | `/admin/login` | 비밀번호 설정 후 로그인(Stage B. 초대받은 이메일과 같은 Google 계정으로도 로그인 가능. Stage A 로컬 개발은 개발용 패널의 페르소나) | `session_context('site')` 호출. 프로필이 없으면 로그아웃(기본 admin 금지) | `status='pending'/'suspended'`: 안내 페이지. 다른 이메일의 Google 계정: `/admin/no-access`(7절) |
| 3 | `/admin` | 최초 진입 | 조직에 등록된 사이트가 없으면 "등록된 사이트가 없습니다. 담당자가 사이트를 등록하면 문의가 여기에 표시됩니다." | 이 화면에 문의 폼이나 가입 링크는 없다 |
| 4 | 담당자 작업 | (플랫폼 관리자) `provision_site` 호출 | service_role RPC로 `sites` 행 생성, 감사 로그 | 엔타이틀먼트 없는 조직은 42501 |
| 5 | `/admin/inquiries` | 첫 문의 확인 | RLS로 자기 조직 문의만 조회 | 0건: "아직 접수된 문의가 없습니다. 사이트의 문의 폼 주소를 확인하세요." |
| 6 | 상세 | 상태를 "확인함" → "답변함"으로 변경, 메모 작성 | `set_inquiry_status` RPC, 감사 로그 | 허용되지 않는 전이: "이 상태에서는 변경할 수 없습니다."(22023) |

결제 단계는 없다(01_PRD.md 4장).

### 2.4 개인정보 삭제 요청 처리

| 단계 | 화면 | 사용자 행동 | 시스템 동작 | 실패 분기 |
|---|---|---|---|---|
| 1 | 이메일 접수 | 요청자가 삭제를 요청 | 운영자가 요청자 본인 확인(이메일 회신) | 본인 확인 실패: 처리하지 않고 기록 |

### 2.5 방문자 AI 상담 → 문의 전환 (2026-10-13)

| 단계 | 화면 | 사용자 행동 | 시스템 동작 | 실패 분기 |
|---|---|---|---|---|
| 1 | 아무 `(site)` 페이지 | 우하단 "상담" 버튼 클릭 | `GET /api/ai/config`가 스위치와 고지문 버전을 돌려주면 패널이 열리고 고지(AI가 답함, 개인정보 입력 금지, 처리방침 링크)를 보인다. 스위치가 꺼져 있으면 버튼 자체가 없다 | config 실패 → 버튼 숨김(문의 폼은 정상) |
| 2 | 패널 | "상담 시작" 확인 | Turnstile 통과 → `POST /api/ai/conversations` → 서명된 방문자 쿠키 발급, `core.ai_conversations` 행(`visitor_key`, `dify_user`) | CAPTCHA 실패·429 → "잠시 후 다시 시도해 주세요" + 문의 폼 링크 |
| 3 | 패널 | 질문 입력(300자) → 보내기 | 마스킹 → 레이트 리밋 5종 → Dify Chat API → HTTP 노드 `/tools/answer` → 그래프 `site.consult`. 그동안 "근거를 찾는 중" | 429 → 재시도 시각. 사이트 일일 상한 → "오늘 상담이 마감됐습니다. 문의를 남겨 주세요"(문의 버튼 강조) |
| 4 | 패널 | 답변 읽기, 출처 칩 열기 | `ai_messages` 2행(user 마스킹본, assistant + citations), `ai_usage` 기록 | 근거 없음 → "근거 자료를 찾지 못했습니다" + 문의 버튼. 모든 제공자 실패 → 오류 띠 + 문의 링크(성공으로 위장 금지) |
| 5 | 패널 | "이 내용으로 문의하기" | `inquiry_hint`(종류, 방문자 질문 요약 초안)를 브라우저 sessionStorage에 두고 `/contact?from=consult`로 이동. 폼이 종류와 내용 초안을 채워 보여 주고 방문자가 고친다. 자동 제출 없음 | 초안 없이도 이동 가능 |
| 6 | `/contact` | 이름, 이메일, 동의 체크 후 제출 | 2.1절과 같다(`source_path`는 `/consult`). 동의 체크, Turnstile, 허니팟, 레이트 리밋 그대로 | 2.1절 실패 분기와 같다 |
| 7 | 패널 | "대화 지우기" | `DELETE /api/ai/conversations/[id]`(Dify 대화 포함). 쿠키는 유지 | 실패 → 재시도 안내 |

### 2.7 운영자: AI 켜기 → 지식 게시 (2026-10-13)

| 단계 | 화면 | 사용자 행동 | 시스템 동작 | 실패 분기 |

### 4.4 레이아웃 후보와 선택

후보 A(채택): 비대칭. 제목이 장면 위로 걸쳐 내려오고, 장면은 오른쪽 가장자리로 잘려 나간다. 2026-10-13부터 오른쪽 구역은 사진이 아니라 3D 온실 구조물(PC·태블릿)이다. 아래 와이어프레임의 "[설치 작업 사진 ...]" 자리가 4.8절의 장면(모바일은 단순판, 대체는 정지 이미지)으로 바뀐다.

| Floria                       컬렉션  웨딩  프로세스  [문의하기] |
+--------------------------------------------------------------+
|                                    +-------------------------+|
|  공간에 서는                        |                         ||
|  식물 건축                          |   [설치 작업 사진         ||
|  Botanic                           |    화면 폭 58%,           ||

### 4.5 원칙과 대담함의 위치

| # | 원칙 |
|---|---|
| 1 | 히어로는 3D 온실 구조물이 주인공이고, 그 아래 Collections·Archive에서는 사진이 주인공이다. 장식 요소(그라디언트 워시, 블러 원)를 넣지 않는다. 원본의 `blur-[150px]` 조명 원(`CLAUDE.md` A절)은 제거한다. 3D에도 그라디언트·블룸·파티클을 쓰지 않는다 |
| 2 | 정보는 사실만. 증빙 없는 숫자, 후기, 평점은 렌더링하지 않는다 |

| 4 | 컬렉션 카드는 높이를 다르게 한다(세로형/정방형 혼합). 같은 둥근 카드를 반복하지 않고 반경은 사진 2px, 표면 12px처럼 위계로 다르게 한다 |

## 7. 운영자 로그인 화면의 인증 단계 (2026-10-14 추가, 확정 결정 22)

정본 `docs/products/_platform-core/AUTH_ROADMAP.md`. 로그인 화면은 운영 콘솔 `/admin/login` 하나다. 공개 사이트·상담 위젯·뉴스레터 화면은 단계와 무관하며 로그인 버튼을 추가하지 않는다.

### 7.1 `/admin/login` 단계별 구성

| 단계 | 구성 | 렌더 조건 |
|---|---|---|
| A Mock | "개발용 로그인" 패널: 페르소나 버튼 목록(05장 10절: 공통 + 사이트 등록 완료 `owner`·미완료 `site_pending`), 현재 로그인 페르소나, 로그아웃. 모든 화면(공개 사이트 포함) 상단에 고정 배지 `MOCK AUTH · 로컬 전용`. 실제 제공자 버튼은 렌더하지 않는다 | `isMockAuthAllowed()`가 참일 때만, 서버 컴포넌트에서 분기(`AUTH_ROADMAP.md` 2.4절). 거짓이면 패널 코드 자체가 없다 |
| B Google | "Google로 계속하기" 버튼(`prompt=select_account`) + 이메일·비밀번호 폼(초대 메일로 비밀번호를 설정한 운영자, 01장 D-20). 가입 링크·가입 폼 없음. 비밀번호 재설정 링크(초대받은 계정만 의미 있음) | `AUTH_PROVIDERS`에 `google`, `email` |
| C 카카오·네이버 | 제외(운영자 전용 콘솔). 버튼 없음 | - |

초대 메일 수락 화면(비밀번호 설정)은 B단계에서 만든다. A단계에서는 시드 계정이 이미 인증 완료 상태라 이 화면이 필요 없다(`AUTH_ROADMAP.md` 2.5절).

### 7.3 첫 로그인 뒤 약관 동의 위치

이 제품은 운영자 이용약관을 MVP에 두지 않는다(01장 6절 약관/고지 행). 그래서 첫 Google 로그인 뒤 별도 약관 단계를 만들지 않고, 첫 진입은 기존 2.3절 3단계(`/admin`)다. 운영자 이용약관이 생기면 그 동의 화면을 `/admin` 최초 진입 앞 첫 단계로 둔다(제안, `AUTH_ROADMAP.md` 5.2절 가입 화면 행).

"설정 → 로그인 방법"(계정 연결, `AUTH_ROADMAP.md` 7.3절)은 C단계 기능이라 이 제품에서는 만들지 않는다.
