# MCP_BASELINE: 에이전트 접근 층(MCP) 공통 기준

작성일 2026-10-23. 상태: **1차 초안**. 모든 제품이 따르는 공통 규칙이다. 제품별 도구 목록과 수치는 `products/<제품>/MCP.md`에 적고(틀: `MCP_PRODUCT_TEMPLATE.md`), 이 문서의 규칙을 반복해 쓰지 않는다. 표기: "제안"은 근거 문서에 없어 이 문서가 정한 값, "미확인"은 확인 전.

## 1. 원칙: API가 기본, MCP는 얹는 층

| 항목 | 규칙 |
|---|---|
| 관계 | MCP는 API를 대체하지 않는다. 기존 도메인 서버 계층(`src/server/<도메인>/`)과 DB RPC 위에 에이전트용 입구를 하나 더 둔다 |
| 단일 정본 | 비즈니스 규칙은 DB RPC·RLS·서버 계층에만 있다. MCP 도구는 이를 호출만 하고 규칙을 다시 구현하지 않는다 |
| 같은 권한 | 에이전트는 로그인한 사용자 본인 권한(또는 익명)으로만 동작한다. MCP 전용 우회 권한을 만들지 않는다 |
| 선택 노출 | 모든 API를 도구로 만들지 않는다. 에이전트가 쓸 가치가 있고 위험이 낮은 기능부터 3~5개 |
| 결정적 연동 | 결제, 정산, 정기 동기화처럼 결과가 정해진 처리는 MCP가 아니라 API·잡·n8n으로 직접 처리한다 |

```
사용자 화면 ────────────> 서버 계층 / Route Handler ──> DB RPC + RLS
AI 에이전트 ──> MCP 서버 ─┘ (같은 서버 계층 또는 같은 RPC)
```

## 2. 도구 위험 등급

| 등급 | 뜻 | 예 | MVP 노출 | 승인 |
|---|---|---|---|---|
| R0 | 공개 데이터 읽기(익명 가능) | 숙소 검색, 상세 | 노출 | 불필요 |
| R1 | 본인 데이터 읽기 | 내 예약, 내 찜 | 로그인 후 노출 | 불필요 |
| R2 | 조직(호스트) 데이터 읽기 | 호스트 예약함 | 로그인 + 역할 | 불필요 |
| W1 | 되돌리기 쉬운 쓰기 | 찜 토글 | Phase 2 | 사용자 확인 1회 |
| W2 | 금전·약속·외부 영향이 있는 쓰기 | 예약 요청, 예약 승인, 취소, 결제 | **도구로 직접 만들지 않는다**. "준비" 도구가 요약과 웹 링크를 주고, 확정은 사람이 웹 화면에서 한다 | 사람이 웹에서 확정 |
| A | 관리·삭제·권한 변경 | 계정 정지, 숙소 삭제 | 노출 금지 | - |

## 3. 도구 설계 규칙

| 항목 | 규칙 |
|---|---|
| 이름 | `<제품>_<동사>_<대상>` 소문자 snake_case. 예 `stay_search_listings` |
| 설명 | 모델이 읽는다. 무엇을 하는지, 언제 쓰는지, 쓰지 말아야 할 때, 입력 단위(날짜 형식, 통화)를 짧게 적는다. 설명에 지시문·외부 URL을 넣지 않는다 |
| 입력 | zod 허용 목록. 길이·범위 상한을 모두 둔다. 사용자 id·조직 id·역할은 입력으로 받지 않는다(토큰에서만) |
| 출력 | 필드 허용 목록(필요한 것만). 한 번에 최대 20건(제안), 문자열은 잘라 낸다. 내부 오류 원문·SQL·스택은 내지 않는다 |
| 구조화 | 사람이 읽는 요약 `content`와 기계가 읽는 `structuredContent`를 함께 준다(SDK 지원 여부는 구현 시 확인) |
| 주석 | `readOnlyHint`, `destructiveHint`, `idempotentHint`, `openWorldHint`를 정직하게 단다. 주석은 보안 수단이 아니라 힌트다 |
| 오류 | 도구 실행 오류는 `isError: true`와 `{ code, message }`. 코드는 각 제품 API 문서의 오류표를 따른다. 프로토콜 오류와 구분한다 |
| 멱등 | 쓰기 도구는 멱등 키를 받는다. 같은 키는 한 번만 실행한다 |
| 버전 | 도구 이름·입력을 깨는 변경은 새 이름으로 낸다. 옛 도구는 폐기 공지 후 제거 |

## 4. 인증과 권한

| 항목 | 규칙 |
|---|---|
| 전송 | 원격은 Streamable HTTP(HTTPS만). 로컬 개발은 stdio. 옛 SSE 전송은 새로 만들지 않는다(미확인: 최신 스펙 권고 재확인) |
| 익명 | R0 도구만. IP 레이트 리밋을 건다 |
| 로그인 | OAuth 2.1 + PKCE 기반 Bearer 토큰. MCP 서버는 리소스 서버이며 토큰의 audience가 자기 자신인지 검사한다. 받은 토큰을 다른 서비스에 그대로 넘기지 않는다(토큰 패스스루 금지). 단, 사용자 본인 DB 호출을 위해 같은 제품의 Supabase 세션을 쓰는 경우는 제품 `MCP.md`에 방식을 적는다 |
| 토큰 획득 | 미확인: Supabase Auth를 OAuth 서버로 쓸 수 있는 범위와 조건. 대안은 제품 Next.js의 OAuth 동의 화면. 구현 전에 스파이크로 확정 |
| scope | 도구 등급별 scope(`<제품>:read:public`, `read:me`, `host:read`, `write:*`). 토큰에 없는 scope의 도구는 목록에서 숨기고 호출도 거부 |
| DB 접근 | 요청 단위 사용자 세션 클라이언트만. **service_role을 MCP 경로에서 쓰지 않는다** |
| 조직 | 조직·역할은 세션과 DB 멤버십으로만 확정한다 |
| 만료 | 접근 토큰은 짧게(제안 1시간 이하). 취소(철회) 시 즉시 거부 |

## 5. 보안 규칙 (SECURITY_BASELINE 23장과 동일)

| # | 위험 | 규칙 |
|---|---|---|
| M1 | 간접 프롬프트 인젝션 | 도구 결과의 사용자 작성 텍스트(후기, 소개글, 메시지)는 신뢰하지 않는 자료다. `untrusted: true`로 표시하고 길이를 제한하며, 링크·HTML·지시문처럼 보이는 구간은 제거하거나 코드 블록으로 감싼다. 이것만으로 막힌다고 보지 않는다 |
| M2 | 혼란된 대리인, 과도한 권한 | 에이전트가 사용자 권한보다 넓은 일을 못 하게 한다. 쓰기는 2절의 등급 규칙을 따른다 |
| M3 | 민감 정보 유출 | 정확한 주소·좌표·연락처·결제 정보·토큰은 도구 출력에서 항상 제외한다(본인 것이어도 웹에서만 본다). 도구 출력 스키마 테스트로 강제 |
| M4 | 토큰 패스스루 | 4절 |
| M5 | 도구 설명 오염 | 도구 설명은 코드와 함께 버전 관리·리뷰한다. 동적 생성 금지 |
| M6 | 비용·남용 | 사용자·IP별 레이트 리밋, 일일 상한, 응답 크기 상한. AI 호출 도구는 기존 크레딧 규칙(`consume_credits`)을 따른다 |
| M7 | 로컬 서버 노출 | 로컬 HTTP 서버는 127.0.0.1에만 바인딩하고 Origin을 검사한다(DNS 리바인딩 방어) |
| M8 | 우리 에이전트가 쓰는 외부 MCP | 승인한 서버만 쓰고, 외부 서버의 도구 설명·결과도 신뢰하지 않는 자료로 다룬다. 내부 에이전트에 외부 서버를 붙이기 전에 목록을 문서에 적는다 |
| M9 | 감사 | 모든 인증된 도구 호출을 요청 id, 사용자, 도구 이름, 결과 코드로 기록한다. 입력 본문 전체는 기록하지 않는다. W1·W2 준비 도구는 DB 감사에도 남긴다 |

## 6. 사람 승인 흐름 (W1·W2)

1. 에이전트가 `<제품>_prepare_*` 도구를 호출한다. 서버는 규칙 검증(날짜, 가격, 가능 여부)만 하고 **아무것도 저장하지 않는다**.
2. 도구는 요약(숙소, 날짜, 금액 등)과 웹 확인 링크를 돌려준다. 링크는 로그인된 사용자 세션에서만 열리고 일회용·단기 만료(제안 15분)다.
3. 사용자가 웹 화면에서 내용을 보고 직접 확정한다. 확정 경로는 기존 서버 함수(`requestReservation` 등)다.
4. 에이전트가 "예약했다"고 단정하지 못하도록, 준비 도구 응답에 "확정 전" 상태를 명시한다.

## 7. 배치 옵션

| 옵션 | 내용 | 장점 | 단점 | 추천 |
|---|---|---|---|---|
| A | 제품 웹 앱 안 Route Handler `/api/mcp` | 배포 하나, 서버 계층 재사용 | 웹 배포와 수명 공유, 긴 연결에 부적합할 수 있음(미확인) | MVP 후보 |
| B | 별도 서비스 `apps/mcp` | 격리, 독립 배포·스케일, 키 분리 | 서버 계층 코드 중복 위험 → RPC만 호출하도록 제한 | **기본 추천** |
| C | 플랫폼 공용 MCP 게이트웨이 1개 | 인증·레이트 리밋 한 곳 | 제품별 도메인 지식이 한곳에 모임 | 제품 5개 이상에 도구가 생기면 검토 |

## 8. 린 검증 순서

1. 로컬 stdio 서버 + R0 읽기 도구 3~4개를 만든다. 코드 없이 먼저 MCP 클라이언트(Claude 등)에서 호출해 본다.
2. 도구 설명만 바꿔 가며 에이전트가 올바른 도구를 고르는지 평가셋 20문항으로 본다.
3. 내부 업무에 먼저 쓴다(예: 호스트 본인의 예약 현황 요약).
4. 외부 공개는 R0 + 레이트 리밋부터. 로그인·쓰기는 그 다음.
5. 호출 로그에서 쓰이는 도구만 남기고 나머지는 접는다.

## 9. 제품별 `MCP.md` 필수 항목

도구 표(이름, 등급, 호출하는 RPC/서버 함수, 출력 필드, 제외 필드), 인증 방식, scope 표, 제한값, 위협 시나리오, 승인 흐름, 평가셋, 미결정 목록. 틀은 `MCP_PRODUCT_TEMPLATE.md`.

## 10. 미확인

- 최신 MCP 스펙의 인증 요구사항 세부(리소스 지시자, 동적 클라이언트 등록)
- Supabase Auth OAuth 서버 기능의 범위와 요금
- 도구 출력 `structuredContent`와 `outputSchema`를 지원하는 클라이언트 범위
