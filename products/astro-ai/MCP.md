# 신비로운AI(astro-ai) MCP

공통 규칙 정본은 `../_platform-core/MCP_BASELINE.md`. 이 문서는 신비로운AI의 도구와 수치만 적는다. 표기: "제안"은 근거 문서에 없어 이 문서가 정한 값, "미확인"은 확인 전, "확인 필요"는 기존 문서에서 정확한 이름을 찾지 못한 것. 상태: **1차 초안(2026-10-23)**

## 1. 노출 목적과 대상 에이전트

이 제품의 데이터는 생년월일시, 가족·지인의 정보, 리딩 본문, 질문, 결제 내역이라 **에이전트에 내줄 것이 거의 없다**(`SECURITY.md` 1절 민감도 높음). 그래서 MVP 도구는 공개 정보(테마, 사주 용어 위키)와 "내 리딩이 어디까지 됐는지, 잔액이 얼마인지" 정도로 짧게 둔다. 도구 출력은 사용자가 쓰는 AI 에이전트(외부 서비스일 수 있음)의 모델 제공자에게도 넘어가므로, 생년월일시·원국·리딩 본문·질문은 본인 것이어도 도구로 내보내지 않는다(`SECURITY.md` T8, `CLAUDE.md` 2절 "AI 입력" 규칙과 같은 방향).

| 대상 | 시키는 일 | 단계 |
|---|---|---|
| 방문자의 AI 비서 | "PDF 테마 종류 알려줘", "십신이 뭐야" 같은 공개 정보 확인 | MVP(익명 읽기) |
| 회원의 AI 비서(로그인) | "내 리딩 만들어지고 있어?", "크레딧 얼마 남았지?" | Phase 1.5 |
| 회원의 AI 비서(로그인) | "사주 리딩 하나 만들고 싶어" → 비용 안내와 웹 링크(**준비만**, 저장·차감 없음) | Phase 1.5 |

**노출하지 않는 것:** 보관함(대상 목록, 호칭, 생년월일시, 원국), 리딩 본문·질문·타로 카드, PDF·낭독 다운로드 URL, 리딩 생성·재렌더·취소·삭제, 보관함 생성·수정·삭제, 크레딧 결제·환불, AI 채팅·음성(크레딧 소비), Live Demo, 계정 내보내기·탈퇴, 어드민 전부. 이유: 개인정보 유출, 크레딧(돈) 소비, 삭제, 계정 처리는 사람이 웹에서만 한다(`MCP_BASELINE.md` 2·6절). 보관함 호칭(`alias`)도 실명일 수 있어 목록 도구를 만들지 않는다(실제 사용 양상은 미확인).

**운세 해석의 성격:** 위키·리딩 설명은 오락·참고용 해설이다. 도구가 돌려주는 위키 문서에는 "AI가 정리하고 운영자가 검수한 참고용 문서" 문구를 필드로 함께 준다(`03_SCREENS_UX.md` 위키 페이지 행, `01_PRD.md` 금지 표현). 에이전트가 사실이나 예언처럼 단정하지 않게 하는 것은 도구 설명과 평가셋으로 확인한다.

## 2. 도구 목록

기존 Route Handler와 RLS 읽기를 그대로 쓴다. 이 제품에는 읽기 전용 제품 RPC가 없다(`04_API.md` 3절 RPC는 `cancel_reading`, `claim_due_deliveries`, `finish_delivery`뿐). 아래 "호출하는 것"은 04장·05장에 있는 이름만 적었다.

| 도구 | 등급 | 한 줄 설명 | 호출하는 RPC/서버 함수 | 출력 필드(허용 목록) | 제외 필드 | 단계 |
|---|---|---|---|---|---|---|
| `astro_list_themes` | R0 | 선택 가능한 PDF 테마 목록 | `astro.themes` 읽기(RLS `is_active`, anon select 허용, `05_DATA_MODEL.md` 4절). 전용 RPC 없음 | key, name, tier, 미리보기 이미지 URL | `config`(색·서체 설정 JSON), `sort_order`, 비활성 테마 | MVP |
| `astro_get_wiki_page` | R0 | 공개된 사주 용어 위키 페이지 1건 읽기 | **확인 필요**: 공개 위키는 서버 컴포넌트가 `core.wiki_pages`(`published`)를 service_role로 읽는다(`04_API.md` 2.1절 하단). MCP 경로는 service_role을 못 쓰므로 읽기 전용 공개 RPC가 먼저 필요(8절 D-M3) | slug, 제목, 요약, 본문(잘라냄, untrusted 표시), 출처 문서 제목, "AI가 정리하고 운영자가 검수한 참고용 문서" 문구, 웹 링크 | 초안·보관 페이지, 편집 이력(`wiki_revisions`), 편집자 id, 운영자 조직 id | 1.5(D-M3 해결 후) |
| `astro_list_my_readings` | R1 | 내 리딩 진행 상태 목록 | `astro.readings` 읽기(사용자 세션 RLS, 컬럼 권한으로 `question_ciphertext`, `key_version`, `credit_ledger_id` 제외, `05_DATA_MODEL.md` 4절). 목록용 Route Handler는 04장에 없음(확인 필요, D-M4) | id, kind(saju/tarot/combined), 테마 key, status, progress, credits_charged, 생성·완료 시각, 웹 링크 | `subject_id`, 대상 호칭, `chart`, `content`, `tarot_cards`, `error_message` 원문, `job_id`, org id | 1.5 |
| `astro_get_reading_status` | R1 | 리딩 1건의 생성·렌더·발송 상태 | `GET /api/readings/[id]`(`04_API.md` 2절. 응답 중 상태 필드만 투영) | status, progress, 현재 렌더 상태(queued/running/done 등), 발송 상태, 오류 코드(`AS###` 등), 웹 링크 | 리딩 본문, 원국, 질문, 타로 카드, 다운로드 URL, 발송 이메일 주소, `error_message` 원문 | 1.5 |
| `astro_get_credit_balance` | R1 | 내 크레딧 잔액 | **확인 필요**: 대시보드는 `credit_balances`를 읽는다(`03_SCREENS_UX.md` 3절 홈 행). 04·05장에 정의가 없고 코어 정의 확인 필요(D-M5) | balance(정수) | 원장 행, 결제 내역, 주문·결제키, 지급 사유 | 1.5 |
| `astro_prepare_reading` | 준비(저장 안 함) | 리딩 종류·테마로 비용과 가능 여부를 계산하고 웹 링크를 준다 | 읽기만: `session_context('astro')`의 `features.readings`, `astro.themes`, 단가 `src/server/pricing.ts`(15/20/30), 잔액 읽기, 진행 중 3건 상한 확인. **`POST /api/readings`와 `consume_credits`는 호출하지 않는다** | 가능 여부, 종류, 비용(크레딧), 차감 후 예상 잔액, 사유 코드(`CR001`, 409 진행 중 3건, 403 종류 불허), "확정 전·크레딧은 아직 차감되지 않음" 문구, 웹 링크(일회용, 15분, 제안) | 대상 선택·생년월일시·질문 입력(**입력으로도 받지 않는다**), 보관함 정보 | 1.5 |

**만들지 않는 도구:** `astro_create_reading`, `astro_cancel_reading`, `astro_delete_reading`, `astro_regenerate_render`, `astro_get_download_url`, `astro_*_subject`(보관함 조회·생성·수정·삭제), `astro_get_chart`, `astro_ask_ai`·`astro_voice_*`·`astro_narrate`(크레딧 소비 AI), `astro_buy_credits`, `astro_refund`, `astro_demo_preview`(생년월일 입력을 받는 공개 경로), `astro_export_account`, `astro_delete_account`, `astro_admin_*`. 필요해지면 06장에 별도 작업으로 올리고 승인 흐름부터 설계한다.

## 3. 인증과 scope

| scope | 도구 | 비고 |
|---|---|---|
| (없음, 익명) | `astro_list_themes`, `astro_get_wiki_page` | anon 키. IP 레이트 리밋 |
| `astro:read:me` | `astro_list_my_readings`, `astro_get_reading_status`, `astro_get_credit_balance`, `astro_prepare_reading` | 사용자 세션 필요. 엔타이틀먼트(`astro`) 없으면 402 |

- DB 호출은 사용자 본인의 Supabase 접근 토큰으로 만든 요청 단위 클라이언트만 쓴다. MCP 서비스 환경에 `SUPABASE_SERVICE_ROLE_KEY`, `ASTRO_PII_KEY_V<n>`(암호화 키), `AI_TOKEN_PRIVATE_KEY`, Toss·Resend·LLM 키를 두지 않는다(`CLAUDE.md` 2절).
- `GET /api/readings/[id]`는 `requireSession('astro')`를 쓰는 Route Handler라서 MCP가 어떻게 같은 세션 검증을 거치게 할지(토큰 형식, 쿠키 세션과의 차이)는 **미결정**이다(8절 D-M1, D-M2).
- 개발용 `/api/dev/login`(Stage A Mock)은 MCP 경로에서 쓰지 않는다. 운영 빌드에서는 404다(`SECURITY.md` 7절).

## 4. 제한값

| 항목 | 값 |
|---|---|
| 익명 IP 레이트 리밋 | 30회/분(제안). 키는 `astro:mcp:<ip_hash>`, 원문 IP 저장 금지(기존 `ip_hash` 규칙) |
| 사용자 레이트 리밋 | 30회/분(제안). 준비 도구는 10회/분(제안) |
| 응답 최대 건수·문자 수 | 목록 20건, 위키 본문 1,500자, 요약 200자, 테마 이름 40자(모두 제안) |
| 토큰 만료 | 접근 토큰 1시간 이하(제안) |
| 준비 링크 만료 | 15분, 일회용(제안) |
| 크레딧 소비 | 0. MVP 도구 중 크레딧을 쓰는 것이 없다. 크레딧이 드는 기능(리딩 15/20/30, 채팅 선차감 3, 음성, 낭독 등)은 웹에서만 |

## 5. 제품 고유 위협

| # | 위협 | 대응 |
|---|---|---|
| MT1 | **생년월일시·원국·리딩 본문이 에이전트 대화에 실려 외부 AI 제공자로 넘어감**(`SECURITY.md` T1, T8의 확장. 국외 이전 동의 구조와 별개 경로) | 어떤 도구도 이 필드를 내지 않고 입력으로도 받지 않는다. 출력 스키마 테스트로 필드 목록 고정. 사용자가 에이전트에 직접 입력하는 것은 막을 수 없으므로 도구 설명과 웹 안내에 "생년월일은 에이전트에 입력하지 마세요"를 둔다(문구 법무 확인) |
| MT2 | **위키·리딩 텍스트 속 지시문**이 도구 결과로 에이전트에 들어감(`SECURITY.md` T7 확장. 위키는 AI 초안을 운영자가 게시한 문서, `04_API.md` 2.1절) | 위키 본문 `untrusted` 표시, 길이 제한, 링크·HTML 제거. 리딩 본문은 애초에 도구에 없음. 도구 결과에 크레딧을 쓰는 도구가 없어 지시가 따라져도 비용 피해가 없음 |
| MT3 | **에이전트가 크레딧 소비를 유도**(리딩 생성, 채팅, 낭독, 결제) | 크레딧을 쓰는 도구를 만들지 않는다. 준비 도구는 비용만 안내하고 확정은 사람이 웹에서 한다(`POST /api/readings`는 기존 `request_id` 멱등 경로 그대로) |
| MT4 | **운세를 사실처럼 단정**(에이전트가 "올해 큰 일이 생긴다"고 말함) | 위키 출력에 참고용 문구 필드를 항상 포함. 평가셋에 단정 금지 문항(7절). 01장 금지 표현(의료·금융 단정, 허위 수치)은 서비스 문구 기준이며 외부 에이전트 발화는 통제 불가(미확인) |
| MT5 | **PDF·낭독 서명 URL 유출**(`SECURITY.md` T3) | 다운로드 URL 도구 없음. 상태 도구의 웹 링크는 로그인 필요한 화면 주소이며 서명 URL이 아니다 |
| MT6 | **가족·지인(제3자) 정보와 미성년 정보 노출**(`SECURITY.md` T2, 5절) | 보관함 관련 필드·도구 없음. 리딩 목록에서도 `subject_id`와 호칭을 뺀다. 미성년 처리의 법적 기준은 미확인(법무) |
| MT7 | **다른 조직 리딩·잔액 조회** | 조직 id를 입력으로 받지 않고 세션 조직만 쓴다(`04_API.md` 1절). 사용자 세션 RLS가 최종 방어선. `outsider` 페르소나 회귀 테스트(`05_DATA_MODEL.md` 10절) |
| MT8 | **익명 도구로 크롤링·비용 유발**(위키 대량 수집) | 익명 IP 레이트 리밋, 일일 상한(제안). 도구는 LLM을 호출하지 않아 비용은 DB 읽기뿐 |

## 6. 승인 흐름 (`astro_prepare_reading`)

```
에이전트 → astro_prepare_reading(kind, theme_key)
        ← 가능 여부, 비용(예: 사주 15), 차감 후 예상 잔액, "확정 전·크레딧 차감 안 됨", 웹 링크(15분, 일회용)
사용자 → 링크로 /dashboard/readings/new 열기(로그인) → 대상 선택, 질문, 테마 확인 → 확인 버튼(크레딧 수 표시)
웹     → POST /api/readings (request_id 멱등, consume_credits) — 기존 경로 그대로
```

준비 도구는 DB에 쓰지 않고 `rate_limit_hit` 외에 어떤 상태도 바꾸지 않는다. 링크는 종류·테마만 담고 대상·생년월일시·질문은 담지 않는다(화면 URL 쿼리로 미리 채우는 방식 자체가 새 기능이므로 제안, D-M6). 에이전트가 "리딩을 만들었다"고 말하지 못하도록 응답에 "확정 전" 상태를 명시한다.

## 10. 테스트 체크리스트

- [ ] 모든 도구 출력에 제외 필드(생년월일시, 원국, 리딩 본문, 질문, 타로 카드, 호칭, 다운로드 URL, 이메일, org id)가 없다(스키마 테스트)
- [ ] 다른 사용자·다른 조직의 리딩·잔액을 도구로 읽을 수 없다(`outsider` 페르소나, `pnpm test:rls` 확장)
- [ ] 토큰 없는 호출은 익명 도구만 된다
- [ ] 레이트 리밋과 응답 크기 상한이 동작한다
- [ ] 쓰기 도구가 없고, `astro_prepare_reading`이 DB에 아무것도 쓰지 않으며 크레딧 원장이 변하지 않는다
- [ ] 위키 속 지시문 평가셋에서 지시를 따르지 않는다
- [ ] 위키 출력에 참고용 문구가 항상 있다
- [ ] 이 서비스 환경에 service_role 키, PII 암호화 키, AI 서명 개인키가 없다
- [ ] 도구 설명이 코드와 함께 버전 관리된다
