# Admin Suite(ERP·HMS·SMS) SECURITY

공통 규칙 정본은 `../_platform-core/SECURITY_BASELINE.md`(1~22장). 이 문서는 이 제품의 수치와 고유 위험만 적는다. 표기: "제안"은 근거 문서에 없어 이 문서가 정한 값, "미확인"은 확인 전. 상태: **1차 초안(2026-10-23)**

기관 운영 도구(ERP), 병원 업무(HMS), 학교 업무(SMS)를 공유 코어로 만든 제품이라, 위험은 "의료·학생 정보", "기관 간 데이터 분리", "역할 권한", "AI의 민감 데이터 처리"에 모인다.

## 1. 지켜야 할 자산

| 자산 | 종류 | 저장 위치 | 민감도 |
|---|---|---|---|
| 환자 정보·진료기록·검사 결과(HMS) | 의료 정보(고민감) | `hms` 스키마 | 매우 높음 |
| 학생 정보·출석·성적(SMS) | 개인정보(미성년) | `sms` 스키마 | 높음 |
| 직원·재고·거래(ERP) | 영업/개인정보 | `erp` 스키마 | 중간~높음 |
| 접근 기록(HMS) | 감사 증빙 | 접근 기록 테이블 | 높음 |
| 사내 규정·매뉴얼 문서(RAG) | 콘텐츠 | Storage/`ai_chunks` | 중간 |
| 초대·가입 코드 | 인증 | 초대 행, 가입 코드 | 중간 |

## 2. 위협 시나리오

| # | 누가 | 무엇을 | 어떻게 | 영향 | 대응 |
|---|---|---|---|---|---|
| T1 | 다른 기관 사용자 | 타 기관 데이터 조회 | org_id 우회, API 조작 | 기관 간 유출 | RLS + (id, org_id, app_id) 복합 외래키(§16), RLS 스모크 테스트 `outsider` 페르소나 |
| T2 | 내부 직원 | 권한 밖 환자·학생 조회 | URL 직접 입력, 역할 상승 | 의료·미성년 정보 노출 | `defineAccess` 매트릭스 + 서버 가드, 클라이언트 PageGuard 단독 금지(§11), `lab_tech`가 `/patients` 직접 입력 시 차단 테스트 |
| T3 | 내부 직원 | 환자 기록 열람 은폐 | 접근 기록 우회 | 감사 불가 | HMS 접근 기록 필수(조회 포함), 변경 불가 로그 |

| T5 | 외부 | 의료 데이터를 상용 AI로 전송 | AI 어시스턴트 입력 | 의료정보 국외 유출 | HMS는 전용 서버(`hms-llm`, `hms-embed`, `hms-voice`)만, 환자 정보는 AI에 넣지 않음(01_PRD), 상용 대체 금지(§16) |

## 4. 외부 서비스와 데이터 이전

| 서비스 | 보내는 데이터 | 비고 |
|---|---|---|
| Supabase | 기관 데이터 전체 | HMS는 전용 인스턴스/격리 여부 미결정 |
| 전용 AI 서버(HMS) | 매뉴얼 질의(환자 정보 제외) | `hms-llm`, `hms-embed`, `hms-voice` |
| Dify·상용 AI(ERP·SMS) | 사내 규정 질의 | 국외 이전 동의 필요 |
| Toss(Phase 2) | 구독 결제 | 계약형 수동 엔타이틀먼트 제안 |
| 이메일 초대 | 이메일 주소 | Auth Admin 초대 |

## 5. 이 제품에만 있는 위험

- **HMS는 의료 데이터 전용 보안 수준**이 필요하다: 전용 AI 서버, 접근 기록, 별도 보존 기간, 모놀리스 강제(공통 §12).
- **SMS는 미성년자 정보:** 학교 승인과 법정대리인 동의 절차가 선행되어야 하고, 학생용 AI는 Phase 2.
- **세 앱이 코어를 공유:** 코어 변경은 전 앱 RLS/RPC 회귀 통과 후 적용(§13).
