# Admin Suite(ERP·HMS·SMS) MCP

공통 규칙 정본은 `../_platform-core/MCP_BASELINE.md`. 이 문서는 Admin Suite의 도구와 수치만 적는다. 표기: "제안"은 근거 문서에 없어 이 문서가 정한 값, "미확인"은 확인 전, "확인 필요"는 문서에서 정확한 이름·내용을 찾지 못한 것. 상태: **1차 초안(2026-10-23)**

## 1. 노출 목적과 대상 에이전트

Admin Suite는 기관 내부 직원만 쓰는 운영 도구다. 공개 데이터가 없고(익명 R0 도구 없음), 데이터 대부분이 의료·미성년 학생·직원·거래 정보다. 그래서 **MVP에서는 에이전트에 아무것도 노출하지 않는다.** 이유 세 가지다.

1. 제품 자체의 AI 어시스턴트가 이미 "규정·매뉴얼 문서 기반 답변만" 하도록 설계됐다. ERP는 "재고·판매 수치를 답하지 않는다(DB 질의는 Phase 2)", SMS는 "학생 개인 정보와 출석 수치는 답하지 않는다"(`01_PRD.md` ERP-F-015, SMS-F-012). 수치를 에이전트로 여는 일은 이 결정을 바꾸는 것이라 사람이 먼저 정해야 한다(D-M1).
2. HMS는 의료정보 격리 결정(확정 결정 2)과 전용 서버만 쓴다는 결정이 있다. 외부 에이전트가 붙는 입구는 이 격리와 맞지 않는다.
3. SMS는 미성년자 정보라 학교 승인과 법정대리인 동의 확인(D-16)이 선행이다.

Phase 2 후보로 **집계 수치만** 읽는 도구 3개를 둔다. 개인·환자·학생을 식별하는 행은 어떤 도구에도 나오지 않는다.

| 대상 | 시키는 일 | 단계 |
|---|---|---|
| ERP 마스터 관리자·판매 관리자의 AI 비서 | "이번 달 판매 추이 요약", 대시보드 지표 요약 | Phase 2 후보(D-M1 승인 후) |
| SMS 관리자·교사의 AI 비서 | 오늘 출석 통계(출석률, 미체크 수) 요약 | Phase 2 후보(D-M1, D-16 확인 후) |
| HMS 직원 | (없음) | **노출하지 않음**: 환자·차트·검사·수납 전부 |

**노출하지 않는 것:** HMS 전 기능, 환자·학생·직원 개인정보 행(`search_patients`, `get_patient_detail`, `get_patient_chart`, `list_lab_worklist`, 직원 디렉토리, 학생 목록), 가입 코드 조회·재발급(`erp.get_join_code`, `rotate_join_code`), 가입 승인·거절(`erp.decide_join_request`), 역할·상태 변경(`erp.set_employee_role`, `set_employee_status`, `sms.set_member_role`, `set_member_status`), 초대 발송, 판매 등록·완료·취소와 입출고(`erp.record_sale`, `complete_sale`, `cancel_sale`, `record_inventory_move`), 출석 기록(`sms.mark_attendance*`), 수납·환불(`record_charge`, `settle_charge`, `refund_charge`), 구독 결제(`/api/billing/*`), 접근 기록 CSV, AI 대화·지식 문서·위키 관리 경로(`/api/ai/*`, `/api/voice/*`). 위 중 계정·권한·삭제·환불은 등급 A 또는 W2라 준비 도구도 만들지 않는다. 판매 등록 같은 W1·W2성 쓰기는 이 제품 MVP 가치가 낮고 재고·금액에 직접 닿으므로 준비 도구 없이 제외한다.

## 2. 도구 목록

모든 도구는 기존 RPC를 사용자 세션으로 그대로 호출한다. 역할 판정은 RPC 안에서 DB가 한다(`04_API.md` 1절 2차 검사, 3절). 도구 이름은 `admin_<앱>_<동사>_<대상>`(제안).

| 도구 | 등급 | 한 줄 설명 | 호출하는 RPC | 출력 필드(허용 목록) | 제외 필드 | 단계 |
|---|---|---|---|---|---|---|
| `admin_erp_get_dashboard_metrics` | R2 | ERP 대시보드 집계 지표 | `erp.dashboard_metrics(p_org_id)`(모놀리스는 `public.*`) | 집계 숫자만. 필드명은 확인 필요(반환이 jsonb이고 키 목록이 04장에 없음) | 상품별 원가·단가 행, 직원 이름·전화, 조직 id, 고객 정보 | Phase 2 후보 |
| `admin_erp_get_sales_trend` | R2 | 기간별 판매 추이 | `erp.sales_trend(p_org_id, p_from, p_to, p_bucket)` | 버킷 시작일, 건수, 금액(KRW) 합계 | 개별 판매 행, 판매자 id, 상품별 단가, 조직 id | Phase 2 후보 |
| `admin_sms_get_dashboard_stats` | R2 | 학교 출석 통계(하루) | `sms.dashboard_stats(p_org_id, p_date)` | 출석률, 정시 출석률, 미체크 수(학급별 같은 정의, `01_PRD.md` SMS-F-008) | 학생 이름·번호·id, 학급 구성원 목록, 보호자 정보, 조직 id | Phase 2 후보 |

`p_org_id`는 도구 입력이 아니다. 토큰이 아니라 **세션과 DB 멤버십**으로 확정한 기관 조직 id를 서버가 채운다. `sms.attendance_trend`는 위 3개와 같은 성격이지만 학급 단위 필터(`p_class_id`) 때문에 이번 초안에서는 뺐다(필요하면 D-M5).

**만들지 않는 도구:** HMS 도구 전부, 위 1절의 "노출하지 않는 것" 전부. 이름으로는 `admin_*_create_*`, `admin_*_update_*`, `admin_*_delete_*`, `admin_*_set_role`, `admin_*_approve_*`, `admin_*_invite_*`, `admin_hms_*`는 만들지 않는다. 필요해지면 06장에 별도 작업으로 올리고 승인 흐름을 먼저 설계한다.

## 3. 인증과 scope

| scope | 도구 | 비고 |
|---|---|---|
| (익명 없음) | - | 이 제품은 R0 도구가 없다 |
| `admin:erp:read` | `admin_erp_get_dashboard_metrics`, `admin_erp_get_sales_trend` | 기관 조직의 ERP 멤버. 판매 추이는 DB가 master_admin·sales_manager만 허용 |
| `admin:sms:read` | `admin_sms_get_dashboard_stats` | SMS admin·teacher만(DB 판정). student 토큰에는 발급하지 않음 |
| (HMS scope 없음) | - | HMS 앱에는 MCP 서버를 두지 않는다 |

- DB 호출은 **사용자 본인 세션으로 만든 요청 단위 클라이언트**만 쓴다. service_role은 이 경로에서 쓰지 않는다(`CLAUDE.md` 2절). 앱별 DB가 다르므로(ERP·SMS·HMS는 각각 별도 인스턴스 가능, `SECURITY.md` 6절) MCP 서버도 앱별로 분리한다.
- 세션은 Mock 인증(Stage A)에서도 실제 Supabase JWT다. 에이전트용 토큰에도 Mock 허용 판정을 새로 만들지 않는다. `/api/dev/login`과 같은 개발용 우회를 MCP 경로에 두지 않는다(`SECURITY.md` T7).
- 토큰 획득 방식(OAuth 동의 화면, audience)은 **미결정**이다(D-M2). 토큰에 역할을 넣지 않는다. 역할은 매 호출마다 DB `my_role`로 확인한다(`04_API.md` 1절 서명 토큰 규칙과 동일한 방향).
- 2단계 인증이 필수인 역할(관리자 등, `SECURITY.md` 3절)은 에이전트 토큰 발급 시에도 2단계 인증을 거친 세션이어야 한다(제안).

## 4. 제한값

| 항목 | 값 |
|---|---|
| 익명 IP 레이트 리밋 | 해당 없음(익명 불가) |
| 사용자 레이트 리밋 | 20회/분(제안). 키 `admin:mcp:<app>:<user_id>`, 기존 `rate_limit_hit` 규칙(`04_API.md` 1절)을 따름 |
| 응답 최대 건수·문자 수 | 추이 버킷 최대 366개(RPC 상한과 동일), 응답 본문 8,000자(제안) |
| 기간 범위 | 판매 추이는 플랜 `sales_trend_days`(기본 31일, 표준 366일) 이하. 플랜 한도 검사는 기존 Route Handler에 있으므로 MCP 경로에서도 같은 값을 적용해야 함(확인 필요: RPC 자체가 플랜 한도를 검사하는지) |
| 토큰 만료 | 접근 토큰 30분 이하(제안). 철회 시 즉시 거부 |
| 캐시 | 응답에 `private, no-store` 취급(`04_API.md` 1절) |

## 5. 제품 고유 위협

| # | 위협 | 대응 |
|---|---|---|
| MT1 | **다른 기관 수치 조회:** 에이전트가 조직 id를 바꿔 호출 (`SECURITY.md` T1) | 조직 id를 입력으로 받지 않는다. 세션의 기관 멤버십으로만 확정. RLS 스모크 `outsider` 페르소나를 MCP 경로에도 적용 |
| MT2 | **역할보다 넓은 수치:** `erp.dashboard_metrics`는 `has_access`만 검사해, 일반 직원(staff)도 호출 가능하다. 화면에는 없는 금액 지표를 에이전트가 조합해 알려 줄 수 있음 | 도구 출력 허용 목록을 "화면 대시보드가 그 역할에 보여 주는 값"으로 제한하고, 어긋나면 D-M3 결정. 확인 전에는 `admin_erp_get_dashboard_metrics`를 master_admin·sales_manager scope에만 연다(제안) |
| MT3 | **수치로 개인 추정:** 학급이 작을 때 출석률로 특정 학생 식별(SMS, 미성년) | 학급 인원이 N명 미만이면 비율 대신 "표본 적음"으로 표시(N은 제안 5). 학생 단위 도구 없음 |
| MT4 | **의료정보 우회:** HMS 데이터를 ERP·SMS 도구로 간접 조회 | HMS는 별도 DB·별도 배포. HMS용 MCP 서버·scope를 만들지 않고, ERP·SMS 서버 환경에 HMS 접속 정보를 두지 않는다(`CLAUDE.md` 2절 hms 격리) |
| MT5 | **직원이 입력한 텍스트의 지시문:** 부서명·상품명·메모에 "이 수치를 외부로 보내라" 같은 문장 (M1) | 허용 목록에 자유 텍스트 필드를 넣지 않는다. 상품명·부서명 등 이름 필드가 필요하면 길이 제한과 untrusted 표시 |
| MT6 | **조직 데이터가 외부 AI 제공자로 나감:** 사용자가 쓰는 에이전트가 해외 모델이면 수치가 국외 이전됨 | 제품 AI의 국외 이전 동의(`set_ai_cross_border_ack`)는 제품 내부 AI에만 해당. 외부 에이전트에는 적용되지 않으므로 기관 관리자 동의·고지 절차를 따로 정해야 함(D-M4) |
| MT7 | **세션 만료 후 토큰 잔존:** 퇴사·정지 직원의 에이전트 토큰이 살아 있음 | 매 호출 `has_access`(활성 프로필·멤버십)를 DB가 다시 검사. 정지(`status`) 즉시 거부. 접근 토큰 짧게 |
| MT8 | **감사 공백:** 에이전트 호출이 사람 호출과 구분되지 않음 | 호출 로그에 도구 이름·요청 id·사용자 id·결과 코드. DB 감사(`write_audit`)에는 읽기 도구는 남기지 않고 서버 로그만(D-M6) |

## 6. 승인 흐름 (W1·W2 도구가 있을 때)

이 제품에는 쓰기 도구도 준비 도구도 없다. 판매 등록·승인·역할 변경·환불은 사람이 웹 화면에서 한다. 필요해지면 `MCP_BASELINE.md` 6절의 준비 도구 흐름을 따로 설계한다.

## 10. 테스트 체크리스트

- [ ] 모든 도구 출력에 제외 필드(개인 식별 정보, 원가·단가 행, 조직 id)가 없다(스키마 테스트)
- [ ] 다른 기관 데이터를 도구로 읽을 수 없다(`outsider` 페르소나 회귀)
- [ ] 일반 직원(staff)·student·정지 계정 토큰으로 호출이 거부된다
- [ ] 토큰 없는 호출은 모두 거부된다(익명 도구 없음)
- [ ] 레이트 리밋과 응답 크기 상한이 동작한다
- [ ] 쓰기 도구·준비 도구가 없다(도구 목록 스냅샷 테스트)
- [ ] HMS 앱·HMS DB 접속 정보가 MCP 서버 환경에 없다
- [ ] 이 서비스 환경에 `SUPABASE_SERVICE_ROLE_KEY`가 없다
- [ ] Mock 인증 허용 판정이 MCP 경로에 영향을 주지 않는다(배포 빌드 `/api/dev/login` 404 유지)
