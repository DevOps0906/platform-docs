# 08 블로그 대행 운영: NOMAD Blog (nomad-blog)

2026-10-20 작성. 상위 전략은 `../00_AGENCY_BUNDLE_STRATEGY.md`(통합 번들 Tier, 영업 채널 7개, 8주 로드맵)이고, 이 문서는 그중 **네이버 블로그 대행 라인**의 운영 기준이다. 제품 기능은 `01_PRD.md`가 맡는다. 근거 없는 값은 "제안", 확인하지 않은 외부 사실은 "미확인"이다.

## 1. 사업 범위

| 항목 | 내용 |
|---|---|
| 형태 | 직접 대행. 운영사가 nomad-blog를 내부 도구로 쓰고 고객은 승인 링크·리포트만 받는다(sceneflow `08` 1장과 같은 방식) |
| 대상 고객 | 로컬 소상공인, 병원·학원·법률사무소 등 (원본 리포트 기준) |
| 상품 | 월 8~20건 포스팅 패키지. 통합 번들에서는 Starter 블로그 8건, Growth 12건 |
| 하지 않는 것 | 상위노출·순위 보장, 허위 후기, 의료·법률 광고 심의 대상 문구 임의 작성 |

## 2. 제작 흐름 (제품 기능 재사용)

키워드 리서치 → 원고 생성 → 썸네일 생성(원본 리포트: gpt-image-2, 비전 검수로 네이버 유사도 감지 회피) → 멀티계정 발행(Playwright). 발행 자동화는 네이버 약관과 계정 위험이 있어 PRD의 위험 동의·승인 절차를 그대로 따른다(미확인: 네이버 약관상 자동 발행 허용 범위는 변호사 확인 전).

## 3. 번들 연계

- 블로그 원고 1건에서 숏폼 스크립트·인스타 캡션·스레드 포스트를 파생 생성한다(번들 전략 4장 2번). 이 파생은 sceneflow와 SNS 운영에서 쓴다.
- 영업: 네이버 카페 인바운드(기술적 애로사항 해결 댓글)와 블로그를 연동한다. 신뢰 기반 계약 유도가 목적이다.
- 리포트: 블로그 순위·유입을 통합 클라이언트 대시보드 한 화면에 넣는다.

## 4. KPI (제안)

| KPI | 정의 |
|---|---|
| 월 발행 건수 달성률 | 계약 건수 대비 발행 건수 |
| 수정 요청 횟수 | 원고 1건당 평균 |
| 키워드 순위 | 약속하지 않고 리포트로만 공개 |
| 계약 유지율 | 번들 업셀 후 해지율 |
