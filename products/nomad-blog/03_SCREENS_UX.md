## 2. 사용자 플로우

### 2.1 가입 → 부트스트랩 → 첫 발행

| 단계 | 화면 | 사용자 행동 | 시스템 동작 | 실패 분기 |
|---|---|---|---|---|
| 1 | `/signup`(B단계부터, A는 `/login` 개발용 패널의 `owner` 페르소나) | 이메일 가입 또는 Google로 계속하기(C단계 카카오·네이버) | 이메일: `signUp(options.data.signup_app='blog')` → 코어 트리거가 개인 조직, free 엔타이틀먼트, 월 크레딧 20. OAuth: `/auth/callback`이 `bootstrap_app_for_org('blog')` 1회 → 같은 결과(7절) | 이메일 미인증이면 인증 안내 화면. OAuth 실패는 `/login?error=callback` |
| 2 | `/dashboard` | 첫 방문 | `session_context('blog')`. 빈 상태: "첫 채널을 연결하고 원고를 만드세요" 2단계 안내 | `entitled=false`면 `bootstrap_app_for_org` 호출 후 새로고침 |
| 3 | `/channels` | 워드프레스 연결(가장 쉬운 채널) | 서버가 URL 검사 → `users/me` 검증 → 자격증명 암호화 저장 → active | 사설 IP·http는 즉시 거부, 인증 실패는 "애플리케이션 비밀번호를 확인하세요" |
| 4 | `/posts/new` | 키워드 입력 → 추천 키워드 선택 → 템플릿·분량 선택 → (받아쓰기 또는 자료 선택) → 생성 | 그래프 정액 5크레딧(빠름, 키워드·검사 포함) 선차감, `blog.generate` 잡 안에서 그래프 `blog.post_draft` 실행, 진행률 Realtime | 402면 부족량과 크레딧팩 버튼 |
| 5 | `/posts/[id]` | 편집, 자동 저장 | 2초 디바운스 저장, `version` 충돌 감지 | 충돌 시 최신 불러오기 안내 |
| 6 | 발행 시트 | "검사"(그래프로 만든 원고는 먼저 `/posts/[id]/review`에서 승인, 2.9절) | 규칙 사전 → LLM 판정(1크레딧, 수정 뒤 재검사) | FAIL: 수정 위치 하이라이트. WARN: 확인 체크 후 진행 |
| 7 | 발행 시트 | 채널 선택 → "지금 발행" | 한도 확인 → 발행 행 INSERT → 잡 | 409(진행 중 발행 있음), 402 `BL004`(월 한도) |
| 8 | `/posts/[id]` | 결과 확인 | 채널별 상태 칩, 발행 URL | failed: 사유와 "다시 시도". unconfirmed: "채널에서 확인해 주세요" |

### 3.3 발행 시트

구성: 채널 계정 체크 목록(상태, 세션 만료일, 오늘 남은 발행 수) → 검사 결과(PASS/WARN/FAIL + 항목) → 채널 정책 경고 → 즉시/예약 → "발행". 데이터: `channel_accounts`, `posts.compliance_*`. 크레딧: 검사 1.

### 3.4 캘린더

월/주 보기, 채널 색 범례(색만으로 구분하지 않고 채널 이름 칩 병기). 레퍼런스: 편집 캘린더 + 예약 위젯(`https://dribbble.com/shots/9895896-WP-Scheduled-Posts-Missed-Schedule-Best-Editorial-Calendar`).

### 3.5 채널

표: 채널, 라벨, 블로그 주소, 상태, 위험 동의, 세션 만료, 마지막 발행. 행동: 연결, 재인증, 해제(owner/admin). 네이버·티스토리 연결 버튼은 동의 전 잠금.

### 3.6 제휴

계정 연결(키 마스킹), 링크 표(상품, 원고, 클릭 7/30일), 원고별 클릭 막대. 수익 열은 제공자 리포트가 있는 경우만. 레퍼런스: 상품별 수익과 추이(`https://dribbble.com/shots/14671941-Farmhouse-Affiliate-Marketing-Dashboard`), 머천트 기능은 제외.

### 3.7 브랜드커넥트

탭: 캠페인(스캔 결과, 마감순, 유형 칩·필터), 지원(상태 칩: 작성/제출 중/제출됨/선정/미선정/실패, 출처 칩: 블로그/클립(video)), 설정(동의 상태, 고지문 버전, 철회). 클립형 캠페인의 지원 버튼은 "영상으로 지원"이다(BL-F-036). 발행된 원고 상세에는 "클립으로 만들기"(BL-F-037, Phase 2)가 있다. 크레딧: 메시지 다듬기 1.

### 3.8 설정 > 대가성 문구

제공자 4개 x `blog_top` 문구 편집. 끄는 스위치 없음. 저장 조건: 10자 이상 + 경제적 이해관계 단어 포함(01장 6.3절). 미리보기는 실제 글 상단 렌더.

### 4.4 레이아웃 안(2개 비교)

A안(선택, 2026-10-13 3D 반영): 좌측 정렬 헤드라인 + 키워드 입력 1줄 + 우측 3D 장면(원고 시트가 접혀 채널 카드로 발행됨, 4.6절). 실제 에디터 화면 캡처는 히어로 바로 아래 첫 섹션으로 옮긴다. 교정 적색 밑줄 하나가 키워드에서 원고로 이어지는 연출은 3D 장면의 시트 위 교정 표시 한 곳으로 대신한다.

```
+------------------------------------------------------------------+
| NOMAD Blog                       가격  로그인  [무료로 시작]       |
+------------------------------------------------------------------+
| 키워드 하나로 원고를 쓰고,          | [실제 에디터 캡처: 제목,     |
| 네이버·티스토리·워드프레스에        |  잠금된 대가성 문구 블록,    |
| 예약 발행합니다.                    |  제휴 카드 1개, 보조 패널]   |
| [키워드 입력 1줄] [원고 미리 보기]  |                              |
+------------------------------------------------------------------+
| 흐름 4단계(실제 순서): 키워드 → 원고 → 검사 → 발행              |
+------------------------------------------------------------------+
| 대가성 문구가 자동으로 들어가는 이유(공정위 심사지침 요약)        |
+------------------------------------------------------------------+
| 가격 표 3열                                                       |
+------------------------------------------------------------------+
```

B안: 중앙 정렬 큰 헤드라인 + 아래 캘린더 캡처. 버림: 캘린더는 첫 행동(키워드 입력)과 거리가 멀고 중앙 정렬 히어로가 생성형 기본값에 가깝다.

원칙: (1) 실제 화면을 보여 준다(히어로 아래 첫 섹션) (2) 대담함은 히어로의 3D 장면 한 곳과 교정 적색 한 곳 (3) 법 준수(대가성 문구)를 숨기지 않고 장점으로 설명 (4) 수치 대신 과정.

변경 기록(2026-10-13): 이전 히어로 "우측에 실제 에디터 화면 + 로드 시퀀스 1회"를 위 A안(3D 장면)으로 바꿨다. 이유는 사용자 결정(2026-10-13, 확정 결정 15: 전 제품 메인페이지 히어로는 PC·태블릿 풀 3D, 모바일 절충안, `docs/products/00_MERGE_ANALYSIS.md:23`)이다. 토큰(원고지, 먹, 교정 적색, 잉크 청, 괘선, 문구 노랑), 서체, 피할 인상 목록, 카피 원칙은 바꾸지 않는다. 히어로 밖 섹션은 연출하지 않는다(4.5절 11번 유지).

### 4.6 3D 히어로 (원고 시트 → 채널 카드)

정본은 `docs/products/_design-guide/HERO_3D.md`(기기 구성 `:5-15`, 성능 예산 `:32-41`, 구현 규칙 `:43-54`, 수용 기준 `:70-75`)이고, 이 절은 blog 소재(`:84`)와 장면만 정한다.

| 기기 | 구성(HERO_3D 1절) | blog 장면 |
|---|---|---|
| PC(1280px 이상) | 풀 3D. 제목·입력·CTA는 HTML 오버레이 | 원고 시트 1장이 3번 접혀 채널 카드 3장(네이버·티스토리·워드프레스)으로 나뉘어 발행됨 |
| 태블릿(768~1279px) | 풀 3D, DPR 상한 1.5, 터치 드래그로 시점 이동 | PC와 같음 |
| 모바일(767px 이하) | HTML 즉시 표시 + 가벼운 3D를 첫 화면 뒤 로드 | 시트 1장이 반으로 한 번 접히는 연출만. 채널 카드 3장은 HTML 칩(채널 이름 텍스트)으로 표시 |

장면 연출(PC·태블릿):

| 단계 | 계기 | 3D | HTML |
|---|---|---|---|
| 0 첫 화면 | 페이지 로드 | 없음. 같은 구도의 정지 이미지 자리(레이아웃 이동 없음) | 헤드라인(LCP 요소), 키워드 입력, CTA |
| 1 대기 | 동적 import 완료 | 괘선이 그어진 원고 시트가 평평하게 놓이고 위쪽에 문구 노랑 띠(대가성 문구 자리)와 교정 적색 밑줄 1개. 아주 느리게 떠 있다(상하 8px, 6초 주기, 제안). [움직임 멈춤] 토글 | 변화 없음 |
| 2 입력 | [원고 미리 보기] 누름 | 시트의 괘선이 위에서 아래로 채워지듯 강조된다(3D는 글자를 그리지 않음) | 입력한 키워드가 시트 위 첫 줄 자리에 HTML로 표시 |
| 3 접힘 | 2단계 직후, 1.4초(제안) | 시트가 3등분으로 접혀 카드 3장으로 갈라지고 가로로 펼쳐진다. 카드마다 문구 노랑 띠가 먼저 붙어 있다 | 카드 아래에 채널 이름 칩 3개(텍스트) |
| 4 정지 | 접힘 끝 | 렌더 중단(`frameloop="demand"`) | CTA "무료로 시작" |

입력을 바꾸면 2~4단계를 다시 실행한다(전환 0.6초, 제안). reduced-motion이면 0~4단계 없이 정지 이미지와 HTML 칩만 보인다.

## 7. 인증 단계별 로그인 화면 (2026-10-14 추가, 확정 결정 22)

정본은 `docs/products/_platform-core/AUTH_ROADMAP.md`(이하 AUTH_ROADMAP) 2.1절, 5.2절, 7.3절이다. 로그인 이후 화면(대시보드부터)은 단계와 무관하게 같다. 이 절의 로그인은 "NOMAD Blog 사용자 로그인"이고, 3.5절 채널 화면의 네이버·티스토리 "연결"(블로그 게시용 계정, 재인증 "다시 로그인" 포함)과는 다른 화면·다른 계정이다.

### 7.1 `/login` 단계별 구성

| 단계 | 구성 | 소유 작업 |
|---|---|---|
| A Mock(MVP 개발) | 페이지 상단 고정 배지 `MOCK AUTH · 로컬 전용`(모든 화면, 문구 노랑 바탕 + 먹 글자, 대비 4.5:1). "개발용 로그인" 패널: 페르소나 버튼 목록(`owner`, `admin`, `member`, `viewer`, `outsider`, `no_app`, `suspended`, `ops` + blog 행 `owner_pro`, 05장 10절), 현재 로그인 페르소나, 로그아웃. 실제 제공자 버튼·`/signup` 링크 없음. 판정(`isMockAuthAllowed()`)이 거짓이면 패널 코드를 렌더하지 않는다(서버 컴포넌트 분기) | BL-06-004 |
| B Google | "Google로 계속하기" 버튼(위) + 이메일·비밀번호 폼(아래, 01장 D-24) + "비밀번호를 잊으셨나요" + `/signup` 링크. 개발용 패널·배지 없음(배포 환경) | BL-06-057 |
| C 카카오·네이버 | B 구성 위에 "카카오로 계속하기"(C1), "네이버로 계속하기"(C2) 버튼. 버튼 색·문구는 각 제공자 디자인 가이드(미확인, 구현 시 최신판 확인, C1-5). 버튼 순서 제안: Google, 네이버, 카카오, 이메일(네이버 블로거 비중, 01장 8.1절) | BL-06-058, 059 |

`/signup`은 B단계부터 있다(이메일 가입 폼 + 같은 OAuth 버튼. OAuth는 가입과 로그인이 같은 버튼). 로그인 화면 문구는 "로그인"이고, 채널 연결 문구("네이버 블로그 연결")와 섞지 않는다.

### 7.3 첫 OAuth 로그인 뒤 약관 동의

blog는 온보딩 화면 `/onboarding/ai`(국외 이전 동의, BL-F-058)가 있으므로 약관 동의를 그 앞 첫 단계 `/onboarding/terms`로 둔다(AUTH_ROADMAP 5.2절). 순서: `/auth/callback` → (첫 로그인이고 약관 미동의) `/onboarding/terms`(이용약관·개인정보처리방침 필수, 만 14세 이상 확인 01장 6.6절, 6.2절 자동 게시 대행 고지 요약) → `/onboarding/ai` → `/dashboard`. 이메일 가입은 가입 폼에서 같은 항목에 동의하므로 `/onboarding/terms`를 건너뛴다. 동의 기록 방식(감사 `blog.terms_ack {notice_version}` 등)은 B 작업에서 정한다(제안, 코어에 약관 동의 표가 없음).

### 7.4 설정 → 로그인 방법 (C단계, P1)

| 항목 | 내용 |
|---|---|
| 위치 | `/settings/login-methods`(제안, BL-06-058 소유. 기존 `/settings/*`의 BL-06-027과 디렉토리가 겹치지 않게 하위 폴더 하나만) |
| 구성 | 연결된 로그인 제공자 목록(Google, 이메일, 카카오, 네이버), 연결·해제 버튼. 남는 로그인 수단이 1개면 해제 비활성 |

| 감사 | `auth.identity_link`, `auth.identity_unlink` |
