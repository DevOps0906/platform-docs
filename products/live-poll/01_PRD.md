## 1. 페르소나와 핵심 과제

| 페르소나 | 상황 | 목표 | 좌절 |
|---|---|---|---|
| 김연수(34, 사내 교육 담당) | 월 2회 200명 규모 타운홀을 진행한다 | 질문을 익명으로 받고 즉석 투표로 의견을 모은다 | 손을 드는 사람이 없다. 설문 링크는 결과를 한참 뒤에야 본다 |
| 박도윤(28, 라이브 방송인) | 유튜브 라이브에서 시청자 투표를 띄운다 | OBS 화면 위에 실시간 결과 막대를 올린다 | 채팅 투표는 집계가 안 되고, 기존 도구는 배경이 투명하지 않다 |
| 청중(행사 참석자) | 휴대폰 하나, 행사장 Wi-Fi | 10초 안에 들어가서 한 번 누르고 결과를 본다 | 가입, 앱 설치, 느린 화면, 같은 Wi-Fi라서 "이미 투표했습니다" 오류 |

| 핵심 과제 | 설명 |
|---|---|
| 1 | 코드 입력 한 번으로 청중이 입장하고, 진행자가 문항을 열면 새로고침 없이 투표 화면이 뜬다(원본 PRD:24) |
| 2 | 제출부터 다른 화면의 차트 반영까지 측정 가능한 지연 목표를 지킨다(리뷰:39, :86) |
| 3 | 로그인 없는 청중의 중복 투표와 봇 남용을 "소프트 제한"으로 막되, 같은 Wi-Fi 정상 사용자를 막지 않는다(리뷰:41, :55) |

## 4. 요금과 크레딧

플랜 정본은 이 표다. 확정 결정 8에 이 제품 항목이 없으므로 금액과 한도는 모두 제안이다. 근거: 리뷰 MVP 목표 동시 3,000명(리뷰:86), 모듈러 seed의 free `max_participants` 100(`docs/products/_supabase-modular/seed.sql:41`).

| 코드 | 가격(원/월) | 월 크레딧 | 가입 크레딧 | 이월 | 상태 | 주요 한도 |
|---|---|---|---|---|---|---|
| `free` | 0 | 0 | 0 | 해당 없음 | 베타 기본(is_default) | 참가자 100, 동시 live 1, 보존 30일 |
| `pro` | 19,900 | 0 | 0 | 해당 없음 | Phase 2(is_active=false) | 참가자 1,000, 동시 live 3, 보존 365일, 브랜딩 제거 |
| `business` | 59,000 | 0 | 0 | 해당 없음 | Phase 2(is_active=false) | 참가자 3,000, 동시 live 10, 보존 730일, 팀 5인 |

크레딧 단가: 해당 없음. 이 제품은 LLM, 이미지, 렌더 호출이 없어 크레딧을 쓰지 않는다. 크레딧팩도 없다(모놀리스는 크레딧 절을 지웠다).

`core.plans.features` 키 해석(서버와 `poll.plan_feature_int`만 읽는다. 키가 없으면 괄호 안 기본값):

| 키 | 타입 | 의미 | 강제 위치 |
|---|---|---|---|
| `max_participants` | int | 행사당 청중 상한. live 전환 시 `events.max_participants`로 고정(100) | `transition_event`, `join_event` |
| `max_live_events` | int, -1 무제한 | 조직의 동시 live 행사 수(1) | `transition_event` |
| `max_events` | int, -1 무제한 | archived가 아닌 행사 수(50) | `create_event` |
| `polls_per_event` | int, -1 무제한 | 행사당 한 번이라도 연 문항 수(50) | `transition_poll` |
| `qna` | bool | Q&A 사용 가능(true) | Route Handler |
| `export_csv` | bool | CSV 내보내기(true) | Route Handler |
| `overlay` | bool | OBS 오버레이(true) | Route Handler |
| `branding` | bool | true면 오버레이/청중 화면 하단에 "Live Poll" 표시 | 화면 |
| `retention_days` | int | 종료 후 원본 투표/참가자/질문 보존 일수(30) | `end_event_internal` |
| `team_members` | int | 조직 멤버 수(Phase 2) | 초대 Route Handler |

모듈러 seed는 2026-10-13부터 모놀리스 seed와 같은 값이다. 키가 없으면 기본값으로 동작한다. 결제(Phase 2)는 `CORE_SPEC.md` 5장 일반결제/빌링키 시퀀스를 그대로 쓴다. 환불: 결제 후 7일 이내 live 행사를 연 적이 없으면 전액(제안).

## 6. 법, 개인정보, 금지 문구

| 항목 | 내용 |

| 개인정보: 진행자 | 이메일, 표시 이름(코어 `profiles`). 목적: 계정과 결제. 보존: 탈퇴 후 조직 soft delete → 30일 → `purge_organization`(`SECURITY_BASELINE.md` 12장) |

| 암호화 대상 | 평문 비밀 컬럼 없음. 참가자 토큰, 오버레이 키, 입장 비밀번호는 해시만(`SECURITY_BASELINE.md` 12장) |
| 삭제 절차 | 행사 삭제 → soft delete → 7일 → 물리 삭제. 청중 개인 삭제 요청은 진행자 콘솔의 참가자 목록에서 해당 닉네임 행 삭제(Phase 2, service_role 경로, 감사 기록) |
