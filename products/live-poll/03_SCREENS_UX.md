# 03 화면과 UX: Live Poll

2026-10-13 개정: 진행자 AI 어시스턴트·Q&A AI 정리·행사 위키·음성 UI(진행자 음성 대화, 청중 음성 질문, 읽어 주기), 3D 히어로, 디자인 시스템 항목을 추가했다. 청중 화면에는 AI 채팅이 없고 음성 질문 마이크 버튼만 있다(02장 5-5절).

## 3. 화면별 명세

### 3.1 진행자 콘솔 `/events/[id]/live`

목적: 진행 중 한 화면에서 문항 진행, 집계 확인, Q&A 정리. 데이터: `poll.events`, `polls`, `poll_options`, `qna_questions`, `participants`(RLS), `host_poll_results`, 공개 토픽 + 진행자 토픽. 크레딧 표시 없음(크레딧 미사용).

```
+----------------------------------------------------------------------+
| 강연 A   [진행 중]  코드 482 913  참가 87명  연결됨   [발표 화면] [종료] |
+----------------------+-----------------------------------+-----------+
| 문항 목록            | 현재 문항: 오늘 세션 만족도는?    | Q&A 큐    |
|  1 만족도 [열림]     | 매우 만족 ######### 41            | 대기 3    |
|  2 다음 주제 [준비]  | 만족     ######     28            | > 질문... |
|  3 평점 [준비]       | 보통     ##          9            |  승인 거절|
| [+ 문항]             | 응답 78 / 참가 87   [닫기] [다음] | 공개 12   |
+----------------------+-----------------------------------+-----------+
```

행동: 열기/닫기(Space), 이전/다음(화살표), 입장 잠금 토글, 비밀번호 설정, 오버레이 URL, 참가자 차단.

### 3.2 발표 화면 `/present/[id]`

목적: 프로젝터 투사. 구성: 상단 제목(48px 이상), 결과 막대(라벨 32px, 숫자 tabular 48px), 하단 "live-poll 주소 + 코드 + QR" 고정. 대기 상태는 큰 코드와 QR만. 데이터: 공개 토픽 + 진행자 세션 스냅샷.

### 3.3 오버레이 `/overlay/[id]`

목적: 방송 화면 하단 1/3. 파라미터 `bg=transparent|green|dark`, `theme`, `scale`, `position=bottom|right`. 크롬 없음. 결과 공개 규칙을 따른다. `branding=true` 플랜은 우하단 작은 표시.

### 3.4 청중 화면 `/e/[code]`

목적: 한 손 조작. 선택지는 높이 56px 이상의 전폭 버튼, 제출은 화면 하단 고정. 상태: 입장 시트 → 대기("곧 투표가 시작됩니다") → 투표 → 제출 완료 → 결과. 상단 연결 배지. Q&A 탭(질문 쓰기, 추천 목록, 내 질문 상태). 데이터: `/api/p/snapshot`, 공개 토픽.

### 3.5 행사 편집 `/events/[id]/edit`

문항 카드 목록(드래그 정렬은 position 갱신), 문항 종류 선택, 선택지 2~10, 결과 공개 규칙, 행사 설정(익명 허용, Q&A, 모더레이션, 종료 후 결과 공유).

### 3.6 결과 `/events/[id]/results`

문항별 확정 집계(`poll_results`), Q&A 목록, CSV 버튼(`/api/host/events/[id]/export.csv`). 보존 기간 경과 표시("원본 응답은 2026-11-11에 삭제됩니다. 집계는 남습니다").

대담함의 위치: 히어로 3D 장면에서 투표가 들어올 때마다 무대 위 막대와 구가 솟고 순위가 바뀌는 연출. 나머지 섹션은 정적.

## 6. 접근성과 반응형

| 항목 | 기준 |
|---|---|
| 키보드 | 콘솔/발표 화면 단축키, 모든 버튼 포커스 표시. 청중 선택지는 radio/checkbox 그룹 시맨틱 |
| 대비 | 본문 4.5:1, 발표 화면 막대 라벨 7:1(먼 거리) |
| 스크린리더 | 결과 갱신은 `aria-live="polite"`로 5초에 1회만 요약 읽기("만족 41표, 1위") |
| 모션 | `prefers-reduced-motion`이면 막대 전환과 재정렬 애니메이션 끔 |
| 폭 | 청중 화면 375px 우선, 콘솔 1280px 이상(1024px에서 Q&A 패널 접힘), 발표 화면 16:9 |
| AI 패널 | 어시스턴트 시트는 포커스 트랩과 Esc 닫기, 스트리밍 영역 `aria-live="polite"`(문장 단위), 크레딧 변화는 별도 `aria-live` 없이 텍스트로. Q&A AI 패널의 라벨은 색만이 아니라 아이콘 + 텍스트 |
| 음성 | 음성은 텍스트 입력의 대안이다. 모든 기능이 음성 없이 동작한다. 마이크 버튼은 누르고 말하기와 토글 두 방식, 녹음 중 상태는 시각 + 텍스트("녹음 중 12초") |
| 3D | 캔버스 `aria-hidden`, 자동 움직임은 멈춤 버튼 제공, reduced-motion이면 정지 이미지 |

## 8. 대시보드 셸과 좌측 GNB (2026-10-19 추가, 원본 프로젝트 메뉴 이행)

이 장은 Live Poll 진행자(호스트) 화면의 공통 셸(헤더 + 좌측 GNB)과 홈 구성을 정한다. 목적은 원본 Slido_Project의 기능이 모두 새 구조 어딘가로 이행되게 하는 것이다. 원본은 기획 문서 2개뿐이고 코드·사이드바가 없다(`docs/reviews/Slido_Project.md:3`). 그래서 원본 "메뉴"는 원본 PRD의 기능 묶음(호스트 `:30`, 참가자 `:31`, 실시간 엔진 `:32`, 비기능 `:33`)과 리뷰가 제안한 화면 작업(`:104-111`)으로 대신한다. 대상 셸은 진행자 셸이다. 주 앱 셸이 `/dashboard`가 아니라 행사 목록 `/events`에서 시작하므로(1절 `:14`, 2.1절 `:42`) 홈은 `/events`다. 청중 화면(`/join`, `/e/[code]`), 발표 화면, OBS 오버레이, 랜딩·로그인·온보딩은 셸 밖 화면이다(8.4절). 1절 화면 표의 경로·역할·플랜·우선순위는 그대로이고, 이 장은 메뉴 순서·묶음·셸 동작만 더한다. 새 경로는 없다. 다른 제품과 `_design-guide` 공용 패턴은 바꾸지 않는다(live-poll 전용).

디자인 시안: Design 캔버스 "Live Poll 대시보드 · GNB 초안"(홈, GNB 접힘, 모바일 서랍 + 메뉴 화면 5개: 진행자 콘솔, 행사 편집, 행사 자료, 결과, 행사 위키). 시안은 진행자 콘솔 기본 라이트 테마(3.8절 `:228`)만 그린다. 메뉴를 비교하려고 콘솔 아트보드도 GNB를 펼쳐 그렸다(실제 기본값은 8.6절 D23). 시안의 수치·제목·질문은 모두 [예시]다.

### 8.4 현재 행사 묶음과 셸 밖 화면

### 8.6 셸 동작 규칙

| 항목 | 규칙 |
|---|---|
| 폭 | 펼침 248px, 접힘 64px 아이콘 레일. 접힌 상태에서 메뉴 이름은 툴팁, 개수 배지는 점. 진행자 콘솔은 D23 기본값으로 진입 때 레일로 접힌다. 콘솔 3열은 1280px 이상, 1024px에서 Q&A 패널 접힘(6절 `:417`) |
| 현재 위치 | 왼쪽 3px 막대(`--color-accent`) + 배경 + `aria-current="page"`. 헤더 아래 경로 표시("Live Poll › 현재 행사 › 진행자 콘솔"). 경로 표시에 청중 닉네임·질문을 넣지 않는다 |
| 역할 | 역할 밖 메뉴는 렌더하지 않는다. 판정은 서버의 `session_context('poll')` `org.role`이고 클라이언트 값을 믿지 않는다. 직접 URL은 서버가 막는다 |
| 개수 배지 | 진행자 콘솔(현재 행사의 Q&A 승인 대기), 행사 위키(초안 검수 대기). 0이면 숨긴다. 값은 서버 집계로 받고 주기 조회를 하지 않는다(CLAUDE.md "폴링 금지"). 콘솔 배지는 진행자 토픽 수신 때만 갱신 |
| 단축키 | 콘솔 단축키(Space, 화살표, 3.1절 `:147`)는 콘솔 본문에 포커스가 있을 때만. GNB·검색 입력 중에는 동작하지 않는다 |
| 반응형 | 1024px 미만은 GNB를 숨기고 햄버거 → 왼쪽 서랍(264px, 배경 딤, 바깥 누르면 닫힘). 검색·현재 행사 칩·플랜 배지·크레딧은 서랍 안으로 |
| 접근성 | GNB는 `<nav aria-label>`, 묶음 제목은 목록 머리, 메뉴 버튼 높이 40px(`--space-row-default`) 이상, 포커스 링, 서랍은 포커스 가둠 + Esc 닫기. 상태 배지는 아이콘 + 텍스트(3.8절 `:243`) |
| 토큰 | 셸은 `apps/live-poll/src/styles/tokens.css`의 의미 기반 이름만 쓴다(3.8절 `:228`). 4.3절 `:275`대로 GNB 배경은 객석 남색 #1E2A44, GNB 글자는 스크린 백색 #F7F8FA다. 시안은 렌더러에 GNB 전용 글자색이 없어 밝은 회색 GNB로 그렸다(시안 한정). 응답 주황은 막대 하이라이트 전용이라 셸에 쓰지 않는다(`:278`) |
| 대비 | 막대 청록 #0F8B8D 위 흰 글자 4.12:1, 스크린 백색 위 성공 #1F8A4C 4.12:1·경고 #B7791F 3.43:1로 글자 기준 4.5:1에 못 미친다(계산값). 출시 체크리스트 4(`:281`)에서 토큰을 고치기 전까지 primary 버튼 글자는 어두운 색(시안 #000C0C, 제안), 상태색은 아이콘 + 굵은 텍스트로만 쓴다 |
| 금지 | 메뉴 이모지, 헤더 전역 어시스턴트 버튼, 청중 화면·오버레이 안 GNB, 하드코딩 개수, 수집하지 않은 지표의 0 표시, "실시간 0.5초" 같은 미검증 수치(01장 `:210`) |
