# 03 화면과 UX: Live Poll

2026-10-13 개정: 진행자 AI 어시스턴트·Q&A AI 정리·행사 위키·음성 UI(진행자 음성 대화, 청중 음성 질문, 읽어 주기), 3D 히어로, 디자인 시스템 항목을 추가했다. 청중 화면에는 AI 채팅이 없고 음성 질문 마이크 버튼만 있다(02장 5-5절).

## 3. 화면별 명세

### 3.1 진행자 콘솔 `/events/[id]/live`

목적: 진행 중 한 화면에서 문항 진행, 집계 확인, Q&A 정리. 데이터: `poll.events`, `polls`, `poll_options`, `qna_questions`, `participants`(RLS), `host_poll_results`, 공개 토픽 + 진행자 토픽. 크레딧 표시 없음(크레딧 미사용).

```
+----------------------------------------------------------------------+
| 강연 A   [진행 중]  코드 482 913  참가 87명  연결됨   [발표 화면] [종료] |
+----------------------+-----------------------------------+-----------+
| 문항 목록            | 현재 문항: 오늘 세션 만족도는?    | Q&A 큐    |
|  1 만족도 [열림]     | 매우 만족 ######### 41            | 대기 3    |
|  2 다음 주제 [준비]  | 만족     ######     28            | > 질문... |
|  3 평점 [준비]       | 보통     ##          9            |  승인 거절|
| [+ 문항]             | 응답 78 / 참가 87   [닫기] [다음] | 공개 12   |
+----------------------+-----------------------------------+-----------+
```

행동: 열기/닫기(Space), 이전/다음(화살표), 입장 잠금 토글, 비밀번호 설정, 오버레이 URL, 참가자 차단.

### 3.2 발표 화면 `/present/[id]`

목적: 프로젝터 투사. 구성: 상단 제목(48px 이상), 결과 막대(라벨 32px, 숫자 tabular 48px), 하단 "live-poll 주소 + 코드 + QR" 고정. 대기 상태는 큰 코드와 QR만. 데이터: 공개 토픽 + 진행자 세션 스냅샷.

### 3.3 오버레이 `/overlay/[id]`

목적: 방송 화면 하단 1/3. 파라미터 `bg=transparent|green|dark`, `theme`, `scale`, `position=bottom|right`. 크롬 없음. 결과 공개 규칙을 따른다. `branding=true` 플랜은 우하단 작은 표시.

### 3.4 청중 화면 `/e/[code]`

목적: 한 손 조작. 선택지는 높이 56px 이상의 전폭 버튼, 제출은 화면 하단 고정. 상태: 입장 시트 → 대기("곧 투표가 시작됩니다") → 투표 → 제출 완료 → 결과. 상단 연결 배지. Q&A 탭(질문 쓰기, 추천 목록, 내 질문 상태). 데이터: `/api/p/snapshot`, 공개 토픽.

### 3.5 행사 편집 `/events/[id]/edit`

문항 카드 목록(드래그 정렬은 position 갱신), 문항 종류 선택, 선택지 2~10, 결과 공개 규칙, 행사 설정(익명 허용, Q&A, 모더레이션, 종료 후 결과 공유).

### 3.6 결과 `/events/[id]/results`

문항별 확정 집계(`poll_results`), Q&A 목록, CSV 버튼(`/api/host/events/[id]/export.csv`). 보존 기간 경과 표시("원본 응답은 2026-11-11에 삭제됩니다. 집계는 남습니다").

```
| 로고                                   가격   로그인  [무료 베타] |
+------------------------------------------------------------------+
| 청중은 코드만 누르면 됩니다       | +--------------------------+ |
| 투표와 질문을 받고, 결과는        | | 482 913                  | |
| 바로 발표 화면에 뜹니다           | | 만족 ##########          | |
| [무료 베타로 행사 만들기]         | | 보통 ####                | |
|                                   | +--------------------------+ |
+------------------------------------------------------------------+
| 행사 중: 투표, Q&A, 발표 화면 / 행사 후: 결과 보존, CSV           |
+------------------------------------------------------------------+

+------------------------------------------------------------------+

+------------------------------------------------------------------+
|                      4 8 2  9 1 3                                |

+------------------------------------------------------------------+
```

안 B는 큰 숫자 히어로(기본값 6)에 걸려 버렸다. 안 A는 제품 동작(막대가 자라는 장면)을 히어로로 쓴다. 2026-10-13부터 안 A의 오른쪽 "동작 데모"는 3D 무대 장면(4.5절)이고, 6자리 코드와 막대 라벨·숫자는 그 위에 HTML로 겹친다.

원칙: (1) 제품 동작으로 설명한다 (2) 숫자는 시연 값만 쓰고(시연 값임을 표시) 운영 실적 수치는 쓰지 않는다 (3) 청중 관점 문장은 짧게 (4) 모션은 히어로 3D 장면 한 곳뿐.

대담함의 위치: 히어로 3D 장면에서 투표가 들어올 때마다 무대 위 막대와 구가 솟고 순위가 바뀌는 연출. 나머지 섹션은 정적.

## 6. 접근성과 반응형

| 항목 | 기준 |
|---|---|
| 키보드 | 콘솔/발표 화면 단축키, 모든 버튼 포커스 표시. 청중 선택지는 radio/checkbox 그룹 시맨틱 |
| 대비 | 본문 4.5:1, 발표 화면 막대 라벨 7:1(먼 거리) |
| 스크린리더 | 결과 갱신은 `aria-live="polite"`로 5초에 1회만 요약 읽기("만족 41표, 1위") |
| 모션 | `prefers-reduced-motion`이면 막대 전환과 재정렬 애니메이션 끔 |
| 폭 | 청중 화면 375px 우선, 콘솔 1280px 이상(1024px에서 Q&A 패널 접힘), 발표 화면 16:9 |
| AI 패널 | 어시스턴트 시트는 포커스 트랩과 Esc 닫기, 스트리밍 영역 `aria-live="polite"`(문장 단위), 크레딧 변화는 별도 `aria-live` 없이 텍스트로. Q&A AI 패널의 라벨은 색만이 아니라 아이콘 + 텍스트 |
| 음성 | 음성은 텍스트 입력의 대안이다. 모든 기능이 음성 없이 동작한다. 마이크 버튼은 누르고 말하기와 토글 두 방식, 녹음 중 상태는 시각 + 텍스트("녹음 중 12초") |
| 3D | 캔버스 `aria-hidden`, 자동 움직임은 멈춤 버튼 제공, reduced-motion이면 정지 이미지 |

## 7. 인증 단계별 로그인 화면 (2026-10-14 추가, 확정 결정 22)

정본은 `docs/products/_platform-core/AUTH_ROADMAP.md`. 이 제품에서 로그인 화면을 쓰는 사람은 진행자(Phase 2 공동 진행자 포함)뿐이다. 청중 화면(`/join`, `/e/[code]`, QR), 발표 화면의 청중 노출부, OBS 오버레이(`/overlay/[id]?k=`)에는 어느 단계에서도 로그인 버튼을 두지 않는다. 이 화면들은 단계와 무관하며 Mock 단계에서도 지금 설계 그대로 동작한다(청중은 참가자 토큰, 오버레이는 키).

| B(공개 베타 전) | "Google로 계속하기" 버튼 + 이메일·비밀번호 폼(01장 LP-F-001, D21), 비밀번호 재설정 링크 | 이메일 가입 폼 + 베타 약관 체크 + "Google로 계속하기" | 배포 환경에서 개발용 패널·배지 없음(판정 거짓이면 서버 컴포넌트가 렌더하지 않는다) |
| C(G2 후) | B + "카카오로 계속하기"(C1), "네이버로 계속하기"(C2, 검수 통과 뒤) | B + 같은 버튼 | 카카오·네이버 버튼 색·문구는 각 디자인 가이드(미확인: 최신판 확인 후 반영, AUTH_ROADMAP C1-5) |

### 7.2 오류 상태

| 코드(쿼리) | 화면 | 문구(제안) |
|---|---|---|
| `/login?error=callback` | 로그인 상단 오류 띠 | "로그인을 마치지 못했습니다. 다시 시도해 주세요" |
| `/login?error=state` | 같음(C2 브리지 경로만) | "로그인 요청이 만료됐습니다. 처음부터 다시 시도해 주세요" |
| `/login?error=email_in_use` | 같음(C2 브리지 경로만) | "이미 다른 방법으로 가입한 이메일입니다. 그 방법으로 로그인한 뒤 설정에서 네이버를 연결하세요" |
| 프로필 없음 | 로그아웃 후 `/login` | 별도 문구 없음(기본 admin 금지) |
| suspended | 403 화면 | "이용이 제한된 계정입니다" |
| `/no-access` | 해당 없음 | live-poll은 open 가입 정책이라 invite 앱의 `/no-access` 안내를 쓰지 않는다. 엔타이틀먼트는 콜백이 `bootstrap_app_for_org('poll')`로 만든다 |

### 7.3 첫 OAuth 로그인 뒤 약관 동의

| 항목 | 내용 |
|---|---|
| 위치 | 제품 온보딩 `/onboarding`의 첫 단계(베타 약관·개인정보처리방침 동의) → 두 번째 단계 "AI 처리 방식"(LP-F-034) |
| 대상 | B·C단계 OAuth(Google·카카오·네이버) 첫 로그인. 이메일 가입자는 가입 폼에서 이미 동의했으므로 건너뛴다 |
| 미동의 | `/events` 등 진행자 화면 진입 차단, `/onboarding`으로 이동(서버 가드). 동의 기록 방식은 LP-06-049에서 정한다(제안: `core.write_audit` `terms.accept`에 약관 버전, 음성 고지 `voice.notice_ack`와 같은 방식) |
| A단계 | 시드 페르소나는 동의 완료 상태로 만든다(시드 스크립트 훅). 온보딩 화면 자체는 A단계에서 구현·검증한다 |

### 7.4 설정 → 로그인 방법 (C단계, P1)

| 항목 | 내용 |
|---|---|
| 위치 | `/settings`의 "로그인 방법" 탭(owner/admin뿐 아니라 로그인한 모든 진행자 본인) |
| 표시 | 연결된 제공자 목록(Google, 이메일, 카카오, 네이버), 연결·해제 버튼 |
| 해제 | 남는 로그인 수단이 1개 이상일 때만 버튼 활성 |
| 감사 | `auth.identity_link`, `auth.identity_unlink`(AUTH_ROADMAP 7.3절) |
