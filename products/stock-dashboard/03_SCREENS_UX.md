# 03 화면과 UX: Stock Dashboard

작성일 2026-10-12. 원본의 화면 지침(다크 테마, 증권사/Total 탭, 블링크, 블러 모달, 우측 AI 패널)은 구체적이므로 구조를 유지하고(`docs/reviews/Stock_Trader_nomad.md:21`), 색과 서체는 `_design-guide` 절차로 다시 정한다. 공개 랜딩은 법률 검토 후로 미루고(`docs/products/_design-guide/REFERENCES.md:207`), MVP는 초대 전용 안내 페이지만 둔다. 2026-10-13: 사용자 결정(확정 결정 15, `docs/products/00_MERGE_ANALYSIS.md:23`)으로 이 안내 화면의 히어로를 3D(시세 흐름 지형)로 바꿨고(4.5절), AI 채팅·음성·브리핑·위키 화면(3.7절)과 디자인 시스템(3.8절)을 더했다.

## 2. 사용자 플로우

### 2.1 초대 → 가입 → 부트스트랩 → 첫 연결 → 첫 진단 (필수)

| 단계 | 화면 | 사용자 행동 | 시스템 동작 | 실패 분기 |
|---|---|---|---|---|
| 1 | 메일 | 초대 링크 클릭 | - | 만료 → `/invite/...`에서 "초대가 만료되었습니다. 운영자에게 재발급을 요청하세요" |
| 2 | `/invite/[token]` | 초대받은 이메일로 가입(또는 로그인) | `signUp(options.data.signup_app='stock')` → 코어 가입 트리거가 프로필, 개인 조직 생성(invite 앱이라 엔타이틀먼트는 만들지 않음) → 초대 토큰 검증 후 서버가 service_role로 `bootstrap_app_for_org('stock', 개인 조직)` 호출 | 다른 이메일 → `ST031` "초대받은 이메일로 로그인하세요" |
| 3 | 같은 화면 | 자동 진행 | `POST /api/beta/redeem` → `redeem_beta_invite` → 플랜 beta 전환 → 첫 달 300 크레딧 | 이미 사용된 초대 `ST030` |
| 4 | `/onboarding/disclaimer` | 투자 고지를 읽고 동의(필수). "AI 처리 방식" 선택: 상용 AI 사용(국외 이전 동의) 또는 국내 오픈소스만(선택) | `record_consent('investment_disclaimer')`. 상용 AI를 고르면 `POST /api/onboarding/ai-consent` → `set_ai_cross_border_ack` + `consents(ai_overseas_transfer)` | 투자 고지 거부 → 로그아웃 안내. AI 처리 방식은 건너뛰어도 진행(오픈소스만), 설정에서 바꿀 수 있음 |
| 5 | `/dashboard`(빈 상태) | "모의투자 계좌 연결" 또는 "샘플 데이터로 둘러보기" | 샘플은 `mock` 연결 생성 + `stock.sync` | - |
| 6 | `/settings/connections` | 증권사, 앱키, 시크릿, 계좌번호 입력. "본인 계좌", "약관 위험" 체크 | `POST /api/connections` → verify → 암호화 저장 → `active` → 동기화 enqueue | 키 오류 → 행 `error` + 원인 |
| 7 | `/dashboard` | 보유 그리드 확인 | Realtime(`holdings`)로 첫 동기화 반영, SSE 시세 구독 | 시세 연결 실패 → "시세 꺼짐" 배지, 스냅샷은 보임 |
| 8 | `/ai` | "내 포트폴리오 진단하기(10 크레딧)" | 선차감 → 그래프 `stock.diagnosis` 실행(진행 상태 표시) → 투자 권유 금지 검사 통과 후 결과 표시 → 저장 | 크레딧 부족 402, 검사 실패·시간 초과 시 자동 환불 표시 |

|---|---|---|---|---|
| 1 | 채팅 패널 | 패널 열기(대시보드 우측 또는 `/research`) | `POST /api/ai/conversations {channel}` → `core.ai_conversations` 행(`dify_user`=HMAC) | 엔타이틀먼트 없음 403, 일 한도 429 |

## 7. 로그인 화면 단계별 구성 (2026-10-14 추가, 확정 결정 22)

정본 `docs/products/_platform-core/AUTH_ROADMAP.md` 2.1, 5.2, 7.3절. 1절 표에 없는 인증 경로와 상태를 여기에 둔다. 로그인 뒤 흐름(`/onboarding/disclaimer` → `/dashboard`)과 2.1절 초대 플로우의 시스템 동작(토큰 검증, `redeem_beta_invite`, beta 전환)은 단계와 무관하다.

| 경로 | 화면 | 역할 접근 | 단계 | 우선순위 |
|---|---|---|---|---|
| `/auth/callback` | OAuth 콜백(화면 없음, `finishLogin` 후 이동). invite 앱이라 `bootstrap_app_for_org`를 부르지 않는다 | 누구나 | B·C | P0(B) |
| `/no-access` | 베타 접근 없음 안내(5절 "베타 접근 없음"과 같은 문구 + 초대 이메일 안내 + 로그아웃) | 로그인 | A·B·C | P0 |
| `/invite/continue` | OAuth 왕복 후 초대 수락 이어 가기(쿠키의 초대 값으로 2.1절 3단계 실행, 01_PRD D-23 제안) | 로그인 | B·C | P0(B) |

| 단계 | `/login` 구성 | `/invite/[token]` 구성 |
|---|---|---|
| A(MVP 개발) | 페이지 상단 고정 배지 `MOCK AUTH · 로컬 전용`(모든 화면). "개발용 로그인" 패널: 페르소나 버튼(`05_DATA_MODEL.md` 10절 전체. 예: `owner` 초대 수락·동의 완료, `fresh_beta` 수락·동의 전, `invitee` 초대 미수락, `beta_revoked`, `no_app`, `suspended`, `ops`), 현재 로그인 페르소나, 로그아웃. 실제 제공자 버튼·이메일 폼은 렌더하지 않는다 | 초대 요약(초대 이메일 마스킹, 만료일) + "개발용 로그인으로 계속"(`invitee` 페르소나 버튼). 로그인 후 자동 수락 |
| B(초대 베타 공개 전) | "Google로 계속하기" + 이메일+비밀번호 폼(기존 PRD 범위, 매직링크는 01_PRD D-22). 가입 링크는 두지 않고 "초대받은 분만 사용할 수 있습니다" | "Google로 계속하기"(초대 이메일과 같은 Google 계정 안내 문구 상시) + "이메일로 가입/로그인". Google은 OAuth 후 `/invite/continue`로 돌아와 수락 |

| 상황 | 표시 | 문구 예 |
