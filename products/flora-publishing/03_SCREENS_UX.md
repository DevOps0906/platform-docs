# 03 화면과 UX: FLORA Publishing

2026-10-13 개정: AI 채팅·음성·설정집 화면(3.1절), 디자인 시스템(3.2절), 3D 히어로(4.6절)를 더했다. **메인페이지 히어로는 2026-10-13 사용자 결정(확정 결정 15, `docs/products/00_MERGE_ANALYSIS.md:23`)으로 "판면 정지 렌더 + 판형 전환 1회"에서 3D로 바뀌었다.** 기기 구성·성능 예산·대체 화면은 `docs/design-module/_design-guide/HERO_3D.md`를, 디자인 시스템은 `docs/design-module/_design-guide/DESIGN_SYSTEM.md`를 따른다.

2026-10-14 FLORA 개편(검토용): 제품을 4개 영역(공개 메인페이지, 작가 작업 공간, 에이전트 작업 공간, 운영 콘솔)과 3개 디자인 레이어로 나누고(8절), 랜딩 섹션 6개(8.3절), 에디터 3단 레이아웃과 AI 패널(8.4절), 에이전트 화면(8.5절), 운영 콘솔(8.6절)을 더했다. 기존 4절 토큰·A안·3D 히어로는 그대로이며 제안서의 색·서체·헤드라인은 01장 D23~D25로 올렸다.

작성일 2026-10-12. 화면 구성의 원본은 `Flora-v2/DESIGN.md`(아래 v2 DESIGN)와 `Flora-v2/PRD.md` 3.1절. 메인페이지는 `docs/design-module/_design-guide/DESIGN_PRINCIPLES.md`(아래 DP) 절차를 따른다. 모든 UI 문구는 한국어(`Flora-v2/CLAUDE.md` UI 텍스트 규칙).

화면 구조 패턴(2026-10-14, `docs/design-module/_design-guide/DASHBOARD_PATTERNS.md` 7절 flora-publishing 행을 이 제품에서 확정): 모든 앱 화면은 A(앱 셸). `/dashboard`는 "오늘 처리할 일"(원고 단계별 다음 행동), `/dashboard/books`는 B(리스트-상세), 위저드 `/books/[id]/wizard`와 `/dashboard/books/new`는 I(위저드·단계형), 제작 단계 보드(챕터·소제목 상태)는 D(칸반), `/books/[id]/editor`는 J(에디터 + 미리보기), `/dashboard/agents`·`/admin/jobs`·실행 추적은 N(작업·실행 모니터), `/dashboard/settings`·`/dashboard/billing`은 H(설정). 화면 작업 지시는 `DESIGN_SYSTEM.md` 10장 형식으로 이 패턴 코드를 함께 적는다.

사이드바(대시보드, 2026-10-14): 홈, 내 책, AI 에이전트, 페르소나, 사용량·결제, 설정. 검수 대기 항목이 있으면 "AI 에이전트" 옆에 개수 배지. v2 사이드바의 오디오북·자동화 메뉴는 뺀다(v2 DESIGN 4.2절, 확정 결정 7). 교육·강의 메뉴는 없다(01장 2절).

## 2. 사용자 플로우

### 2.1 가입 → 부트스트랩 → 첫 책

| 단계 | 화면 | 사용자 행동 | 시스템 동작 | 실패 분기 |
|---|---|---|---|---|
| 1 | `/` | "무료로 책 만들기" 클릭 | `/signup` 이동 | - |
| 2 | `/signup`(Stage B부터. Stage A는 `/login` 개발용 패널의 페르소나 버튼으로 바로 4단계) | 이메일·비밀번호 또는 Google | `signUp({data:{signup_app:'publishing'}})` → 인증 메일 | 이미 가입된 이메일: "로그인하거나 비밀번호를 재설정하세요" |
| 3 | `/auth/callback` | 메일 링크 클릭(Google은 계정 선택 후 자동) | 세션 쿠키, `handle_new_user` → 개인 조직, Free 엔타이틀먼트, 20크레딧(OAuth 첫 로그인은 `finishLogin`의 `bootstrap_app_for_org` 1회) | `next` 검증 실패 시 `/dashboard` |

| 5 | `/dashboard/books/new` | "AI로 만들기" | `POST /api/books` → 책 생성 → `/books/[id]/wizard?step=1` | Free 3권 초과: `PB001` → "Free는 책 3권까지입니다. 휴지통을 비우거나 Basic으로 바꾸세요" |
| 6 | 위저드 1~6단계 | 판형, 장르, 페르소나, 제목, 기획안, 목차 선택 | 단계마다 2초 debounce 저장, LLM 단계는 선차감 | 402: 잔액 모달(부족량, 팩 구매 버튼) |
| 7 | 위저드 7단계 | 섹션별 "생성" 또는 "전체 순차 생성"(Basic) | 단건은 스트리밍, 전체는 잡 + Realtime 진행바 | 섹션 실패: 해당 섹션만 빨간 표시 + "다시 생성"(환불 완료 안내) |
| 8 | 8~9단계 | 표지 3후보 중 선택, 책 정보 검토 | fal 잡, 메타데이터 생성 | 표지 일부 실패: 성공한 후보만 표시 + 환불 안내 |
| 9 | 10단계 `/books/[id]/finish` | "PDF 내보내기" | `render.pdf` 잡 → 완료 시 다운로드 버튼(서명 URL 7일), Confetti 1회, 책 `completed` | 렌더 실패: "PDF를 만들지 못했습니다. 크레딧 2를 돌려드렸습니다" + 다시 시도 |

## 7. 로그인 화면의 인증 단계 (2026-10-14 추가, 확정 결정 22)

정본은 `docs/products/_platform-core/AUTH_ROADMAP.md` 2.1, 5.2, 7.1, 7.2, 7.3절이다. 화면은 서버 컴포넌트가 `listLoginOptions('publishing')`(02장 9.2절) 결과로만 그리며, 다른 화면은 단계를 모른다.

### 7.1 단계별 로그인 화면 구성

| 단계 | `/login` | `/signup`, `/reset-password` | 공통 표시 |
|---|---|---|---|
| A(Mock, 로컬 전용) | "개발용 로그인" 패널: 페르소나 버튼(owner, admin, member, viewer, outsider, no_app, suspended, ops, Basic 구독자 `basic`, 05장 10절), 현재 로그인 페르소나, 로그아웃. 버튼은 `POST /api/dev/login { persona, next }` 후 응답 경로로 이동. 제공자 버튼·이메일 폼 없음 | 렌더하지 않는다(404) | 모든 화면 상단 고정 배지 `MOCK AUTH · 로컬 전용`(대비 4.5:1, 닫기 없음). `isMockAuthAllowed()`가 거짓이면 패널·배지 코드를 렌더하지 않는다 |
| B(Google + 이메일) | "Google로 계속하기" 버튼(위) + 구분선 + 이메일·비밀번호 폼(01장 PB-F-001, D22) + "비밀번호를 잊으셨나요" 링크 | 이메일 가입(약관 동의 체크, 메일 인증 안내), 재설정 메일 요청·새 비밀번호 입력 | 배지 없음. OAuth는 가입과 로그인이 같은 버튼이라 `/signup`에도 같은 Google 버튼을 둔다 |
| C1·C2(카카오·네이버) | B 구성 위에 "카카오로 계속하기"(C1), "네이버로 계속하기"(C2) 버튼을 더한다. 버튼 색·문구는 각 사의 디자인 가이드를 따른다(미확인: 최신판 확인 후 반영, C1-5). 운영에서 `AUTH_PROVIDERS`에 없는 제공자는 버튼을 숨긴다 | 같음 | 같음 |

버튼 순서는 Google → 카카오 → 네이버 → 이메일 폼이다(제안: 공개 베타 사용자는 Google로 시작했으므로 위치를 바꾸지 않는다). 모든 버튼은 Lucide 아이콘이 아니라 제공자 로고 SVG를 쓰며 이모지는 쓰지 않는다(6절).

OAuth는 가입 폼이 없으므로 약관 동의를 제품 온보딩 첫 단계에서 받는다. `/onboarding`(2.6절)을 2단계로 쓴다.

### 9.4 이중 타임라인 (PB-F-069)

랜딩 4번 섹션과 에이전트 작업 상세(8.5절 타임라인)가 같은 두 줄 구조를 쓴다. 승인이 필요한 단계는 저자 줄에 "승인"을 붙인다.

| 단계 | 저자가 하는 일 | FLORA가 하는 일 |
|---|---|---|
| 기획 | 판형·장르·페르소나를 고르고 기획안 하나를 고른다 | 제목 후보와 기획안 3종을 만든다 |
| 목차 | 목차 3안 중 하나를 고쳐 구조를 저장한다(승인) | 목차 3안을 만든다. 업로드 원고는 장·절을 읽어 목차로 바꾼다 |
| 집필 | 직접 쓰거나 초안을 요청하고, 본문이 있던 곳의 제안은 비교 후 반영한다(승인) | 소제목 단위로 초안을 만들고 실패한 소제목만 다시 만든다 |
| 편집 | 수정안을 비교해 반영한다(승인) | 다듬기·문체 확인 수정안을 만든다 |
| 출판 | 내보내기 전 확인을 보고 내려받는다 | 판형에 맞춰 PDF·ePub을 렌더하고 검사 결과를 보여 준다 |

작업 상세에서는 "대기 → 실행 → 노드별 진행 → 완료"가 FLORA 줄, 검수 결정·재시도가 저자 줄이다(8.5절 작업 상세 표의 타임라인 행을 두 줄로 나눈다).

## 10. 대시보드 셸과 좌측 GNB (2026-10-19 추가, 원본 프로젝트 메뉴 이행)

이 장은 FLORA Publishing 작가 작업 공간(8.1절 B·C 영역)의 공통 셸(헤더 + 좌측 GNB)과 홈 구성을 정한다. 목적은 원본 4개 프로젝트의 메뉴·기능이 모두 새 구조 어딘가로 이행되게 하는 것이다. 원본은 Flora-v2 기능 묶음(`docs/reviews/Flora-v2.md:30-32`), flora v1 기능 묶음(`docs/reviews/flora.md:30-34`), flora-publisher 사이드바 6개 메뉴(`docs/reviews/flora-publisher.md:6`, `:22`), SellingDocs 기능 요구 4묶음(`docs/reviews/SellingDocs.md:32`)이다. 1절 화면 표의 경로·권한·플랜과 1절 사이드바 문단(:47)의 6개 메뉴는 그대로 두고, 이 장은 메뉴 순서·묶음·셸 동작과 GNB 항목 1개("새 책 만들기", 경로는 1절 :23에 이미 있음)만 더한다. 새 경로는 만들지 않는다. 운영 콘솔(`/admin/*`, 8.6절)은 `ops` 레이어의 별도 셸이라 이 장의 대상이 아니다(8.1절 :505). 다른 제품과 `_design-guide` 공용 패턴은 바꾸지 않는다(FLORA Publishing 전용).

### 10.5 홈 구성 (`/dashboard`, 1절 홈 행 구체화)

위에서 아래 순서. 1절 패턴 열 "B 변형(오늘 할 일)"(:21)과 화면 구조 패턴 문단의 "오늘 처리할 일(원고 단계별 다음 행동)"(:45)을 따른다. 주인공은 만들던 책이다(8.1절 B 영역 "만들던 책으로 돌아가 다음 일을 끝내기"). 큰 숫자 KPI 카드를 두지 않는다(8.2절 marketing 행 :515의 "큰 숫자" 금지를 작업 공간에도 적용, 제안).

| 순서 | 영역 | 내용 | 누르면 |
|---|---|---|---|
| 0 | 인사 1줄 | "작업을 이어가세요."(8.4절 :567 와이어프레임 문구) | - |
