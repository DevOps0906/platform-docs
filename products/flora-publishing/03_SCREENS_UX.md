# 03 화면과 UX: FLORA Publishing

작성일 2026-10-12. 화면 구성의 원본은 `Flora-v2/DESIGN.md`(아래 v2 DESIGN)와 `Flora-v2/PRD.md` 3.1절. 메인페이지는 `docs/products/_design-guide/DESIGN_PRINCIPLES.md`(아래 DP) 절차를 따른다. 모든 UI 문구는 한국어(`Flora-v2/CLAUDE.md` UI 텍스트 규칙).

## 2. 사용자 플로우

### 2.1 가입 → 부트스트랩 → 첫 책

| 단계 | 화면 | 사용자 행동 | 시스템 동작 | 실패 분기 |
|---|---|---|---|---|
| 1 | `/` | "무료로 책 만들기" 클릭 | `/signup` 이동 | - |
| 2 | `/signup` | 이메일·비밀번호 또는 Google | `signUp({data:{signup_app:'publishing'}})` → 인증 메일 | 이미 가입된 이메일: "로그인하거나 비밀번호를 재설정하세요" |
| 3 | `/auth/callback` | 메일 링크 클릭 | 세션 쿠키, `handle_new_user` → 개인 조직, Free 엔타이틀먼트, 20크레딧 | `next` 검증 실패 시 `/dashboard` |
| 4 | `/dashboard` | 첫 방문 | `session_context` 1회 조회, 시드 3종과 "AI로 책 만들기" 표시 | 프로필 없음 → 로그아웃 후 `/login`(기본 admin 금지) |
| 5 | `/dashboard/books/new` | "AI로 만들기" | `POST /api/books` → 책 생성 → `/books/[id]/wizard?step=1` | Free 3권 초과: `PB001` → "Free는 책 3권까지입니다. 휴지통을 비우거나 Basic으로 바꾸세요" |
| 6 | 위저드 1~6단계 | 판형, 장르, 페르소나, 제목, 기획안, 목차 선택 | 단계마다 2초 debounce 저장, LLM 단계는 선차감 | 402: 잔액 모달(부족량, 팩 구매 버튼) |
| 7 | 위저드 7단계 | 섹션별 "생성" 또는 "전체 순차 생성"(Basic) | 단건은 스트리밍, 전체는 잡 + Realtime 진행바 | 섹션 실패: 해당 섹션만 빨간 표시 + "다시 생성"(환불 완료 안내) |
| 8 | 8~9단계 | 표지 3후보 중 선택, 책 정보 검토 | fal 잡, 메타데이터 생성 | 표지 일부 실패: 성공한 후보만 표시 + 환불 안내 |
| 9 | 10단계 `/books/[id]/finish` | "PDF 내보내기" | `render.pdf` 잡 → 완료 시 다운로드 버튼(서명 URL 7일), Confetti 1회, 책 `completed` | 렌더 실패: "PDF를 만들지 못했습니다. 크레딧 2를 돌려드렸습니다" + 다시 시도 |

### 2.2 원고 업로드 경로

| 단계 | 화면 | 사용자 행동 | 시스템 동작 | 실패 분기 |
|---|---|---|---|---|
| 1 | `/dashboard/books/new/upload` | 권리 확인 체크 후 파일 선택(드래그) | `POST /api/uploads`로 서명 업로드 URL 발급 → Storage 직접 업로드 | Free: "원고 업로드는 Basic에서 쓸 수 있습니다" |
| 2 | 같은 화면 | 업로드 완료 | `POST /api/uploads/[id]/complete` → 크기·형식 재검사 → 파싱 잡 → 진행 표시 | 20MB 초과 413, 형식 불일치 415, 파싱 실패: "문서 구조를 읽지 못했습니다. txt나 md로 저장해 다시 올려 주세요" |
| 3 | 같은 화면 | 챕터·소제목 미리보기 확인 → "이 구조로 시작" | 책 생성(`source='upload'`) + 챕터·섹션 INSERT(원문 본문) | 플랜 한도 초과 구조: 초과분 목록을 보여 주고 Basic 안내 |
| 4 | 위저드 1~3단계 → 4·5 간소화 → 7단계 | 판형·장르·페르소나 선택, 제목·기획안 제안 수락 | 기획 검토 LLM | 402 처리 동일 |

### 2.3 크레딧팩 결제

| 단계 | 화면 | 사용자 행동 | 시스템 동작 | 실패 분기 |
|---|---|---|---|---|
| 1 | 402 모달 또는 `/dashboard/billing` | 팩 선택 | `POST /api/billing/orders`(서버가 금액 결정, `payment_orders` 선저장) | owner/admin 아님: 403 |
| 2 | Toss 결제창 | 결제 | - | 사용자 취소 → `/dashboard/billing/fail` |
| 3 | `/dashboard/billing/success` | 복귀 | `POST /api/billing/confirm` → Toss confirm → `confirm_payment_order` → pack 크레딧 지급 | `PM001` 금액 불일치: "결제 확인에 실패했습니다. 승인 취소를 요청했습니다" + 운영 알림 |
| 4 | 원래 화면 | 이어서 생성 | 잔액 갱신(세션 컨텍스트 재조회) | - |

### 2.4 Basic 구독

| 단계 | 화면 | 사용자 행동 | 시스템 동작 | 실패 분기 |
|---|---|---|---|---|
| 1 | `/pricing` 또는 `/dashboard/billing` | "Basic 시작" | 빌링키 발급창(customerKey = `org_<org_id>`) | - |
| 2 | 복귀 | - | 빌링키 암호화 저장 → 첫 결제 주문 → confirm → 구독 active, 엔타이틀먼트 basic, 200크레딧 | 첫 결제 실패: 구독 생성 안 함, 카드 안내 |
| 3 | 매월 | - | 정기결제 워커, 실패 시 past_due → 재시도 1/3/7일 → canceled(CS 5.3) | past_due 배너 "결제 수단을 확인하세요" |
| 4 | `/dashboard/billing` | "해지" | 해지 예약(기간 말까지 Basic) | - |

### 2.5 전체 순차 생성과 취소

| 단계 | 화면 | 사용자 행동 | 시스템 동작 | 실패 분기 |
|---|---|---|---|---|
| 1 | 7단계 | "전체 순차 생성" | 확인 모달: 대상 섹션 수, 예상 크레딧, 현재 잔액 | 잔액 부족: 모달 안에 부족량과 팩 구매 |
| 2 | 7단계 | 확인 | 실행 생성 + 부모 잡, 진행바(완료/전체), 섹션별 상태 칩 | 이미 진행 중: 409 "이 책은 이미 생성 중입니다" |
| 3 | 7단계 | "중단" | `request_generation_cancel` → 60초 안에 새 섹션 시작 중지, 대기 섹션 환불 | 이미 끝남: `PB007` → 상태 새로고침 |
| 4 | 7단계 | 완료 확인 | `succeeded` 또는 `partial`(실패 섹션 목록과 "실패한 섹션만 다시 생성") | - |

## 3. 화면별 명세

| 화면 | 목적 | 구성 | 데이터 출처 | 행동 | 크레딧 표시 |
|---|---|---|---|---|---|
| 대시보드 홈 | 다음 책을 바로 시작 | 인사 1줄, 큰 버튼 2개(AI로 만들기, 내 원고로 만들기), 시작 템플릿 3, 최근 책 6 | `session_context`, `books`(최근 수정순) | 책 생성, 시드 복제 | 상단바에 잔액(plan + pack) 상시 |
| 위저드 셸 | 10단계 진행 | 상단 원형 진행바(모바일은 "3/10"), 본문, 하단 이전/다음 | `books.current_step`, `step_state` | 완료 단계만 이동 | LLM 버튼 옆에 "1크레딧" 같은 비용 라벨 |
| 1단계 판형 | 판형 선택 | 6장 카드(실물 비율 미리보기, 크기, 본문 pt, 추천 장르) + 우측 Auto-Fit 스펙 | `src/data/formats.json` | 선택, 미세조정 슬라이더 | 없음 |
| 3단계 페르소나 | 문체 선택 | 장르 탭, 60장 카드(Free는 41번째부터 잠금), 즐겨찾기 별 | `personas.json`, `member_settings` | 선택, 즐겨찾기 | 없음 |
| 4~6단계 | 제목, 기획안, 목차 | 후보 카드/탭, 인라인 편집, 목차 트리 드래그 정렬, 챕터·소제목·단락 수 슬라이더(플랜 한도 표시) | LLM 응답, `books.plan_brief`, `chapters`, `sections` | 생성, 선택, 편집 | 각 생성 버튼 비용 |
| 7단계/에디터 | 원고 작성 | 좌: 목차(섹션 상태 칩), 중: 본문(Tiptap), 선택 시 플로팅 툴바, 우: 활성 문체 배지·어조(Basic) | `sections`, Realtime | 섹션 생성, 전체 생성, 선택영역 보조, Diff 수락 | 툴바 항목별 비용, 전체 생성 예상치 |
| 8단계 표지 | 표지 선택 | 스타일 5칩, 3후보 그리드, 제목·저자 오버레이 입력 | `cover_images` | 생성, 선택 | 6크레딧 |
| 9단계 책 정보 | 메타데이터 | 폼(제목, 부제, 저자, 장르, 키워드 5, 소개 200자, 출판사, ISBN 형식 + 참조용 고지) | `books.book_info` | AI 작성, 편집 | 1크레딧 |
| 완성 | 산출물 받기 | 좌: 미리보기(같은 HTML, 판형 비율 iframe), 우: PDF/ePub 버튼, 워터마크 여부, 이번 달 남은 내보내기 수(Free), 내보내기 기록(만료일) | `book_exports`, `core.jobs` | 내보내기, 다운로드, 공개 페이지(Phase 2) | PDF 2, ePub 1, 같은 원고 재다운로드 0 |
| 결제 | 잔액과 결제 | 플랜 카드 2, 팩 카드 2, 잔액(plan/pack 분리), 사용 내역 표(원장), 결제 내역 | `credit_balances`, `credit_ledger`, `payments`, `plans`, `credit_packs` | 팩 구매, 구독 시작/해지 | 전부 |
| 설정 | 계정과 화면 | 표시 이름, 화면 테마 7(잠금 표시), 기본 생성 모드, 계정 삭제(확인 문구 입력) | `profiles`, `member_settings` | 저장, 삭제 요청 | 없음 |
| 알림 연동 | 웹훅 | URL 목록, 이벤트 체크, 비밀 1회 표시, 최근 전송 20건 | `webhook_endpoints`, `webhook_deliveries` | 추가, 비활성, 테스트 전송 | 없음 |
| 운영자 | 운영 | 지표 표, 조직 검색, 수동 크레딧 조정(사유 필수), 렌더 실패 목록 | service_role 서버 조회 | 조정(감사 기록) | - |

### 4.5 생성형 기본값 회피 검토 (DP 5단계, `DESIGN_PRINCIPLES.md:114-127`)

| # | 기본값 | 이 계획의 상태 |
|---|---|---|
| 1 | 크림 배경 + 고대비 세리프 + 테라코타 | 배경은 차가운 교정지 회색, 강조는 시안. 세리프는 디스플레이에만 |
| 2 | 거의 검정 + 애시드 그린/버밀리언 | 사용 안 함. v2 다크 + 보라는 랜딩에서 뺀다 |
| 3 | 헤어라인 브로드시트 | 괘선은 재단선 모티프에만, 다단 신문 구성 없음 |
| 4 | SaaS 카드 키트 | 기능 카드 그리드 없음. 섹션 4개 |
| 5 | 대문자 아이브로, 가운데 점 메타, `→` 버튼 | 사용 안 함. 버튼 문구는 동작을 말함 |
| 6 | 큰 숫자 히어로 | 사용 안 함(허위 수치 금지와도 일치) |
| 7 | 한 단어 강조 헤드라인 | 사용 안 함 |
| 8~9 | 대문자 라벨, 불필요한 라벨 | 사용 안 함 |
| 10 | 의미 없는 번호 | "만드는 순서"는 실제 순서라서만 번호 사용 |
| 11 | 섹션마다 페이드 업 | 로드 시 판형 전환 1회만 |
| 12 | 습관적 기본 서체 | 마루부리 + IBM Plex Sans KR, 이유는 4.3절 |

카피 점검(01장 6절): "베스트셀러", "보장", 사용자 수·출간 수 같은 숫자, 가상 후기를 쓰지 않는다. 헤드라인 예: "원고를 넣으면 이 판형의 인쇄용 PDF와 ePub이 됩니다"(DP 카피 규칙 예시와 같은 방향, `DESIGN_PRINCIPLES.md:194`).
