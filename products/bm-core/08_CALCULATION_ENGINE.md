# 08 계산 엔진: BM-Core

작성일 2026-11-11. 근거 원본 B장 6·7·8·12·14, A장 4~7단계(`research/00_SOURCE_DESIGN.md`). 자유 구조 문서. 모든 수치·규칙은 "제안"이며 원본 값(BookForge)은 가정치다. 엔진 버전 `1.0.0`(제안). 계산은 `packages/bm-engine`(React·Supabase 비의존 순수 TS)에서만 한다. AI는 계산하지 않는다(`02_ARCHITECTURE.md#5`).

## 1. 원칙

| 원칙 | 내용 |
|---|---|
| 결정론 | 같은 입력 + 같은 엔진 버전 = 같은 결과. 시계·난수·I/O 없음 |
| Decimal | 내부는 임의 정밀 Decimal(라이브러리 `미확인`, 착수 시 선정). JS `number` 금지 |
| 재현 | `calculation_runs`에 `input_snapshot`, `result`, `engine_version`, `warnings`를 함께 저장(`05_DATA_MODEL.md#2.12`) |
| 설명 | 결과마다 쓴 공식 id와 가정 목록(`assumptions[]`: key, value, grade)을 포함 |
| 예측·실측 구분 | 입력마다 출처 `forecast`/`actual`을 표시한다. 단순 LTV는 이탈률이 일정하다는 가정을 경고로 남긴다 |
| 병합 조건 | 기존 테스트 전부 통과해야 병합(CI, 원본 14장) |

## 2. 공식

| 지표 | 공식 | 단위 | 비고 |
|---|---|---|---|
| ARPU | 기간 매출 ÷ 평균 유료 고객 | 원/월 | 고객 0이면 4절 |
| 변동비 합계 | 고객당 변동비 항목 합(`variable_per_user` + 단위 환산한 `usage_based`) | 원/월/고객 | 결제수수료율은 매출 × 율로 환산 |
| 공헌이익(CM) | 매출 − 변동비 | 원/월/고객 | 고객당 기준 |
| 공헌이익률 | CM ÷ 매출 | 비율 | |
| 단순 LTV | 월 고객당 CM ÷ 월 이탈률 | 원 | 이탈률 일정 가정. 코호트 LTV로 확장(이후) |
| 평균 고객 수명(부수, 제안) | 1 ÷ 월 이탈률 | 개월 | "수명 미검증" 경고와 함께 |
| LTV/CAC | LTV ÷ 실제 CAC | 배 | CAC 가정 입력 필요 |
| CAC 상한(`cacCeiling`) | LTV ÷ 목표 배수(기본 3, 입력 가능) | 원 | 실제 CAC와 별도 필드 |
| CAC 회수기간 | CAC ÷ 월 고객당 CM | 개월 | |
| BEP 고객 | 월 고정비 ÷ 월 고객당 CM | 명(올림) | 파트별 BEP는 배분 후 같은 공식(제안) |
| MRR | Σ(요금제 월 환산 가격 × 유료 고객 수) | 원/월 | 연 요금제는 ÷12 |
| ARR | MRR × 12 | 원/년 | 할인·환불·부가세·수수료·AI비·이탈 미반영 표시 |
| 월 영업손익 | 총 공헌이익 − 월 고정비 | 원/월 | 총 공헌이익 = CM × 고객 수 |
| 사업성 점수 | 5축 × (지표 4개 × 0~5점) = 축당 0~20, 합 0~100 | 점 | 6절 |

## 3. 반올림과 정밀도

반올림은 **저장·표시 시점의 마지막 한 번만** 한다. 중간 계산은 전체 정밀도를 유지한다(제안).

| 대상 | 규칙 | 근거 |
|---|---|---|
| KRW 금액(LTV, CM, ARPU, CAC 상한) | 원 단위 정수, half-up(0.5 올림) | 733,333.33 → 733,333 |
| 비율(CM률, 이탈률) | 소수 8자리 half-up(`numeric(12,8)`) | 5% = 0.05 |
| LTV/CAC, 회수기간 | 소수 2자리 half-up | 4.51 |
| BEP 고객 수 | 올림(ceil). 정수 명 | 222.22 → 223(반올림이면 222로 손익분기 미달) |
| 통화 | `currency` 필수. KRW 외 통화는 소수 자릿수를 통화표로 지정(이후, 1.0은 KRW만) | |
| 배분 잔여 | 최대잔여법(6절) | 합계 = 원 총비용 |

## 4. 경계조건

| 조건 | 동작 | 결과 필드 / 경고 코드 |
|---|---|---|
| 월 이탈률 = 0 | LTV 계산 불가. 무한대를 반환하지 않는다 | `ltv: null`, `LTV_UNBOUNDED` |
| 이탈률 < 0 또는 > 1 | 입력 오류(422 `validation_failed`, 엔진 `INVALID_INPUT`) | 결과 없음 |
| 매출(ARPU) = 0 | CM률 계산 불가 | `contributionMarginRate: null`, `ZERO_REVENUE` |
| 유료 고객 = 0 (ARPU 분모) | ARPU 계산 불가 | `arpu: null`, `NO_CUSTOMERS` |
| CM ≤ 0 | BEP·LTV 의미 없음. 음수 LTV를 만들지 않는다 | `breakEvenCustomers: null`, `ltv: null`, `NEGATIVE_CONTRIBUTION`. CM 자체는 음수로 반환 |
| 고정비 = 0 | BEP 0명 | `breakEvenCustomers: 0` |
| CAC 미입력 또는 0 | LTV/CAC·회수기간 계산 안 함 | `ltvCacRatio: null`, `CAC_MISSING`. `cacCeiling`은 계산 |
| 음수 금액 입력 | 입력 오류 | `INVALID_INPUT` |
| 배분 합계 ≠ 원 총비용 | 내부 불변식 위반. 저장하지 않고 오류 | `ALLOCATION_SUM_MISMATCH`(엔진 버그 신호) |
| 모든 입력이 forecast | 항상 경고 | `UNVALIDATED_INPUTS`(검증도와 연결) |

## 5. 시나리오

월 요금 29,000원 공통. 파라미터만 바꿔 같은 엔진을 호출한다.

| 시나리오 | 변동비 | 월 이탈률 | 월 고정비 | CM | LTV | BEP |
|---|---|---|---|---|---|---|
| 보수적 | 11,000 | 9% | 4,000,000 | 18,000 | 200,000 | 223명 |
| 기준 | 8,700 | 5% | 3,000,000 | 20,300 | 406,000 | 148명 |
| 낙관적 | 7,000 | 3% | 2,500,000 | 22,000 | 733,333 | 114명 |

민감도(P1 차트용, 제안): 한 파라미터를 ±구간으로 바꿔 지표 변화를 계산하고 나머지는 고정한다. 시나리오 분석 모듈 `scenario-analysis`가 담당한다.

## 6. 배분

| 항목 | 규칙 |
|---|---|
| 원칙 | 공통비는 원인 기준 우선: 서버·API = 사용량, 인건비 = 투입 시간(또는 매출 비중), 마케팅 = 캠페인 귀속(원본 6장, A장 5단계 파트 표) |
| 구성 | `allocation_rules.configuration = {weights:{<part_id>:number}}`. 가중치는 비율이 아니라 기준값(사용량·시간·매출) 그대로이고 엔진이 정규화한다(0.33333333 × 3 ≠ 1 문제 방지) |
| 계산 | 파트 몫 = 총비용 × 가중치 ÷ 가중치 합 |
| 반올림 | 최대잔여법: 원 단위 내림 후 남은 원을 소수부가 큰 순으로 1원씩. 동률은 `part_id` 오름차순 |
| 불변식 | 파트 몫 합 = 원 총비용(오차 0). 가중치 합 ≤ 0 또는 파트 누락이면 `BM002`/`INVALID_INPUT` |
| 직접비 | `direct` 기준은 해당 파트에 100% 귀속 |

## 7. BookForge 기대값 (회귀 기준)

원본 A·B장의 가정치. 엔진 결과는 아래와 정확히 일치해야 한다(제안: 허용 오차 0).

| 지표 | 입력/식 | 기대값 |
|---|---|---|
| ARPU | 29,000 | 29,000원 |
| 변동비 | AI API 5,500 + 결제수수료 1,000 + CS 2,200 | 8,700원 |
| 공헌이익 | 29,000 − 8,700 | **20,300원** |
| 공헌이익률 | 20,300 ÷ 29,000 | 0.70(70.0%) |
| LTV | 20,300 ÷ 0.05 | **406,000원** |
| LTV/CAC | 406,000 ÷ 90,000(CAC 90,000 가정) | 4.51 |
| CAC 상한 | 406,000 ÷ 3 | 135,333원(원본은 ≈135,000 근사 표기) |
| CAC 회수기간(파생) | 90,000 ÷ 20,300 | 4.43개월 |
| BEP 고객(기준) | 3,000,000 ÷ 20,300 = 147.78 | **148명** |
| BEP 고객(보수적) | 4,000,000 ÷ 18,000 = 222.22 | **223명** |
| BEP 고객(낙관적) | 2,500,000 ÷ 22,000 = 113.64 | **114명** |
| LTV(보수적) | 18,000 ÷ 0.09 | 200,000원 |
| LTV(낙관적) | 22,000 ÷ 0.03 = 733,333.33 | 733,333원 |
| 공헌이익률(보수·낙관) | 18,000÷29,000, 22,000÷29,000 | 0.62068966 / 0.75862069 |
| MRR(원본 13장) | 50 × 19,900 + 20 × 49,000 + 5 × 129,000 | 2,620,000원/월 |
| ARR | 2,620,000 × 12 | 31,440,000원 |
| 월 영업손익(원본 C장 Sankey) | 총매출 6,000,000 − 변동비 2,300,000 = CM 3,700,000; − 고정비 2,500,000 | 1,200,000원 |
| 점수 합계(원본 A장 7단계) | 14 + 16 + 4 + 17 + 16 | 67점 → 60~79 구간 |

점수 구간(원본 A장 흐름): 80 이상 = MVP 개발·지원사업 신청 / 60~79 = 부족한 축 추가 검증 / 40~59 = 노코드 MVP로 축소 / 40 미만 = 보류·폐기. 경계는 하한 포함(80은 최상위 구간). blocking 조건이 하나라도 있으면 점수와 무관하게 승인 불가(85점이어도 보류, 원본 8장).

## 8. 테스트 픽스처

위치 `packages/bm-engine/fixtures/*.json`, 테스트 `packages/bm-engine/tests/`. 금액은 문자열로 직렬화해 Decimal 입력을 보장한다. 아래 입력 중 "경계"와 "배분 반올림" 수치는 테스트용 제안값이다.

| 픽스처 id | 입력 요약 | 기대 |
|---|---|---|
| `bookforge-base` | 7절 기준 입력(CAC 90,000) | 7절 기준 열 전부 |
| `bookforge-conservative` / `-optimistic` | 5절 입력 | CM 18,000·LTV 200,000·BEP 223 / CM 22,000·LTV 733,333·BEP 114 |
| `mrr-arr-sample` | 플랜 3종 × 고객 50·20·5 | MRR 2,620,000, ARR 31,440,000 |
| `operating-profit-sample` | 고객 수·CM·고정비 | 월 영업손익 1,200,000 |
| `boundary-churn-zero` | 이탈률 0 | `ltv: null`, `LTV_UNBOUNDED` |
| `boundary-negative-cm` | 변동비 30,000(CM −1,000) | CM −1,000, `ltv: null`, `breakEvenCustomers: null`, `NEGATIVE_CONTRIBUTION` |
| `boundary-zero-revenue` | ARPU 0 | CM률 null, `ZERO_REVENUE` |
| `boundary-invalid-churn` | 이탈률 −0.01, 1.01 | `INVALID_INPUT`(결과 없음) |
| `boundary-no-cac` | CAC 없음 | `ltvCacRatio: null`, `CAC_MISSING`, `cacCeiling` 계산됨 |
| `boundary-bep-exact` | 고정비 ÷ CM이 정수(예 3,000,000 ÷ 20,000 = 150) | 150(올림이 초과하지 않음) |
| `allocation-rounding` | 총비용 100원, 가중치 1:1:1 | 34/33/33(합 100) |
| `allocation-usage` | 총비용 1,000,000원, 가중치 60:25:15 | 600,000/250,000/150,000 |
| `allocation-invalid` | 가중치 합 0 | `INVALID_INPUT` |
| `score-bookforge` | 축 점수 14,16,4,17,16 | 67, 구간 60~79 |
| `score-blocking` | 총점 85 + 실결제 0건 blocking | 승인 불가, `blockingHits` 1건 |
| `score-band-edges` | 총점 80, 79, 60, 59, 40, 39 | 80 최상위 / 79·60 → 60~79 / 59·40 → 40~59 / 39 → 보류 |
| `repro-hash` | 같은 입력 2회 | `input_hash`·결과 동일, 엔진 버전 변경 시 버전 필드만 다름 |

추가 테스트: 속성 테스트(배분 합 = 총비용, BEP × CM ≥ 고정비 > (BEP−1) × CM, 입력 순서 불변), 엔진 버전 승격 시 이전 `calculation_runs` 재계산 비교(차이는 변경 로그에 기록). 원본 12장 인수 기준 "계산 공식·경계값 전부 통과, 배분 합계 일치"가 이 표의 통과 조건이다.
