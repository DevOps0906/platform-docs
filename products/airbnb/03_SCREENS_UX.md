# 03 화면과 UX: Stay(가칭)

근거 약어는 01장과 같다(리뷰, 원본, SQL, seed). 원본 화면(`pages/**`, `components/**`)은 흐름과 입력 항목의 근거로만 쓰고 배치·색·아이콘은 옮기지 않는다(01장 D14). 게스트 화면은 소비자 앱, 호스트 화면은 앱 셸(8절) 안의 관리 화면이다.

## 2. 사용자 플로우

### 2.1 검색 → 예약 요청

| 단계 | 화면 | 사용자 행동 | 시스템 동작 | 실패 분기 |
|---|---|---|---|---|
| 1 | `/` | 지역 입력(자동완성), 체크인·체크아웃, 인원 선택 후 검색 | 지역 → 지도 경계로 변환(`/api/maps/places`), `/search?…`로 이동 | 지역 미선택이면 현재 지도 기본 경계(서울) |
| 2 | `/search` | 목록을 훑고 지도를 움직인다 | `search_listings`(경계·날짜·인원), 지도 이동 400ms 디바운스 후 재검색 | 결과 0건: 5절 빈 화면(날짜·인원 완화 제안) |
| 3 | `/listings/[id]` | 사진·정보·리뷰 확인, 달력에서 날짜 조정 | `get_listing_public`, `listing_unavailable_ranges`, `listing_reviews_public` | 비공개·삭제 숙소 404 |

| 5 | `/listings/[id]/book` | 금액 확인, 호스트에게 메시지(선택), "요청 보내기" | `create_reservation` → requested, 24시간 응답 기한 표시 | SY002·SY003·SY004·SY005·SY429는 5절 문구, 날짜를 바꾸면 다시 시도 |
| 6 | `/trips/[id]` | 요청 상태 확인 | 호스트에게 메일(SY-F-024). 승인되면 상태 갱신 + 주소 표시 | 24시간 무응답 → expired, "다른 숙소 찾기" 버튼 |

### 2.3 숙소 등록 → 게시 (등록 마법사)

원본 13단계(`pages/room/register/*`) 순서를 유지한다. 단계마다 "저장하고 계속"이 서버에 저장(`register_step` 갱신)하고, "나가기"는 그대로 나가도 다음에 마지막 단계에서 다시 연다.

| 단계 | 화면(`edit/[step]`) | 사용자 행동 | 시스템 동작 | 실패 분기 |
|---|---|---|---|---|
| 0 | `/host/listings/new` | "숙소 등록 시작" | `create_listing` → draft, `edit/building`으로 이동 | 4번째 숙소: SY012 "무료 베타는 숙소 3개까지" |
| 1 | `building` | 큰 건물 유형 → 세부 유형, 숙소 유형(집 전체/개인실/다인실), 게스트 전용 여부 | RLS UPDATE(`large_building_type`, `building_type`, `room_type`, `is_set_up_for_guest`) | 필수 미선택 시 버튼 비활성 |
| 2 | `bedrooms` | 최대 인원, 침실 수, 침실별 침대 | `max_guests`, `bedroom_count`, `bed_count`, `bed_list` | 인원 1~16 범위 |
| 3 | `bathroom` | 욕실 수(0.5 단위), 전용/공용 | `bathroom_count`, `bathroom_type` | - |
| 4 | `location` | 주소 검색 또는 직접 입력 | 서버 지오코딩 → `listing_private`(주소·우편번호) | 검색 결과 없음: 직접 입력 + 지도에서 핀 |
| 5 | `geometry` | 지도 핀 위치 미세 조정 | `listing_private.lat/lng` 저장 → 공개 좌표 소수 2자리 | "게스트에게는 약 1km 범위만 보입니다" 안내 고정 |
| 6 | `amenities` | 편의시설 체크 | `amenities` | - |
| 7 | `conveniences` | 게스트가 쓸 수 있는 공간 체크 | `conveniences` | - |
| 8 | `photo` | 사진 끌어 놓기, 순서·대표 지정, 캡션 | 서명 업로드 URL → Storage → `listing_photos` INSERT → 변환 잡 | 형식·크기·31장째 거부(5절), 업로드 실패 사진만 재시도 |
| 9 | `description` | 설명 작성 또는 "AI 초안"(2.8) | `description`, `house_rules` | 5,000자 초과 차단 |
| 10 | `title` | 제목(50자) 작성 또는 AI 제목 3안에서 고르기 | `title` | - |
| 11 | `price` | 1박 요금, 청소비 | `price_per_night`, `cleaning_fee` | 10,000원 미만 차단 |
| 12 | `date` | 운영 기간, 최소·최대 박수, 체크인·아웃 시각, 즉시 예약 | `available_from/to`, `min/max_nights`, `check_in/out_time`, `instant_book` | 최소 > 최대 차단 |
| 13 | `checklist` | 빠진 항목 확인, 영업신고 확인 체크(D7), "게시" | `transition_listing('published')` | SY010: 빠진 항목 목록을 단계 링크로 표시 |

## 3. 화면별 명세

### 3.1 홈·랜딩 `/`

목적: 검색 시작. 데이터: 추천 지역(정적), 3D 히어로(시연 데이터). 행동: 검색, 말로 찾기(로그인 후). 크레딧 표시: 말로 찾기 버튼 옆 "1크레딧".

```
+----------------------------------------------------------------------+
| [로고]                         숙소 올리기   로그인                   |
|                                                                      |
|  어디로 떠나세요?                         .-- 3D 히어로 --.            |
|  +------------+-----------+-----------+  | 펼쳐지는 지도  |            |
|  | 지역       | 체크인~아웃 | 인원      |  |  집 핀 솟음    |            |
|  +------------+-----------+-----------+  '----------------'            |
|  [ 검색 ]   또는  [ 말로 찾기 ]          (시연 화면입니다)             |
|                                                                      |
|  추천 지역:  강릉  제주  경주  여수  전주                              |
+----------------------------------------------------------------------+
```

### 3.2 검색 결과 `/search`

목적: 조건에 맞고 비어 있는 숙소 비교. 데이터: `search_listings`(카드: 대표 사진, 제목, 지역, 1박 요금, 별점·리뷰 수, 인원). 행동: 필터(가격, 유형), 지도 이동 재검색, 카드 호버 → 핀 강조, 찜. 크레딧 표시: 없음.

```
+------------------------------------------------------------------+

+-------------------------------+----------------------------------+
| 숙소 24곳 (지도 범위)          |                                  |

| [더 보기]                      |                                  |
+-------------------------------+----------------------------------+
모바일: 목록 기본, 하단 "지도 보기" 버튼으로 전환
```

목적: 결정. 데이터: `get_listing_public`, `listing_unavailable_ranges`(400일), `listing_reviews_public`, 리뷰 요약(`ai_runs` 최신, 10건 이상). 행동: 사진 전체 보기, 날짜·인원 선택, 예약, 찜, 도우미 시트, 공유. 크레딧 표시: 도우미 버튼 "질문 1회 1~2크레딧".

### 3.4 예약 확인 `/listings/[id]/book`

목적: 마지막 확인. 데이터: 상세 데이터 + 계산 금액(SY-F-007). 행동: 기간·인원 수정(상세로), 메시지 입력, 요청 보내기. 크레딧 표시: 없음. 하단 고지: "베타 기간에는 결제가 없습니다. 호스트가 승인하면 주소와 체크인 안내가 열립니다."

### 3.5 내 여행 `/trips`, `/trips/[id]`

목적: 예약 상태와 숙박 정보. 데이터: `my_trips`. 카드: 상태 배지, 기간, 숙소 카드, 남은 응답 시간(requested), 주소(confirmed·completed만), 리뷰 버튼. 행동: 취소, 리뷰 쓰기, 지도 열기. 크레딧 표시: 없음.

```
+----------------------------------------------+
| 다가오는 여행 | 지난 여행 | 취소              |
+----------------------------------------------+
| [확정] 10/30~11/2 바다 앞 독채                |
|   강원 강릉시 해안로 1, 101호  [지도] [안내]   |
|   [예약 취소]                                 |
| [요청 중] 11/9~11/10  응답 기한 21시간 남음    |
|   주소는 승인 후 보입니다      [요청 취소]     |
+----------------------------------------------+
```

### 3.6 호스트 홈 `/host`, 숙소 목록 `/host/listings`

목적: 오늘 할 일. 데이터: `host_reservations`(requested, 오늘 체크인·아웃), `listings`(RLS). 홈 KPI 카드 3개: 응답 대기, 이번 주 체크인, 게시 중 숙소. 목록 열: 대표 사진, 제목, 상태 배지(draft·published·unlisted·suspended), 등록 단계(`register_step`/13), 1박 요금, 평균 별점, 작업(편집, 달력, 게시/비공개, 삭제). 크레딧 표시: 헤더 잔액(8절).

목적: 30분 안에 게시. 데이터: `listings`, `listing_private`, `listing_photos`(RLS). 행동: 단계 입력, 저장하고 계속, 이전, 나가기, AI 초안(9·10단계). 크레딧 표시: AI 초안 버튼 "3~5크레딧".

### 3.8 예약함 `/host/reservations`, 달력 `/host/listings/[id]/calendar`

예약함: 탭(요청 / 다가오는 / 지난 / 취소), 행 = 게스트 표시 이름·사진, 숙소, 기간, 인원, 금액, 상태. 행을 누르면 오른쪽 패널에 메시지·승인·거절·취소·리뷰 답글. 데이터: `host_reservations`. 달력: 월 보기, 예약 막대(상태 색 + 텍스트), 차단 구간(빗금), 드래그로 기간 선택 → "이 날짜 막기"(`block_dates`), 차단 클릭 → 해제(`unblock_dates`). 크레딧 표시: 없음.

## 7. 인증 단계별 로그인 화면

정본은 `docs/products/_platform-core/AUTH_ROADMAP.md`다(01장 8.1절).

### 7.1 A단계: Mock 로그인(로컬 전용)

`/login`에 "개발용 로그인" 패널만 보인다: 페르소나 버튼(`host`, `guest`, `owner`, `outsider`, `suspended` 등, 05장 10절). 배포 환경에서는 패널이 렌더되지 않고 `/api/dev/login`은 404. `/signup`은 `/login`으로 이동.

### 7.2 B단계: Google + 이메일

```
+--------------------------------+
| Stay에 로그인                   |
| [ G  Google로 계속하기 ]        |
| ---------- 또는 ----------     |
| 이메일 [               ]       |
| 비밀번호 [             ]       |
| [ 로그인 ]  비밀번호 찾기       |
| 계정이 없나요? 가입하기          |
+--------------------------------+
```

`/signup`: 이메일, 비밀번호(8자 이상), 표시 이름, 약관·개인정보 동의(필수), 만 19세 이상 확인(필수, 01장 6절). 오류: 이메일 형식, 이미 가입된 이메일("로그인하거나 Google로 계속하세요"), OAuth 취소("로그인을 취소했습니다"), 콜백 실패("다시 시도해 주세요").

### 7.3 OAuth 첫 로그인 뒤 온보딩

`/onboarding` 1단계: 약관·개인정보 동의 + 만 19세 이상 확인(이메일 가입자는 가입 폼에서 이미 동의했으므로 건너뜀). 2단계: AI 처리 방식("상용 AI 사용(해외 서버로 전송, 국외 이전 동의)" / "국내 오픈소스만") — 고지문 버전 표시, 나중에 `/settings/ai`에서 바꿀 수 있음. 완료 후 `next`로 복귀.

### 7.4 C단계: 카카오·네이버

로그인 화면 Google 버튼 아래에 "카카오로 계속하기", "네이버로 계속하기"를 추가한다(각 제공자 버튼 가이드 준수, 미확인: 최신 가이드). 카카오 이메일 미동의 시 D15 정책 안내. 네이버 경로는 D16 결과에 따른다.
