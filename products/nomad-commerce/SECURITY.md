# NOMAD Commerce SECURITY

공통 규칙 정본은 `../_platform-core/SECURITY_BASELINE.md`(1~22장). 이 문서는 이 제품의 수치와 고유 위험만 적는다. 표기: "제안"은 근거 문서에 없어 이 문서가 정한 값, "미확인"은 확인 전. 상태: **1차 초안(2026-10-23)**

상품 상세페이지를 만들어 쿠팡·스마트스토어에 올리는 셀러 도구라, 위험은 "마켓 계정 자격증명", "결제·크레딧", "금지어 위반", "외부 URL/API 호출"에 모인다.

## 1. 지켜야 할 자산

| 자산 | 종류 | 저장 위치 | 민감도 |
|---|---|---|---|
| 마켓 계정 API 자격증명(쿠팡·스마트스토어) | 키 | core `encrypted_credentials`(`CREDENTIALS_KEY_V<n>`) | 높음 |
| 결제 정보(Toss 빌링키·주문) | 돈 | 결제대행사 토큰, 주문 테이블 | 높음 |
| 크레딧 잔액·거래 내역 | 돈 | 크레딧 테이블 | 높음 |
| 상품·원가·마진 데이터 | 영업 비밀 | 상품 테이블 | 중간 |
| 생성 상세페이지·이미지 | 콘텐츠 | Storage | 중간 |
| 셀러 AI 대화 | 개인정보 | `ai_messages` | 중간 |

## 2. 위협 시나리오

| # | 누가 | 무엇을 | 어떻게 | 영향 | 대응 |
|---|---|---|---|---|---|
| T1 | 공격자 | 마켓 자격증명 탈취 | DB 유출, 로그 기록 | 타인 마켓 계정으로 상품 변조 | 평문 컬럼 금지, `encrypted_credentials`만, 로그에 키 금지(§5, §12) |
| T2 | 공격자 | 결제 금액 조작·중복 결제 | 클라이언트 금액 신뢰, 웹훅 재전송 | 무료 크레딧, 이중 지급 | 서버 confirm + 금액 대조 + 멱등, 웹훅은 상태 동기화만(§6) |
| T3 | 악의적 사용자 | 크레딧 선차감 우회 | 동시 요청, 실패 환불 악용 | 크레딧 손실 | `consume_credits` 선차감 → 실패 시 환불(RPC 내부), 동시 작업 상한 |
| T4 | 사용자 | 아마존 URL 가져오기 악용(SSRF) | 내부 주소 URL 입력 | 서버 내부 접근 | 서버가 URL을 fetch하지 않고 ASIN만 추출(01_PRD CM-F-010). 외부 크롤링 추가 시 사설 IP 차단(§10) |
| T5 | 사용자 | 금지어·허위 표시 상품 게시 | 금지어 우회 | 마켓 제재, 법적 책임 | 2단계 금지어·compliance 게이트, FAIL은 서버가 차단 |
| T6 | 사용자 | 인라인 편집 XSS | 상세페이지 HTML 삽입 | 저장형 XSS | 서버 sanitize 후 저장·렌더(§10) |
| T7 | 봇 | 공개 AI 입구 남용 | 비로그인 상담 | AI 비용 | MVP에는 비회원 AI 없음(Phase 2는 강한 레이트 리밋 전제) |
| T8 | 외부 | 이미지 생성·AI 제공자 데이터 전송 | 상품 이미지·설명 전송 | 국외 이전 | 온보딩 국외 이전 동의, 상용/오픈소스 이원화(§16) |
| T9 | 외부 AI 에이전트 | MCP로 원가·마켓 키·업로드 이력 수집, 크레딧 소진, 상품명 속 지시문 실행 | 에이전트 토큰 남용, 간접 프롬프트 인젝션 | 영업 비밀·자격증명 유출, 비용 | 읽기 도구는 사용자 세션 RLS, 키·원가 출력 제외, 결제·생성·업로드 도구 없음, 생성은 준비 + 웹 확정(`MCP.md`, `SECURITY_BASELINE.md` 23장) |

## 5. 이 제품에만 있는 위험

- **구매대행 법규:** 건기식 등 규제 상품은 고시·문구 위반 시 책임이 셀러에게 있고, 플랫폼 면책 표시가 필요한지 법무 확인.
- **금지어 판정 오류:** 1단계 규칙 + 2단계 LLM 판정이라 오탐·미탐이 있다. FAIL 차단과 WARN 사용자 확인 흐름을 로그로 남긴다.
- **마켓 약관:** 쿠팡·스마트스토어 API 이용약관 및 자동 업로드 허용 범위는 미확인.
