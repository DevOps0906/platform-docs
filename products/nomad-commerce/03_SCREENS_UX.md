# 03 화면과 UX: NOMAD Commerce

## 2. 사용자 플로우

### 2.1 가입 → 부트스트랩 → 첫 생성 (필수)

| 단계 | 화면 | 사용자 행동 | 시스템 동작 | 실패 분기 |
|---|---|---|---|---|
| 1 | `/` | "무료로 시작" | `/login` 이동 | - |
| 2 | `/login` | A: 개발용 패널에서 페르소나 선택. B: Google 또는 이메일(C 이후 카카오·네이버 추가) | 이메일은 `signUp(..., data.signup_app='commerce')` → 가입 트리거가 조직·free 엔타이틀먼트·크레딧 지급. Google·카카오·네이버는 `/auth/callback`의 `finishLogin`이 `bootstrap_app_for_org('commerce')` 1회(7절) | 콜백 오류 → 로그인 화면에 원인 문구(`error=callback`, `state`, `email_in_use`) |
| 3 | `/dashboard` | 첫 방문 | `session_context('commerce')`. 빈 상태 카드 "첫 상품을 가져오세요" + AI 처리 방식 안내 띠(`/onboarding/ai`로 이동. 건너뛰면 국내 오픈소스 AI만 사용) | `entitled=false`(다른 앱으로 가입한 계정) → `bootstrap_app_for_org('commerce')` 후 새로고침 |
| 4 | `/sourcing` | 아마존 URL 붙여넣기 | ASIN 추출 → 1크레딧 차감 → `import.amazon` 잡 | URL에서 ASIN 없음 → 입력 아래 오류. 크레딧 부족 → 402 패널 |
| 5 | `/products` | 상품 선택 → "상세페이지 만들기" | 생성 모달(유형 자동 추천, 10슬롯 기본) → 9크레딧 차감 → `detail_pages` waiting | 플랜 밖 유형/15슬롯 → 잠금 표시 + 업그레이드 링크 |
| 6 | `/detail-pages/[id]` | 진행 보기 | 8단계 진행률, 슬롯 카드가 하나씩 채워짐 | 슬롯 실패 → 카드에 "다시 생성(1크레딧)". 전체 실패 → 자동 환불 안내 |
| 7 | 같은 화면 | compliance 결과 확인 | PASS면 다음 단계 버튼, WARN이면 항목 목록 + "확인했습니다" | FAIL → 수정 가이드, 내보내기·업로드 버튼 비활성 |

```
+--------------------------------------------------------------+
| NOMAD Commerce            가격  로그인  [무료로 시작]         |

| [아마존 URL 입력........][만들기]|  | L-3 ------- |  ---4,800px-- |
+-----------------------------+--------------------------------+
| 흐름 4단계(실제 순서): 가져오기 > 생성 > 검수 > 등록/내보내기 |
| 각 단계에 실제 화면 캡처 1장                                  |
+--------------------------------------------------------------+
| 가격표(플랜 4개, 크레딧 단가 표)   | 법적 고지 링크            |
+--------------------------------------------------------------+

안 B (버림): 중앙 정렬 큰 헤드라인 + 아래 3열 기능 카드
  → SaaS 카드 키트(기본값 4번)에 해당하고 결과물이 보이지 않아 버림
```

| 원칙 | 내용 |
|---|---|
| 결과물이 주인공 | 히어로는 실제로 생성한 롱이미지 띠와 마켓별 분할을 보여 준다. 샘플 상품은 자체 촬영 또는 라이선스 확보 이미지 |
| 순서는 실제 순서만 | 번호는 가져오기→생성→검수→등록 흐름에만 쓴다 |
| 검수를 숨기지 않는다 | 금지어 검수(PASS/WARN/FAIL)를 기능으로 보여 준다 |
| 숫자는 단가만 | 크레딧 단가와 가격만 숫자로. 사용자 수·매출 통계 없음 |

대담함의 위치: 히어로 한 곳. 2026-10-13 사용자 결정(확정 결정 15)으로 기존의 "스크롤에 따라 롱이미지 띠가 2,800px 분할선에서 쿠팡/스마트스토어 두 열로 나뉘는 연출"을 3D 히어로(4.5절)로 바꿨다. 안 A의 우측 롱이미지 띠 자리에 3D 장면이 들어가고, 토큰 플랜과 "피할 인상"은 그대로다. 나머지 섹션은 정적.

## 5. 상태, 오류, 빈 화면

| 상황 | 표시 |
|---|---|
| 잡 진행 | `core.jobs.progress` + phase 문구(01장 3.6절), 슬롯 카드 상태(pending/generating/completed/failed/skipped). Realtime 끊기면 10초 폴링으로 전환 |
| 대기(waiting) | "앞에 n건 생성 중. 플랜 동시 생성 수 m" + 취소 버튼 |
| 크레딧 부족(402, CR001) | "크레딧이 n 부족합니다. 크레딧팩을 사면 바로 이어서 생성합니다" + 팩 구매 |
| 플랜 부족(403, CM007, CM002, CM003) | 잠긴 기능 이름 + 필요한 플랜 + 업그레이드 |
| compliance WARN | 항목 목록(단어, 위치, 대체어 제안) + "검토했습니다" 확인(감사 기록) |
| compliance FAIL | 등록·내보내기 비활성, 항목별 수정 버튼 |
| 업로드 실패 | 마켓 오류 코드 + 우리 말 요약 + 해결 링크(폼 필드로 이동) |
| 네트워크 오류 | 토스트 + 재시도. mock 응답으로 숨기지 않는다 |
| 빈 상태 | 상품 없음: "아마존 링크나 엑셀로 첫 상품을 가져오세요" / 상세페이지 없음: "상품을 선택해 첫 상세페이지를 만드세요" / 계정 없음: "쿠팡 Wing에서 발급한 Open API 키를 등록하세요" |
| AI 답변 생성 중 | 스트리밍 + 중지 버튼. 규칙 질문은 근거를 찾는 동안 "근거를 찾는 중" |

## 7. 로그인 화면 단계별 구성 (2026-10-14 추가, 확정 결정 22)

정본 `docs/products/_platform-core/AUTH_ROADMAP.md` 2장, 5.2절, 7장. 로그인 뒤 화면(대시보드 이후)은 단계와 무관하게 같다.

| 단계 | `/login` 구성 | `/auth/callback` | 비고 |
|---|---|---|---|
| A(MVP 개발, 로컬) | "개발용 로그인" 패널: 페르소나 버튼(`owner`, `admin`, `member`, `viewer`, `outsider`, `no_app`, `suspended`, `ops` + 제품 행 `pro`, `ai_consent`, 05장 10절), 현재 로그인 페르소나, 로그아웃. 실제 제공자 버튼은 렌더하지 않는다 | 없음(`POST /api/dev/login`이 세션 쿠키를 설정하고 `next` 또는 `/dashboard`로 이동) | 모든 화면 상단에 고정 배지 `MOCK AUTH · 로컬 전용`. `isMockAuthAllowed()`가 거짓이면 패널·배지 코드를 렌더하지 않는다(서버 컴포넌트 분기) |
| B(공개 베타 전) | "Google로 계속하기" 버튼 + 이메일 폼(로그인/가입 탭, 비밀번호 재설정 링크). 하단에 이용약관·개인정보처리방침 링크 | `finishLogin` 후 `/dashboard`(또는 화이트리스트 `next`) | Google은 가입과 로그인이 같은 버튼. 이메일 가입 화면·인증 메일 안내·비밀번호 재설정 화면은 B단계에 만든다 |
| C1·C2(G2 후) | B 구성 + "카카오로 계속하기"(카카오 디자인 가이드 색·문구, 미확인: 최신판 확인), "네이버로 계속하기"(검수 통과 전 운영에서 숨김) | 카카오·`custom:naver`는 같은 콜백. 브리지면 `/auth/naver/start` → `/auth/naver/callback` | 버튼 순서는 Google, 카카오, 네이버, 이메일(제안) |

오류 상태(로그인 화면 상단 오류 띠, 쿼리 `error`로 표시):

| 코드 | 원인 | 문구 |
|---|---|---|
| `error=callback` | 코드 없음·재사용·만료, 코드 교환 실패 | "로그인을 완료하지 못했습니다. 다시 시도해 주세요" |
| `error=state` | (C2 브리지) state 불일치·없음·만료 | "로그인 요청이 만료됐습니다. 처음부터 다시 시도해 주세요" |
| `error=email_in_use` | (C2 브리지) 같은 이메일의 다른 방법 가입자 | "이미 다른 방법으로 가입한 이메일입니다. 그 방법으로 로그인한 뒤 설정에서 네이버를 연결하세요" |
| 403 suspended | 정지 계정 | "이용이 정지된 계정입니다. 고객센터로 문의하세요"(제안) |

commerce는 open 앱이라 `/no-access`(초대제 안내)와 `/pending`(승인제)을 쓰지 않는다. `entitled=false`는 콜백이 부트스트랩으로 메운다.

첫 OAuth 로그인 뒤 약관 동의: 제품 온보딩 첫 단계에 둔다. 순서는 `/onboarding/terms`(제안: 이용약관·개인정보처리방침 필수 동의, 마케팅 수신 선택) → `/onboarding/ai`(AI 처리 방식, 1절 표). 이메일 가입자는 가입 폼에서 같은 동의를 받으므로 이 단계를 건너뛴다. 동의 기록 방식(감사 행 또는 별도 저장)은 CM-06-058에서 정한다(코어에 공용 약관 동의 표 없음, 미확인).

C단계 "설정 → 로그인 방법"(`/settings/login`, 제안 경로, P1): 연결된 제공자 목록(Google, 카카오, 네이버, 이메일), 연결(`linkIdentity`, 브리지 네이버는 로그인 상태에서 연결), 해제(남는 로그인 수단이 1개 이상일 때만). 감사 `auth.identity_link`·`auth.identity_unlink`(`AUTH_ROADMAP.md` 7.3절). 역할 접근은 본인(모든 멤버).

## 8. 대시보드 셸과 좌측 GNB (2026-10-19 추가, 원본 프로젝트 메뉴 이행)

이 장은 NOMAD Commerce 앱 화면(`(app)` 그룹, `/dashboard`와 같은 단계의 `/products`, `/sourcing` 등)의 공통 셸(헤더 + 좌측 GNB)과 홈 구성을 정한다. 목적은 원본 4개 프로젝트의 메뉴·기능이 모두 새 구조 어딘가로 이행되게 하는 것이다. 원본은 Nomad-AI-Factory_V.2 기획의 핵심 흐름과 확장 축(`docs/reviews/Nomad-AI-Factory_V.2.md:7`, `:38`), nomad-ai-factory(v1) 기능 목록(`docs/reviews/nomad-ai-factory.md:22-27`), nomad-ai-commerce 기능 목록과 대시보드 페이지 묶음(`docs/reviews/nomad-ai-commerce.md:22-28`, `:36`), sellingstudio 기능 목록과 대시보드 8개 탭(`docs/reviews/sellingstudio.md:20`, `:22-28`, `:46`)이다. 1절 화면 표의 경로·권한·플랜은 그대로이고, 이 장은 메뉴 순서·묶음·셸 동작만 더한다. 새 경로는 만들지 않는다. 공개 화면(`/`, `/pricing`, `/legal/*`, `/login`, `/wiki`)은 셸 밖이고, 운영 화면(`/admin/*`, `app/admin/`, `CLAUDE.md:52`)은 별도 레이아웃이라 GNB에는 `platform_admin`용 링크 1개만 둔다. 다른 제품과 `_design-guide` 공용 패턴은 바꾸지 않는다(nomad-commerce 전용).

### 8.5 홈 구성 (`/dashboard`, 1절 홈 행 구체화)

1절 홈 행은 "대시보드(KPI, 환율, 최근 작업) C → B"(:15)이고 3절은 "KPI 4개(오늘 생성, 생성 중, 이번 달 업로드 성공/실패), USD 환율과 기준일, 최근 작업 표"(:136)다. 위에서 아래 순서. KPI는 같은 크기 카드 4개로 두지 않고(`DASHBOARD_PATTERNS.md` C 패턴 "피할 것"), 2번 흐름 보드의 단계 숫자로 두며 누르면 해당 목록(B)으로 간다. 진행 중인 상세페이지가 주인공이다. 데이터가 없으면 5장 빈 상태(:379)를 보이고, 첫 방문은 2.1절 :48의 빈 상태 카드 "첫 상품을 가져오세요" + AI 처리 방식 안내 띠를 1번 위에 둔다. 모든 숫자는 실데이터다(01장 CM-F-007 :79).

| 순서 | 영역 | 내용 | 누르면 |
|---|---|---|---|
| 1 | 오늘 처리할 일 | 검수 WARN 확인, compliance FAIL 수정, 업로드 반려·실패, 등록 폼 필수 누락, 마켓 계정 검증 오류, 엑셀 매핑 필요. 각 개수, 0이면 숨김 | 상세페이지, 상세페이지, 업로드 이력, 등록 폼, 마켓 계정, 가져오기 |
| 2 | 이번 주 흐름 | 가져옴 › 생성 중 › 검수 대기 › 등록 준비 › 제출됨 › 승인 6단계 개수. 3절 KPI 4개는 "생성 중"(오늘 생성 수를 보조 줄로)과 "승인"(이번 달 업로드 성공/실패를 보조 줄로)에 담는다 | 가져오기, 상세페이지, 상세페이지, 등록 폼, 업로드 이력, 업로드 이력 |
| 3 | 생성 중인 상세페이지(넓게) + 크레딧(좁게) | 상세페이지: 8단계 진행 막대 + phase 문구(01장 3.6절), 대기는 "앞에 n건"(5장 :372), 실패는 환불 안내(:383). 크레딧: 잔액, 이번 달 소비, 기능별 사용 | 상세페이지, 플랜·크레딧 |
| 4 | 최근 작업(넓게) + 환율·마진(좁게) | 작업 표(시각, 작업, 대상, 상태, 크레딧 증감). 환율: USD 1개와 기준일, API 실패 시 마지막 값 + "기준일" 경고(CM-F-008 :80) | 각 상세, 상품DB(마진) |
| 5 | 플랜 한도(넓게) + 알림(좁게) | 한도: 상품 수, 마켓 계정 슬롯, 오늘 채팅 턴(80% 이상 경고색). 알림: 8.2절 알림과 같은 목록 최근 4건 | 플랜·크레딧, 해당 메뉴 |

`DASHBOARD_PATTERNS.md:130`은 commerce 홈을 "C(마켓별 성과)"로 권하고 4.1절 :247도 "대시보드 마켓별 업로드 성과"를 레퍼런스로 두지만, 3절 :136의 KPI는 마켓별이 아니다. 마켓 계정별 성과 영역을 더할지는 D-21에 함께 둔다.
