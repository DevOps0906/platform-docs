# 03 화면과 UX: Microweb Studio

2026-10-13 개정: AI 채팅·음성·문구 위키 화면, 디자인 시스템(3.2절), 쇼룸 3D 히어로(4.6절)를 더했다. 쇼룸 히어로는 사용자 결정(2026-10-13, 확정 결정 15)으로 기존 "휴대폰 화면" 안에서 3D 안으로 바뀌었고 변경 기록은 4.4절에 있다. 공개 청첩장(`/i/*`, 템플릿 테마)과 쇼룸은 `DESIGN_PRINCIPLES.md`를 따르고 B2B 레퍼런스(Atlassian, Primer)를 쓰지 않는다. 스튜디오(운영자 화면)만 3.2절의 디자인 시스템을 따른다.

장면 연출(PC·태블릿):

| 단계 | 계기 | 3D | HTML |
|---|---|---|---|
| 0 첫 화면 | 페이지 로드 | 없음. 같은 구도의 정지 이미지 자리(레이아웃 이동 없음) | 헤드라인(LCP 요소), CTA, 샘플 프레임 자리 |
| 1 열림 | 동적 import 완료(약 0~0.8초) | 인주 도장이 풀리고 봉투 덮개가 뒤로 젖혀진다 | 변화 없음 |
| 2 올라옴 | 약 0.8~2.0초 | 카드가 봉투에서 위로 올라온다 | 변화 없음 |
| 3 펼침 | 약 2.0~3.5초 | 카드가 한지 괘(접힌 선) 두 줄을 따라 3단으로 펼쳐져 한 장의 평면이 된다 | 변화 없음 |
| 4 정지 | 약 3.5~4.2초 | 펼친 면이 정면에 고정되고 렌더가 멈춘다(`frameloop="demand"`) | 펼친 면 위치에 실제 샘플 청첩장(375px HTML 프레임)이 크로스페이드로 겹치고 스크롤 가능 |

시간은 모두 제안이며 구현 후 모션 검토에서 확정한다. reduced-motion이면 0~5단계 없이 정지 이미지와 샘플 프레임만 보인다. 기울기(DeviceOrientation) 입력은 쓰지 않는다(터치·포인터 드래그만, 제안; 쓰게 되면 HERO_3D 1.1절대로 버튼으로 권한을 요청한다).

|---|---|---|
| 장면 배경 | 백자 `#F6F7F5` | 그라디언트 없음 |

| 접힌 선·봉투 가장자리 | 먹 `#1E2023`(얇은 선) | 선 두께는 구현 시 확정 |
| 도장 | 인주 `#B23A48` | 3D에서 인주를 쓰는 유일한 요소 |
| 카드 면 | 백자 | 글자는 3D에 넣지 않고 HTML 샘플 프레임이 겹친다. 펼칠 때의 면 텍스처는 실제 샘플을 빌드 때 캡처한 AVIF(PC·태블릿만, 모바일은 단색) |

| 공용 키트 | `packages/ui-3d`(제안, 로더·토큰 재질·조명·대체 이미지·성능 모니터) 위에 microweb 소재만 얹는다. 키트가 없으면 같은 인터페이스로 `hero3d/` 안에 두고 키트가 생기면 옮긴다(06장 R-12) |
| 예산 | 3D 번들+에셋 PC·태블릿 1MB, 모바일 300KB 이하, 60fps / 30fps 이상, LCP 2.5초(HERO_3D 2절) |
| 번들 격리 | 하객 페이지(`/i/*`)와 스튜디오 번들에 three.js 0바이트(CI 번들 분석, 하객 JS 150KB 예산 보호) |
| 접근성 | 캔버스 `aria-hidden`, 샘플 프레임은 제목 있는 iframe, [다시 보기]·[움직임 멈춤] 키보드 조작, reduced-motion 정지 이미지 |
| 검증 | PC·태블릿·모바일 스크린샷 3종, Lighthouse 모바일·데스크톱, 프레임 측정, 고문(Fable) 디자인 검토(HERO_3D 4절) |

## 6. 접근성과 반응형

| 항목 | 기준 |
|---|---|
| 하객 페이지 | 375px 우선, 데스크톱은 중앙 480px 컬럼. 글자 크기 조절 200%에서 깨지지 않음 |
| 대비 | 본문 4.5:1 이상. 템플릿 테마도 테마 등록 시 대비 검사 |
| 키보드 | 스튜디오 전 기능 Tab 순회, 포커스 링 표시 |

| 음악 | 자동 재생 없음, 토글에 `aria-pressed` |
| 계좌/전화 | 버튼에 대상 이름 포함 라벨("신랑 아버지에게 전화") |
| 3D 히어로 | 캔버스 `aria-hidden`, reduced-motion 정지 이미지, [다시 보기]·[움직임 멈춤] 키보드 조작, 3D 로딩 전에 제목·CTA 사용 가능 |

| 인사말 음성 플레이어 | 재생/정지 버튼은 대상 라벨("인사말 음성 듣기"), 자동 재생 없음, 자막(인사말 본문)이 같은 블록에 보임 |

## 7. 로그인 화면 단계별 구성 (2026-10-14 추가, 확정 결정 22)

정본 `docs/products/_platform-core/AUTH_ROADMAP.md` 2.1절, 5.2절, 7장. 로그인 화면은 스튜디오 디자인 시스템(3.2절)을 쓴다. 하객 페이지(`/i/*`), 고객 시안(`/p/*`), 쇼룸은 단계와 무관하게 로그인 버튼이 없다.

| 단계 | `/login` 구성 | 비고 |
|---|---|---|
| A Mock(로컬 전용) | 상단 고정 배지 `MOCK AUTH · 로컬 전용`(스튜디오 모든 화면), "개발용 로그인" 패널: 페르소나 버튼(`owner`, `admin`, `member`, `viewer`, `outsider`, `no_app`, `suspended`, `ops`, `studio_denied`, 05장 10절), 현재 로그인 페르소나, 로그아웃. 실제 제공자 버튼 없음 | Mock 판정이 거짓이면 패널 코드를 렌더하지 않는다(서버 컴포넌트 분기). `pending` 페르소나는 approval 앱 전용이라 없다 |
| B Google + 초대 메일 | 제목 "Microweb Studio 운영자 로그인", "Google로 계속하기" 버튼, 초대 메일 안내("초대 메일의 링크로 처음 로그인하세요. Google로 로그인할 때는 초대받은 이메일과 같은 계정을 고르세요"). 공개 가입 링크 없음(초대제) | 이메일+비밀번호 가입 폼을 새로 두지 않는다(초대 메일 수락 경로만) |
| C 카카오·네이버(P2 선택) | Google 아래 카카오·네이버 버튼(01장 D-19로 켤 때만). 카카오 버튼은 카카오 디자인 가이드의 색·문구(미확인, 최신판 확인 후) | 네이버는 검수 통과 전 운영에 노출하지 않는다 |

| `error=state`(C2 브리지 state 불일치) | `/login` 상단 오류 띠 | "로그인 요청이 만료되었습니다. 처음부터 다시 시도해 주세요" |
