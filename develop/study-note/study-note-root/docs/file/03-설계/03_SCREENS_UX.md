## 2. 사용자 플로우

### 2.1 가입 → 첫 생성

| 단계 | 화면 | 사용자 행동 | 시스템 동작 | 실패 분기 |
|---|---|---|---|---|
| 1 | `/signup` | 이메일/비밀번호 또는 Google, 만 14세 이상 체크(Stage B부터. A는 `/login` 개발용 패널에서 페르소나 선택, Google 가입은 첫 로그인 뒤 `/onboarding/terms`에서 체크, 7.3절) | `signUp({options:{data:{signup_app:'notes'}}})`. 개인 조직, 월 30 크레딧 부트스트랩(Google은 `/auth/callback`의 `finishLogin`이 보충) | 이미 가입: 로그인 안내. 체크 누락: 가입 불가 |
| 2 | `/verify` | 메일의 링크 클릭 | 인증 완료 후 `/app` | 미인증이면 `/app`은 보이되 실행 버튼에 "이메일 인증 후 사용할 수 있습니다" |
| 3 | `/app` | 날짜 확인, 원문 붙여넣기 | 초안을 localStorage에 300ms 디바운스 저장(실패해도 동작) | 5,000자 초과: 버튼 비활성 + 초과 글자 수 |
| 4 | `/app` | 첫 실행 시 동의 모달에서 동의(원문이 외부 AI 사업자로 전송됨) | `write_audit('notes_consent.llm')` | 거부: 실행 불가 |
| 5 | `/app` | [정리하기] 또는 Ctrl+Enter | `POST /api/notes/runs` → 크레딧 선차감, 잡 생성 | 402 크레딧 부족, 409 이미 실행 중, 429 한도 |
| 6 | `/app` | 카드 A, B가 로딩 → 결과 표시, 통합 카드 로딩 → 결과 | Realtime으로 `run_steps` 반영 | 카드별 오류 표시, 환불 안내 |
| 7 | `/app` | [TXT 다운로드], [복사] | 브라우저에서 파일 생성 | |

### 2.6 강의 녹음 → 노트 생성

| 단계 | 화면 | 사용자 행동 | 시스템 동작 | 실패 분기 |
|---|---|---|---|---|
| 1 | `/app/lecture` | 과목과 제목 입력 | 허용 시간(`lecture_max_minutes`)과 예상 크레딧 표시 | 플랜에 없으면 업그레이드 안내(Pro 비활성 기간에는 "준비 중") |
| 2 | 강의 녹음 고지 모달 | 고지문(제3자 목소리, 규정 확인 책임, 고지문 버전)을 읽고 [확인하고 녹음 시작]. "원본 보관"은 기본 해제 | `POST /api/voice/lectures`: 고지 감사 기록, `voice_sessions` 생성. 보관을 고르면 별도 동의 문구 + `consent_kind='third_party_notice'` | 취소: 텍스트 붙여넣기 경로 안내. 고지 없이 조각 업로드는 403 `LECTURE_NOTICE_REQUIRED` |
| 3 | 녹음 중 | 마이크 허용 → 녹음. 경과·남은 시간, 일시정지, 재개. 5분마다 조각이 자동 업로드 | `POST /api/voice/lectures/[id]/chunks`(multipart, `seq`) → 선차감 → STT → 전사 조각 저장 | 마이크 거부·미지원: 안내. 업로드 실패: 조각을 보류했다가 재전송. STT 실패: 그 조각만 [다시 시도], 환불 |
| 4 | 녹음 중 | [녹음 끝내기] 또는 허용 시간 도달 시 자동 종료 | `POST /api/voice/lectures/[id]/finish`: 마지막 조각 처리, 전사 조각 병합, 정산 | 413 `VOICE_TOO_LONG`(허용 시간 이후 조각) |
| 5 | 전사 확인 | 전사본 읽기·수정(선택). "전사 오류가 있을 수 있습니다" 안내. [노트로 정리] | 문서 등록(`POST /api/notes/documents`, source_type `text`) 후 2.5절 3~5단계 | 402 크레딧 부족: 전사본은 보존되고 나중에 정리 가능 |

## 6. 접근성과 반응형

| 항목 | 기준 |
|---|---|
| 키보드 | Ctrl+Enter 실행, Tab 순서 입력 → 정리하기 → 카드 버튼, `:focus-visible` 표시, 설정 패널은 포커스 트랩과 Esc 닫기 |
| 대비 | 본문 4.5:1 이상(라이트/다크). 형광노랑은 배경 용도로만 쓰고 글자는 먹청 |
| 스크린 리더 | 진행 상태 영역 `aria-live="polite"`, 카드에 모델명과 상태를 텍스트로 |
| 모션 | `prefers-reduced-motion`이면 형광펜 연출과 카드 페이드 제거 |
| 폭 | 375/768/1024/1440px, 가로 스크롤 없음 |
| 채팅·진행 상태 | 스트리밍 메시지 영역 `aria-live="polite"`, 그래프 진행과 강의 조각 상태도 텍스트로 알림. 색만으로 상태를 구분하지 않는다 |

| 퀴즈 | 키보드로 보기 선택·제출·다음 문제. 정답/오답은 아이콘 + 텍스트 |
| 3D | 캔버스 `aria-hidden`, [움직임 멈춤], reduced-motion 정지 이미지 |

## 7. 로그인 화면 인증 단계 (2026-10-14 추가, 확정 결정 22)

정본은 `docs/file/03-설계/공용코어/AUTH_ROADMAP.md` 2.1절(A), 5.2절(B), 7장(C)이다. 1절 `/signup`, `/login` 행과 2.1절 1단계의 단계 표기를 이 절이 자세히 적는다. 로그인 뒤 화면(`/app` 이하)은 단계와 무관하게 같다.

### 7.1 단계별 `/login` 구성

| 단계 | 구성 | 렌더 조건 | 작업 |
|---|---|---|---|
| A | "개발용 로그인" 패널: 페르소나 버튼 목록(05장 10절: `owner`, `admin`, `member`, `viewer`, `outsider`, `no_app`, `suspended`, `ops`, `unverified`, `low_credit`), 현재 로그인 페르소나, 로그아웃. 모든 화면 상단 고정 배지 `MOCK AUTH · 로컬 전용`(색은 `tokens.css` 상태 토큰만, 대비 4.5:1, 텍스트로 읽힌다). 실제 제공자 버튼과 `/signup` 링크는 없다 | 서버 컴포넌트에서 `isMockAuthAllowed()`가 참일 때만. 거짓이면 패널 코드를 렌더하지 않는다 | NT-06-006 |
| B | "Google로 계속하기" 버튼 + 이메일·비밀번호 폼(01장 D-22), [가입하기] (`/signup`), [비밀번호를 잊었나요?]. 가입 화면의 만 14세 이상 체크는 이메일 가입에만, Google은 7.3절 | `AUTH_PROVIDERS`에 `google`, `email` | NT-06-053 |
| C | 카카오·네이버 버튼 추가(카카오 버튼 색·문구는 카카오 디자인 가이드, 미확인. 네이버는 검수 통과 전 운영에 노출하지 않는다, C2-6) | `AUTH_PROVIDERS`에 `kakao`, `naver` | NT-06-054, 055 |

버튼 순서(B·C): Google → 카카오 → 네이버 → 구분선 → 이메일 폼(제안: 이 제품 페르소나가 IT 교육 수강생·직장인이라 Google 계정 보유가 가장 흔하다고 보지만 측정값은 없다).

### 7.2 오류·안내 상태

| 상태 | 원인 | 문구(제안) |
|---|---|---|
| `/login?error=callback` | 코드 없음·재사용·만료, 교환 실패(B-3) | "로그인을 마치지 못했습니다. 다시 시도하세요" |
| `/login?error=state` | 네이버 브리지 state 불일치·만료(C2 브리지만) | "로그인 요청이 만료되었습니다. 다시 시도하세요" |
| `/login?error=email_in_use` | 네이버 브리지에서 같은 이메일의 다른 방법 가입자(C2-5) | "이미 다른 방법으로 가입한 이메일입니다. 그 방법으로 로그인한 뒤 설정에서 네이버를 연결하세요" |
| 프로필 없음 | `session_context`에 프로필 없음 | 로그아웃 후 `/login`(기본 admin 금지) |
| 403 정지 | `suspended` | "이용이 정지된 계정입니다" |
| 이메일 미인증 | 이메일 가입 후 인증 전(NT-F-001), 카카오 이메일 없는 사용자(01장 D-20 (b)) | 기존 2.1절 2단계와 같다: `/app`은 보이되 실행 버튼에 "이메일 인증 후 사용할 수 있습니다" |
| invite 앱 `/no-access` | 해당 없음(이 제품은 open 앱) | - |

### 7.3 첫 OAuth 로그인 뒤 약관 동의

| 순서 | 화면 | 내용 |
|---|---|---|
| 1 | `/auth/callback` | `finishLogin`. 약관 동의 기록이 없으면 `/onboarding/terms?next=...` |
| 2 | `/onboarding/terms`(제품 온보딩 첫 단계) | 이용약관·개인정보처리방침 동의(필수), 만 14세 이상 확인(필수, D-6). 동의하지 않으면 로그아웃 안내. 기록은 `write_audit('notes_consent.terms')`(제안) |
| 3 | `/onboarding/ai` | 기존 2.11절(국외 이전 동의). 순서만 약관 뒤로 |

이메일 가입자는 `/signup`에서 같은 항목에 동의했으므로 1번에서 바로 2.11절로 간다. Stage A 페르소나는 이메일 가입자처럼 약관에 동의한 상태로 본다(시드 훅이 동의 감사 기록을 남긴다, 05장 10.2절). 약관 단계는 NT-06-053이 만들기 전(W6 이전)에는 없으므로 Mock E2E(NT-06-024)가 이 단계에 의존하지 않게 하고, 약관 단계 자체는 053의 `tests/e2e/auth/`가 새 Google 사용자 흐름으로 검증한다.
