# develop — 제품별 개발 묶음

폴더 1개가 프로젝트 1개입니다. 각 폴더에는 개발 안내서(`<제품>_develop.md`), 설치 스크립트(`setup-<제품>.sh/.ps1`),
개발 폴더에 붙는 묶음(`<제품>-root/`)이 같은 형식으로 들어 있습니다. 개발은 이 저장소가 아니라 setup 스크립트가 만드는
`D:\WorkSpace\DEV\<제품>\` 폴더에서 합니다(맨 위 [README](../README.md) 4절).

## 공용

| 폴더 | 내용 |
|---|---|
| [`_shared/`](_shared/) | 모든 제품이 같이 쓰는 설치 가이드와 도구: Dify(AI 채팅 서버), LLM 키·오픈소스 LLM 서버·라우팅, 음성 서버, 개발 위키 스킬 원본, 묶음 생성 스크립트 `build_root.py` |

## 제품 16개

기획 제품은 16개이고 모두 기획·개발 묶음이 있습니다. 14번째 arch-studio(설치형 건축 설계 앱, 2026-10-16), 15번째 local-news(지역신문 멀티테넌트 SaaS, 2026-10-15), 16번째 book-trailer(북트레일러 자동화, 2026-10-15)가 뒤에 추가되었습니다.

공용모듈(compliance, media, community, search, membership, ads, editorial)을 쓰는 개발 방법은 제품마다 [`../develop_V2/`](../develop_V2/README.md)에 따로 있습니다. 설치 스크립트와 개발 묶음은 이 폴더(V1)를 그대로 쓰고, V2 개발서는 바뀌는 부분만 다룹니다.

크레딧·결제, 잡 워커, AI 계층, 음성)을 쓰고, 공개 랜딩이 있는 제품은 3D 히어로를 씁니다.
디자인은 각 개발서 13장에 있습니다: 디자인 시스템 4단계, 메인 히어로, 시각 레퍼런스(랜딩은 Awwwards, 앱 화면은 Dribbble).
로그인은 각 개발서 19장에 있습니다(2026-10-14, 확정 결정 22): 개발은 로컬 시드 계정 Mock 로그인(Stage A)으로 시작 → 사람이 G1을 판정하면 Google(+ 이메일·초대 메일, Stage B) → G2 후 카카오·네이버(Stage C, 제품별 P1·P2·제외). 정본은 [`products/_platform-core/AUTH_ROADMAP.md`](../products/_platform-core/AUTH_ROADMAP.md) 8장 제품별 매트릭스입니다.

## 권장 개발 순서 (`products/README.md` "개발 순서")

| 순서 | 제품 | 이유 |
|---|---|---|
| 0 | 공용 코어(`products/_platform-core`, 통합 DB) | 모든 제품이 의존한다 |
| 1 | study-note, website-floria | 범위가 작아 공용 코어를 먼저 실전 검증한다 |
| 2 | flora-publishing, astro-ai | 공용 PDF 렌더 서비스를 함께 만든다 |
| 3 | sceneflow, nomad-blog, nomad-commerce | 제휴·SNS 업로더·잡 워커를 공유한다 |
| 4 | microweb-studio, live-poll, toon-factory | 독립 도메인이다 |
| 5 | admin-suite, stock-dashboard | 의료정보·금융 규제 확인이 먼저 필요하다 |

nomad-docs는 이 순서표가 만들어진 뒤 추가된 제품으로, 공용 PDF 렌더 서비스(flora-publishing 소유)를 쓰므로 2단계 이후가 자연스럽습니다.

local-news는 4단계(독립 도메인) 뒤에 둡니다. 공용 코어에 R-1~R-10(독자 인증 매트릭스, Multi-tenant Theming 승격 등, `products/local-news/06_AGENT_PLAN.md` 6절)을 먼저 요청해야 하기 때문입니다.

book-trailer는 4단계(독립 도메인)와 같은 위치가 자연스럽습니다. 렌더러를 이 제품이 소유하므로 다른 제품에 의존하지 않고, YouTube 업로드(P1)만 3단계의 sns-uploader를 소비합니다. 다만 개발 전에 대행 판매로 수요를 먼저 검증하는 순서를 권합니다(`book-trailer/book-trailer_develop.md` 1.1절).

arch-studio는 설치형 데스크톱 제품이라 다른 제품에 의존하지 않고 공용 코어(0단계) 다음이면 언제든 시작할 수 있습니다. 공용 코어 요청(데스크톱 Bearer 세션 R-A6, 일회성 결제 C-1 등, `products/arch-studio/06_AGENT_PLAN.md` 6장)이 먼저 필요하고, 본 개발 전에 2일 도면 스파이크(AR-06-019)와 샘플 도면 랜딩으로 먼저 검증하는 순서를 권합니다(`arch-studio/arch-studio_develop.md` 1.1절).
