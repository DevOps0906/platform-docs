# llm-wiki: 개발용 프로젝트 위키 유지

원본 위치는 `docs/develop/_shared/llm-wiki/SKILL.md`이고, 각 개발 폴더에서는 `.claude/skills/llm-wiki/SKILL.md`로 복사해 씁니다. 설계 정본은 `docs/products/_platform-core/LLM_WIKI.md` 4절이며, 위키 규칙 템플릿은 같은 폴더의 `WIKI_SCHEMA.md`(개발 폴더에서는 `docs/wiki/WIKI_SCHEMA.md`)입니다.

## 0. 원칙

| 원칙 | 내용 |
|---|---|
| 산출물이 정본 | 근거는 `docs/file/`(등록 산출물)과 코드입니다. 위키가 산출물과 충돌하면 산출물이 맞고 위키를 고칩니다 |
| 출처 필수 | 모든 주장 옆에 출처(산출물 ID, 파일 경로:줄, 결정 문서)를 적습니다. 출처 없는 문장은 쓰지 않습니다 |
| 비밀 금지 | 키, 토큰, 비밀번호, 개인정보를 위키에 쓰지 않습니다. 환경변수는 이름만 적습니다 |
| 사람 편집 보호 | 사람이 고친 문단(`<!-- human -->` 표시 또는 log의 사람 편집 기록)은 덮어쓰지 않고 제안만 합니다 |
| 최소 변경 | task와 관련된 페이지만 고칩니다. 전체 재작성은 compile 요청이 있을 때만 합니다 |
| 추측 금지 | 확인하지 못한 내용은 "확인 필요"로 표시합니다 |

## 1. 갱신 시점 (트리거)

| 시점 | 실행 | 대상 |
|---|---|---|
| task 완료 | ingest | 그 task가 건드린 modules 페이지, 새 결정이 있으면 decisions 페이지, log |
| 웨이브 종료 | lint (+ 필요 시 compile) | 위키 전체 |
| 산출물(`docs/file/`)이 추가·변경 | ingest (sources) | 해당 산출물의 sources 페이지와 그것을 인용하는 페이지 |
| 질문 받음(구현·리뷰 중) | query | 읽기 전용. 재사용 가치가 있으면 저장을 제안 |

오케스트레이터가 task 완료 보고를 받은 뒤 이 스킬을 실행합니다.

## 2. ingest (수집) 절차

1. 입력을 확인합니다: task ID, 변경된 파일 목록, 관련 산출물 ID, 결정 사항.
2. `docs/wiki/index.md`를 읽어 관련 기존 페이지를 찾습니다.
3. 변경 파일을 읽고(필요한 부분만) 사실을 확인합니다. 읽지 않은 내용은 쓰지 않습니다.
4. 페이지를 갱신합니다.
   - 모듈이 새로 생겼거나 책임이 바뀌면 `modules/<이름>.md`를 만들거나 고칩니다(7장 템플릿).
   - 결정이 있었으면 `decisions/<YYYYMMDD>-<슬러그>.md`를 만듭니다. 이전 결정을 대체하면 옛 페이지 상단에 `대체됨: [[새 결정]]`을 적습니다.
   - 용어가 새로 나왔으면 `concepts/<용어>.md`를 만들거나 고칩니다.
   - 산출물이 바뀌었으면 `sources/<산출물 ID>.md`의 요약과 해시/버전을 갱신합니다.
5. 링크를 갱신합니다: 새 페이지는 관련 페이지의 "관련" 절에서 연결하고, 연결된 쪽에도 되돌아오는 링크를 적습니다.
6. `index.md`에 새 페이지를 한 줄로 추가하고 요약이 바뀌었으면 고칩니다.
7. `log.md` 맨 아래에 한 줄을 추가합니다(append-only): `YYYY-MM-DD | <task ID> | ingest | <바뀐 페이지 목록> | <요약 한 줄>`.
8. 점검: 새 페이지마다 요약 1~2문장, 출처 절, 관련 절이 있고 `[[링크]]`가 실제 페이지를 가리키는지 확인합니다.

## 3. query (질의) 절차

1. `docs/wiki/index.md`를 읽고 질문과 관련된 페이지 후보를 고릅니다.
2. 후보 페이지를 읽고, 출처에 적힌 산출물·코드를 필요한 만큼 확인합니다.
3. 답에 출처(위키 페이지 + 원본 경로)를 붙입니다. 위키와 원본이 다르면 원본을 따르고 차이를 알립니다.
4. 답이 여러 번 쓰일 만하면 "페이지로 저장할까요?"를 제안합니다. 승인 없이 저장하지 않습니다.
5. 위키에 답이 없으면 없다고 말하고 원본에서 찾은 결과를 알립니다.

## 4. lint (점검) 절차

| 검사 | 방법 | 처리 |
|---|---|---|
| 깨진 링크 | 모든 `[[slug]]`가 파일로 존재하는지 확인 | 목록으로 보고, 명백한 오타는 수정 제안 |
| 고아 페이지 | 어떤 페이지에서도 링크되지 않고 index에도 없는 페이지 | index에 추가하거나 삭제 제안 |
| 낡은 페이지 | 출처 산출물/코드의 수정일이 페이지의 `갱신일`보다 새로움 | 갱신 대상 목록 |
| 출처 없는 주장 | "출처" 절이 비었거나 문장에 근거가 없음 | 표시하고 출처 보강 제안 |
| 모순 | 같은 사실이 두 페이지에서 다르게 적힘 | 두 위치와 근거를 나란히 보고. 산출물 기준으로 수정 제안 |
| index 누락 | 파일은 있는데 index에 없음 | 추가 제안 |
| 비밀 | 키·토큰·비밀번호 패턴, 개인정보 | 즉시 제거를 제안하고 log에 기록(값은 적지 않음) |
| 명명 | slug 규칙(소문자·숫자·하이픈) 위반 | 보고 |

lint 결과는 `docs/wiki/log.md`에 `lint | <발견 N건>` 한 줄로 남기고, 수정은 승인된 항목만 ingest 절차로 반영합니다.

## 5. compile (정리) 절차 (요청이 있을 때만)

1. 흩어진 같은 주제를 한 topic 페이지로 합칩니다. 합친 페이지의 "출처"에 원래 페이지를 남깁니다.
2. 삭제 대신 `대체됨: [[새 페이지]]`로 남겨 이력을 지킵니다.
3. `index.md`를 다시 만들고 log에 `compile`을 기록합니다.

## 6. 파일 구조

```
docs/wiki/
├── WIKI_SCHEMA.md
├── index.md
├── log.md            append-only
├── modules/
├── decisions/
├── concepts/
└── sources/
```

## 7. 페이지 템플릿

공통 머리: 첫 줄 요약 1~2문장, 이어서 메타 표.

### 7.1 modules/<이름>.md

```markdown
# <모듈 이름>

<한두 문장 요약: 이 모듈이 무엇을 책임지는가>

| 항목 | 내용 |
|---|---|
| 경로 | `apps/...` |
| 책임 | ... |
| 주요 파일 | `경로` : 역할 |
| 의존 | [[다른 모듈]], 공용 모듈 |
| 소유 task | <task ID 목록> |
| 갱신일 | YYYY-MM-DD |

## 동작 요약
...

## 출처
- 산출물: <산출물 ID>
- 코드: `경로:줄`

## 관련
- [[...]]
```

### 7.2 decisions/<YYYYMMDD>-<슬러그>.md

```markdown
# <결정 제목>

<결정 한 문장>

| 항목 | 내용 |
|---|---|
| 상태 | 확정 / 대체됨 |
| 날짜 | YYYY-MM-DD |
| 관련 산출물 | <산출물 ID> |
| 관련 task | <task ID> |

## 이유
...

## 대안과 기각 사유
...

## 영향
...

## 출처
## 관련
```

### 7.3 concepts/<용어>.md

```markdown
# <용어>

<정의 1~2문장>

## 사용처
## 출처
## 관련
```

### 7.4 sources/<산출물 ID>.md

```markdown
# <산출물 제목> (<산출물 ID>)

<산출물이 무엇인지 1~2문장>

| 항목 | 내용 |
|---|---|
| 경로 | `docs/file/...` |
| 버전/수정일 | ... |
| 이 산출물을 인용하는 페이지 | [[...]] |

## 핵심 내용 (요약)
## 출처
## 관련
```

### 7.5 index.md

```markdown
# 위키 목차

| 종류 | 페이지 | 요약 |
|---|---|---|
| module | [[modules/<이름>]] | 한 줄 |
| decision | [[decisions/<...>]] | 한 줄 |
| concept | [[concepts/<...>]] | 한 줄 |
| source | [[sources/<...>]] | 한 줄 |
```

## 8. 금지

- 키, 토큰, 비밀번호, 개인정보, `.env` 내용을 쓰는 것
- 산출물과 다른 내용을 위키에 "새 사실"로 확정하는 것
- log.md의 과거 행을 고치거나 지우는 것
- 읽지 않은 파일의 내용을 추측해서 적는 것
