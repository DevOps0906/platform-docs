# WIKI_SCHEMA: 개발용 프로젝트 위키 규칙

이 파일은 각 개발 폴더의 `docs/wiki/WIKI_SCHEMA.md`로 복사해 쓰는 템플릿입니다. 정본 설계는 `docs/products/_platform-core/LLM_WIKI.md` 2, 4절이고, 절차는 스킬 `llm-wiki`(`.claude/skills/llm-wiki/SKILL.md`)에 있습니다. `<제품>` 같은 표시는 복사할 때 채웁니다.

## 1. 목적과 범위

| 항목 | 내용 |
|---|---|
| 목적 | 기획서(산출물)와 코드를 에이전트가 정리해 다음 작업의 맥락으로 쓴다 |
| 대상 | <제품 이름> (`<폴더>`) |
| 정본 | 등록 산출물 `docs/file/`과 코드. 위키는 산출물을 대체하지 않는다. 충돌하면 산출물이 맞고 위키를 고친다 |
| 편집 주체 | 에이전트(스킬 실행)와 사람. 사람이 고친 문단은 에이전트가 덮어쓰지 않고 제안만 한다 |

## 2. 페이지 종류

| 종류 | 위치 | 내용 |
|---|---|---|
| index | `index.md` | 목차. 모든 페이지를 한 줄 요약과 함께 나열한다 |
| log | `log.md` | 변경 기록. append-only |
| module | `modules/<이름>.md` | 모듈 경로, 책임, 주요 파일, 의존 |
| decision | `decisions/<YYYYMMDD>-<슬러그>.md` | 결정 한 건과 이유, 대안, 영향 |
| concept | `concepts/<용어>.md` | 도메인 용어·개념 |
| source | `sources/<산출물 ID>.md` | 등록 산출물 요약 |

## 3. 이름 규칙

| 항목 | 규칙 |
|---|---|
| slug | 소문자, 숫자, 하이픈. 하위 경로는 `/` (예: `modules/ai-gateway`) |
| 파일 이름 | slug + `.md` |
| decision | 날짜 8자리 + 하이픈 + 슬러그 (예: `20261013-ai-token-lifetime`) |
| source | 산출물 ID를 그대로 소문자 하이픈으로 (예: `sources/prd-v1`) |
| 링크 | `[[slug]]` 표기. 경로 포함 (예: `[[modules/ai-gateway]]`) |

## 4. 페이지 구조

| 순서 | 절 | 규칙 |
|---|---|---|
| 1 | 제목 | `# 제목` |
| 2 | 요약 | 첫 줄에 1~2문장 |
| 3 | 메타 표 | 경로, 책임, 상태, 갱신일 등 종류별 항목 |
| 4 | 본문 | 마크다운. 확인하지 못한 내용은 "확인 필요" |
| 5 | 출처 | 산출물 ID, 파일 `경로:줄`, 결정 문서. 비어 있으면 안 된다 |
| 6 | 관련 | 위키 링크 목록. 연결은 양방향으로 유지 |

## 5. 출처 규칙

- 모든 주장은 출처를 가진다(산출물 ID 또는 `경로:줄`). 출처 없는 문장은 lint 대상이다.
- 산출물이 바뀌면 그 산출물을 인용하는 페이지는 "낡음"으로 간주해 갱신한다.
- 위키 페이지끼리만 서로 인용하는 순환 출처는 허용하지 않는다. 최종 출처는 산출물 또는 코드여야 한다.

## 6. 갱신 시점

| 시점 | 작업 |
|---|---|
| task 완료 | ingest: 관련 modules·decisions 페이지와 log |
| 웨이브 종료 | lint (필요 시 compile) |
| 산출물 변경 | ingest: sources 페이지와 인용 페이지 |

## 7. log.md 형식

한 줄에 한 건, 과거 행은 수정하지 않는다.

```
YYYY-MM-DD | <task ID 또는 -> | <ingest|lint|compile|human-edit> | <바뀐 페이지> | <요약 한 줄>
```

## 8. 금지

| 금지 | 이유 |
|---|---|
| 키, 토큰, 비밀번호, `.env` 값, 개인정보 | 위키는 git에 올라간다 |
| 산출물과 다른 내용을 새 사실로 확정 | 산출물이 정본 |
| log.md 과거 행 수정·삭제 | 이력 보존 |
| 읽지 않은 파일 내용 추측 | 오류 전파 |
