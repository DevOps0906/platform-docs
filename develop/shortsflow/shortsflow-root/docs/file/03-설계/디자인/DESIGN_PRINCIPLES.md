## 디자인 절차 (모든 제품 공통, 7단계)

### 1단계. 레퍼런스 수집

| 항목 | 규칙 |
|---|---|
| 랜딩/메인페이지 | Awwwards 사이트 페이지(SOTD, Honorable Mention, Developer Award 수상작)를 우선한다. 히어로는 전 제품 3D 표준(PC·태블릿 풀 3D, 모바일 절충안, 정지 이미지 대체)을 따른다: `HERO_3D.md`(확정 결정 15). |
| 대시보드/앱 화면 | Dribbble 샷 또는 Dribbble 검색 결과를 우선한다. |
| 수량 | 제품당 3~5개. `REFERENCES.md`의 제품 표에서 시작하고, 부족하면 같은 카테고리에서 추가한다. |
| 기록 방식 | `REFERENCES.md`와 같은 열(출처, URL, 참고 포인트, 적용 화면)로 제품 폴더의 `03_SCREENS_UX.md`에 남긴다. |
| 참고 포인트 작성법 | "멋있다"가 아니라 가져올 요소 하나를 쓴다. 예: "히어로에서 실제 결과물(책 표지)을 크게 보여 주는 방식", "좌측 고정 필터 + 우측 고밀도 표". |
| 금지 | 레퍼런스의 로고, 사진, 카피, 일러스트를 복제하지 않는다. 구조와 리듬만 참고한다. 확인하지 않은 URL을 만들어 넣지 않는다. |

### 2단계. 주제/대상 브리프 작성

frontend-design의 "주제에 근거한 디자인" 원칙에 따라, 코드 전에 아래 표를 채운다. 브리프가 비어 있으면 에이전트가 제안하고 사용자 확인을 받는다.

| 항목 | 작성 내용 | 예시 (astro-ai) |
|---|---|---|
| 주제 | 제품이 다루는 실제 대상, 재료, 업계 용어 | 만세력, 사주 원국, 대운, 타로 카드, 책자형 PDF |
| 대상 | 누가, 어떤 상황에서 쓰는가 | 20~40대, 자기 이해나 가족 선물용으로 리포트를 소장하려는 사람 |
| 주된 일 | 이 화면이 해야 하는 단 하나의 일 | 생년월일시를 입력하고 리포트 샘플을 확인한 뒤 크레딧을 구매하게 한다 |
| 주제의 고유 어휘 | 시각적 선택의 원천이 될 소재 | 천간지지 한자, 명식표 격자, 제본된 책의 물성 |
| 피할 인상 | `REFERENCES.md`의 안티 방향 | 점집 간판 같은 보라 그라디언트와 별 반짝이 |

### 3단계. UUPM 디자인 시스템 초안 생성

UUPM 설치는 `SKILLS.md`를 따른다. 아래 명령은 UUPM README와 `scripts/search.py`의 인자 정의 그대로다. CLI(`uipro init --ai claude`)로 설치하면 스크립트 경로는 `.claude/skills/ui-ux-pro-max/scripts/search.py`다. Windows에서 `python3`가 없으면 `python`으로 실행한다. Python이 없으면 에이전트가 설치하지 말고 사용자에게 요청한다(UUPM README 규칙).

| 목적 | 명령 |
|---|---|
| 초안 확인(저장 안 함) | `python3 .claude/skills/ui-ux-pro-max/scripts/search.py "<제품 키워드>" --design-system -p "<제품명>"` |
| 마크다운 출력 | `python3 .claude/skills/ui-ux-pro-max/scripts/search.py "<제품 키워드>" --design-system -f markdown` |
| MASTER.md 저장 | `python3 .claude/skills/ui-ux-pro-max/scripts/search.py "<제품 키워드>" --design-system --persist -p "<제품명>" -o <앱 루트>` |
| 페이지 오버라이드 저장 | `python3 .claude/skills/ui-ux-pro-max/scripts/search.py "<제품 키워드>" --design-system --persist -p "<제품명>" --page "dashboard" -o <앱 루트>` |
| 밀도/모션/변주 다이얼 | `--density 1~10`(10이 대시보드형 고밀도), `--motion 1~10`, `--variance 1~10`(10이 비대칭/대담). `--design-system`과 함께만 쓴다. |
| 기존 MASTER.md 덮어쓰기 | `--force` (기본은 기존 파일이 있으면 건너뜀) |
| 영역별 검색 | `--domain style`, `color`, `chart`, `landing`, `product`, `ux`, `typography`, `icons`, `gsap`, `react`, `web`, `google-fonts` 중 하나 |
| 스택 지침 | `--stack nextjs`, `--stack shadcn`, `--stack react` 등 |
| 잘림 없는 출력 | `--json` 또는 `--full` (사람용 출력은 긴 필드를 300자에서 자른다) |

저장 구조와 읽는 순서(UUPM README의 Master + Overrides 패턴):

| 파일 | 역할 |
|---|---|
| `design-system/<제품 슬러그>/MASTER.md` | 전역 기준(색, 서체, 간격, 컴포넌트) |
| `design-system/<제품 슬러그>/pages/<페이지>.md` | 해당 페이지에서 MASTER와 달라지는 점만 기록 |
| 읽는 순서 | 페이지를 만들 때 `pages/<페이지>.md`를 먼저 확인한다. 있으면 그 규칙이 MASTER보다 우선이고, 없으면 MASTER만 쓴다. |

이 저장소의 규칙:
- `-p` 값은 제품 폴더명(`flora-publishing`, `astro-ai` 등)으로 통일한다. 슬러그가 폴더명과 같아진다.
- 마케팅 랜딩은 `--page "landing"`, 운영 화면은 `--page "dashboard"`로 오버라이드를 분리한다.
- 대시보드는 `--density 7~9 --motion 2~3`, 랜딩은 `--density 3~5`에서 시작한다. `--variance`는 제품 성격에 맞춰 정한다.
- 제품별 권장 쿼리는 `REFERENCES.md`의 각 제품 "UUPM 쿼리" 행에 있다.
- UUPM이 만든 MASTER.md는 "초안"이다. 4단계와 5단계를 거친 결과로 MASTER.md를 고쳐 쓴다(`--force`로 재생성하지 말고 직접 편집).

### 4단계. frontend-design 토큰 계획

UUPM 초안을 참고하되, frontend-design의 첫 번째 패스 형식으로 계획을 다시 쓴다. 결과는 MASTER.md 상단과 제품 `03_SCREENS_UX.md`의 "디자인 방향" 절에 둔다.

| 항목 | 작성 규칙 |
|---|---|
| 색 | 기본 팔레트를 이름 붙인 hex 4~6개로 쓴다. 이름은 역할이 아니라 주제에서 온 이름이 좋다(예: "먹색 #1B1A17", "한지 #EFE9DC"). 상태색(성공/경고/오류)은 별도 표로 둔다. |
| 서체 | 서체와 역할(디스플레이, 본문, 숫자/데이터)을 쓴다. 한 가족 또는 두 가족만 쓰고, 두 가족이면 확연히 다르게 고른다. 어느 프로젝트에나 쓰는 기본 서체를 습관적으로 고르지 않는다. 한국어 본문 서체를 반드시 지정한다. |
| 서체 스케일 | 타이포그래피 원칙(The Elements of Typographic Style)의 기본 지침을 따르는 명확한 스케일, 의도한 굵기와 자간을 정한다. |
| 레이아웃 | 한 문장 설명 + ASCII 와이어프레임. 정렬(좌측, 중앙, 양쪽)을 명시한다. 최소 두 가지 안을 그려 비교한 뒤 하나를 고른다. |
| 원칙 | 이 화면을 이 제품답게 만드는 상위 지침 3~5개 |
| 대담함의 위치 | 기억에 남을 요소 하나를 지정한다. 나머지는 조용하게 둔다. |

ASCII 와이어프레임 예시(형식 참고용):

```
+--------------------------------------------------+
| 로고                         가격  샘플  로그인  |
+--------------------------------------------------+
|                                                  |
|  [펼쳐진 리포트 PDF 실물 이미지, 화면 폭 60%]     |
|  한 문장 헤드라인 (좌측 정렬)                     |
|  생년월일시 입력 1줄 폼 + 샘플 보기 버튼          |
|                                                  |
+--------------------------------------------------+
| 리포트 목차 미리보기 (실제 장 제목 8개)           |
+--------------------------------------------------+
```

### 6단계. 구현

| 규칙 | 내용 |
|---|---|
| 토큰 우선 | 색, 서체, 간격, 반경은 CSS 변수(Tailwind 테마)로만 쓴다. 컴포넌트 안 하드코딩 hex 금지. |
| 반경과 그림자 | 위계에 따라 반경과 그림자를 다르게 둔다. 모든 요소에 같은 값을 쓰지 않는다. |
| 모션 | 사용자가 촉발하지 않는 모션은 한 번의 연출된 순간(페이지 로드 시퀀스 하나 또는 리빌 하나)으로 제한한다. 사용자 행동에 대한 응답 모션(열기, 펼치기, 확인)은 무엇이 바뀌었는지 보여 줄 때 쓴다. |
| 줄 길이 | 본문은 80자 미만. 세리프 본문은 산세리프보다 줄간격을 조금 넓힌다. |
| CSS 특이도 | `.section`같은 타입 셀렉터와 `.cta`같은 요소 셀렉터가 섹션 사이 padding/margin을 서로 덮어쓰지 않게 구조를 잡는다. |
| 아이콘 | SVG 아이콘(Lucide 또는 Heroicons)만 쓴다. 이모지를 아이콘으로 쓰지 않는다. |
| 실제 콘텐츠 | 브리프의 실제 콘텐츠와 주제 어휘로 만든다. 로렘 입숨 금지. |
| 자기 비평 | 가능한 환경이면 스크린샷을 찍어 검토한다. 마지막에 장식 하나를 뺀다. 시도한 것과 버린 것을 MASTER.md 하단 "작업 노트"에 적는다. |

## UUPM 프리셋과 frontend-design이 충돌할 때

원칙: frontend-design이 이긴다. UUPM은 초안과 체크리스트 도구로 쓰고, 미적 결정권은 frontend-design 절차에 있다. 단, 사용자 브리프와 확정 결정은 둘보다 앞선다.

| 충돌 상황 | 결정 |
|---|---|
| UUPM이 추천한 팔레트가 생성형 기본값 목록 1~2번에 해당 | 버리고 주제에서 색을 다시 뽑는다. |
| UUPM이 추천한 서체 조합이 흔한 기본 조합 | 주제에 맞는 서체로 바꾼다. 한국어 본문 서체를 반드시 짝지운다. |
| UUPM 랜딩 패턴의 섹션 순서(Hero, Services, Testimonials 등) | 섹션 목록은 참고만 한다. 히어로는 "주제 세계에서 가장 특징적인 것"으로 연다(frontend-design 원칙). |
| UUPM KEY EFFECTS가 여러 호버/전환 효과를 권함 | 연출된 모션 하나만 남긴다. |
| UUPM 체크리스트 항목(접근성, 반응형, 이모지 금지, cursor-pointer) | 미적 판단이 아니므로 그대로 지킨다. 충돌로 보지 않는다. |
| `--density`가 높게 나온 간격 스케일과 랜딩 여백 | 대시보드는 UUPM 밀도를 따르고, 랜딩은 frontend-design 판단을 따른다. |
| 충돌을 해결한 기록 | MASTER.md 하단 "UUPM 대비 변경점" 표에 항목, UUPM 값, 최종 값, 이유를 남긴다. |

## 카피 규칙

frontend-design "디자인 속 글쓰기" 절을 한국어 제품에 맞게 옮겼다.

| 규칙 | 내용 | 좋은 예 | 나쁜 예 |
|---|---|---|---|
| 목적 | 글은 이해와 사용을 돕기 위해서만 둔다. 장식이 아니다. 각 문구는 한 가지 일만 한다. | - | - |
| 사용자 관점 | 시스템 구조가 아니라 사용자가 이해하는 말로 부른다. | 알림 관리 | 웹훅 설정 |
| 설명 우선 | 파는 말보다 무엇인지, 무엇을 하는지 평이하게 쓴다. 재치보다 구체성. | 원고를 넣으면 인쇄용 PDF와 ePub을 만듭니다 | 당신의 창작을 혁신하세요 |
| 능동형 CTA | 버튼은 누르면 일어나는 일을 정확히 말한다. | 변경 사항 저장 | 제출 |
| 일관된 동사 | 같은 동작은 흐름 내내 같은 이름을 쓴다. | 버튼 "발행" → 토스트 "발행했습니다" | 버튼 "발행" → 토스트 "게시 완료" |
| 오류 | 무엇이 잘못됐고 어떻게 고치는지 쓴다. 사과하지 않고, 모호하지 않게. 사람이 아니라 인터페이스의 목소리로. | 크레딧이 2 부족합니다. 크레딧팩을 구매하면 바로 이어서 생성합니다. | 죄송합니다. 문제가 발생했습니다. |
| 빈 상태 | 분위기가 아니라 다음 행동을 안내한다. | 아직 프로필이 없습니다. 첫 프로필을 추가하세요. | 텅 비어 있네요 |
| 어조 | 대화체, 평이한 동사, 군더더기 없음. 브랜드와 대상에 맞춘다. 영어 UI는 sentence case. | - | - |
| 언어 | 사용자 노출 문구는 한국어가 기본이다. 영어 아이브로 라벨, 영어 대문자 라벨을 장식으로 넣지 않는다. | - | - |

## 대시보드와 마케팅 페이지의 구분

| 항목 | 대시보드/앱 화면 | 마케팅 랜딩/메인페이지 |
|---|---|---|
| 목표 | 명확성과 밀도. 반복 업무를 빠르게 끝낸다. | 첫 화면에서 제품이 무엇인지 알게 하고 첫 행동으로 이끈다. |
| 대담함 | 거의 없다. 상태색과 데이터가 주인공이다. | 한 곳에만 쓴다. 기억에 남는 요소 하나(히어로 처리, 서체, 인터랙션 중 하나)를 정하고 나머지는 조용히 둔다. |
| 주 레퍼런스 | Dribbble 샷/검색 | Awwwards 수상작 |
| UUPM 다이얼 | `--density 7~9 --motion 2~3` | `--density 3~5`, `--motion`은 연출 순간 하나에 맞춰 설정 |
| 모션 | 사용자 행동에 대한 응답만(펼침, 저장 확인, 진행률) | 페이지 로드 시퀀스 하나 또는 리빌 하나 |
| 타이포 | 본문 서체 중심, 숫자는 tabular 정렬, 위계는 크기보다 굵기와 색 대비로 | 서체 자체를 디자인 요소로 쓴다 |
| 레이아웃 | 고정 내비게이션, 표/필터/상세 패널, 위계별로 다른 컨테이너 처리(전부 같은 카드로 나누지 않음) | 섹션 수를 줄이고 주제 콘텐츠(실제 결과물, 실제 화면)로 채운다 |
| 색 | 중립 배경 + 의미 있는 상태색. 트랙/카테고리 색은 범례와 함께 쓴다. | 주제에서 뽑은 4~6색 팔레트 |
| 숫자 강조 | KPI 타일은 허용(실제 운영 지표이므로). 단 모든 지표를 같은 카드로 만들지 않는다. | 큰 숫자 히어로는 기본값이므로 피한다 |
| 체크리스트 | 7단계 전부 + 표 가로 스크롤 처리, 빈 상태, 로딩 스켈레톤 | 7단계 전부 + 첫 화면 LCP 이미지 최적화 |

- 대시보드/앱 화면의 구조(레이아웃)는 `DASHBOARD_PATTERNS.md`의 패턴 코드(A~O)로 정한다. 홈 화면에 KPI 타일(패턴 C)을 쓸지는 그 문서 5장 "홈 화면 고르기"를 따른다.
