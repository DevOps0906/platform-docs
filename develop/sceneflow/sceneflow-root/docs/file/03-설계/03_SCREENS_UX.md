# 03 화면과 UX: SceneFlow (sceneflow)

2026-10-13 개정: AI 채널 코치 채팅, 음성(대화, 받아쓰기, 내레이션 엔진 선택), 채널·브랜드 가이드 위키, 대본 기획 미리보기, 디자인 시스템 항목, 4.5절 3D 히어로를 추가했다. 4.5절의 3D 히어로는 사용자 결정(2026-10-13, 확정 결정 15)으로 기존 4.3절 "플레이헤드 1회 스윕" 히어로 연출을 대체한다.

## 7. 로그인 화면 단계별 구성 (2026-10-14 추가, 확정 결정 22)

정본: `docs/file/03-설계/공용코어/AUTH_ROADMAP.md` 2.1절, 3.2절, 5.2절, 7장. 로그인 뒤 화면(`/dashboard/**`, `/onboarding/ai`)은 단계와 무관하게 같다. 여기서 말하는 로그인은 사용자 계정 로그인이며, 채널 연결(`/dashboard/channels`의 YouTube·Meta·TikTok OAuth, 네이버 클립 브라우저 로그인 창)은 단계와 상관없이 2.1절·2.2.1절 그대로다.

### 7.1 `/login` 구성

| 단계 | 구성 | 표시 조건 |
|---|---|---|
| A | "개발용 로그인" 패널: 페르소나 버튼 목록(라벨 예 "owner · Starter 개인 조직", "adv_owner · Advanced 팀 owner", "adv_member · Advanced 팀 member", "outsider · 다른 조직", "no_app · video 엔타이틀먼트 없음"), 현재 로그인 페르소나, 로그아웃. 모든 화면 상단에 고정 배지 `MOCK AUTH · 로컬 전용`(대시보드 셸 포함, 경고색 토큰). 제공자 버튼·이메일 폼·`/signup` 링크 없음 | 서버 컴포넌트에서 `isMockAuthAllowed()`가 참일 때만 렌더. 거짓이면 패널 코드 자체를 내보내지 않는다 |
| B | "Google로 계속하기" 버튼(`prompt: 'select_account'`) + 이메일·비밀번호 폼(01장 D-28) + "비밀번호를 잊으셨나요" + `/signup` 링크. OAuth는 가입과 로그인이 같은 버튼이라 `/signup`에도 같은 Google 버튼 | `AUTH_PROVIDERS`에 `google`, `email` |
| C | B 구성 + "카카오로 계속하기"(C1, 카카오 디자인 가이드 색·문구, 가이드 최신판은 미확인), "네이버로 계속하기"(C2) | `AUTH_PROVIDERS`에 `kakao`, `naver`. 네이버는 검수 통과 전 운영에 노출하지 않는다 |

버튼 순서(제안): Google, 카카오, 네이버, 구분선, 이메일 폼. `next` 쿼리는 그대로 전달하고 서버가 화이트리스트로 검사한다.

### 7.3 첫 OAuth 로그인 뒤 약관 동의

OAuth는 가입 화면을 거치지 않으므로 약관·개인정보처리방침 동의를 제품 온보딩의 첫 단계에서 받는다. 순서: `/auth/callback` → (첫 로그인이고 약관 동의 기록이 없으면) 온보딩 첫 단계 `/onboarding/terms` "약관 동의"(이용약관, 개인정보처리방침, 만 14세 이상 확인, 01장 6절) → `/onboarding/ai`(AI 처리 방식, 2.7절) → `/dashboard`. 동의 기록 위치(감사 기록 또는 프로필 메타데이터)는 VID-06-063에서 정한다(제안: `write_audit`, action `terms.accept`, 약관 버전을 메타데이터에). 이메일 가입은 `/signup` 폼에서 동의를 받으므로 이 단계를 건너뛴다. Stage A 시드 계정은 동의한 상태로 본다.

### 7.4 설정 → 로그인 방법 (C단계, P1)

`/dashboard/settings/login-methods`(제안 경로): 연결된 로그인 수단(Google, 카카오, 네이버, 이메일) 목록, 연결·해제. 연결은 로그인 상태에서 `linkIdentity`(브리지 네이버는 서버 경로), 해제는 남는 로그인 수단이 1개 이상일 때만. 역할 접근은 본인(전 역할), 플랜 접근은 전 플랜. 이 화면은 채널 연결(`/dashboard/channels`)과 다른 화면이며 서로 링크하지 않는다(사용자가 "네이버 연결"을 혼동하지 않게 문구를 "네이버 아이디로 로그인 연결"로 쓴다, 제안).

### 8.5 길이 게이지, 출처 경고, 예상 크레딧 표시 규칙

| 표시 | 규칙 |
|---|---|
| 길이 게이지 | 막대 하나: 0 ~ 목표 x 1.2 눈금, 허용 구간(목표 x 0.9 ~ 1.1)을 옅은 띠로, 현재 합계를 채움으로. 글자 3개를 항상 같이 쓴다: "09:42 / 10:00", "(허용 09:00~11:00)", 상태 "범위 안" / "1분 12초 짧음" / "48초 김". 범위 안은 `--color-success`, 밖은 `--color-warning`(오류색은 쓰지 않는다: 편집 중 범위 밖 저장은 허용, 01장 VD-F-132). 값은 서버 장면 합계로 다시 맞추고 클라이언트 계산을 믿지 않는다(CLAUDE.md 스토리보드 규칙). 범위 밖이면 [렌더로 이동]은 열리지만 렌더 버튼이 비활성 + `VD017` 문구 |
| 장면 수 | "장면 42 (허용 30~80)". 쇼츠 3~12, 롱폼 분당 3~8, 최대 240. 최대에 닿으면 [장면 추가] 비활성 + `VD018` 문구. 하한 미달은 경고 글자만 |
| 출처 경고 수 | `source_required=true`이고 `sources`가 빈 장면 수 + 출처 점검이 WARN을 준 장면 수(중복 제외). 0이면 "출처 경고 없음". 눌러서 해당 장면만 거른다. 경고는 WARN(D-33)이라 렌더를 막지 않고 업로드 compliance에서 확인한다. "사실 확인 완료" 같은 보증 문구를 쓰지 않는다(01장 10.5절 금지 문구) |
| 출처 점검 상태 | 하단 바: "미검사" / "점검 중" / "WARN 3 · 14:10 기준" / "경고 없음 · 14:10 기준". 점검 뒤 장면이 바뀌면 "점검 뒤 장면 5개가 바뀌었습니다" |
| 예상 크레딧 | 서버 단가표(01장 10.4절, `priceOf`)로 지금 상태에서 다음 단계까지 남은 비용을 합산해 "마스터 컷까지 약 N"으로 보인다. [내역]: 새 이미지 n장 x 3, 내레이션 언어별(4.1절 단가, 엔진별), 렌더(10분당 10 / 숏폼 언어당 3), 출처 점검 1, 잔액, 부족분. 이미 ready인 소재와 재사용 이미지는 0으로 셈하고 "재사용 0"을 따로 보인다. 화면 값은 안내이고 실제 차감은 각 요청에서 서버가 정한다 |
| 버튼 옆 단가 | 이미지 만들기·다시 만들기 3, 장면 내레이션 다시 만들기 1, 이미지 재사용 0, 미리보기 0, 출처 점검 1, 쇼츠 선정 2, 컷당 3, 세로 구도 다시 만들기 3. 0인 행동에는 "0크레딧"을 써서 비용이 없음을 알린다 |
| 예시(01장 10.4절) | 롱폼 10분, KO, 40장면, 새 이미지 30장 + 재사용 10장: 대본 5 + 스토리보드 8 + 이미지 90 + TTS 5 + 렌더 10 + 출처 점검 1 = 119. 쇼츠 5편 +17 = 136. 단가는 제안값이다 |

## 9. AI 자동편집과 화면비·해상도 화면 (2026-10-18 추가, 01장 11장)

2026-10-18 개정: 01장 11장(확정 SF-5~SF-8, VD-F-143~159, 명령 허용 목록 11.4절, 단가 11.5절, 플랜 키 11.6절, 열린 결정 D-38~44)의 화면을 이 장에 둔다. 테이블·RPC·오류 코드는 `D:/WorkSpace/platform/docs/products/_supabase-modular/migrations/1200_video.sql` 13절(`:3038`부터)이 정본이다: `video.edit_plans`(`:3401`), `edit_presets`(`:3353`), `pronunciation_lexicon`(`:3371`), `clip_transcripts`(`:3385`), 사용자 RPC `apply_edit_plan(p_plan_id, p_command_ids)`(`:3690`), `undo_edit_plan`(`:3904`), `reject_edit_plan`(`:3996`). 기존 장의 줄 수는 바꾸지 않았다. 8장과 달라진 점은 9.9절에 모았다.

**SceneFlow의 주력 기능은 AI 자동편집이다(SF-5, `01_PRD.md:573`).** 편집기 첫 화면의 중심은 "말이나 글로 지시 → AI 편집안 → 변경 미리보기와 예상 크레딧 확인 → 승인(일부 선택 가능) → 실행 → 되돌리기"다. AI는 편집 명령 목록(EDL)만 만들고 파일을 직접 고치지 않으며(SF-6), 승인 전에는 장면이 바뀌지 않는다(SF-7). 화면 문구에 "AI가 완벽 편집", "편집 시간 ○% 절감" 같은 보장·미검증 수치를 쓰지 않는다(`01_PRD.md:686`).

API 경로는 04장이 정본이다. 이 장에 적은 Route Handler 경로와 시트 쿼리(`?plan=`, `?sheet=`)는 제안이다.

### 9.4 명령 표시 규칙

명령 이름은 01장 11.4절 `op`(`01_PRD.md:621-639`)의 한국어 라벨로 보인다. `op` 코드는 화면에 쓰지 않고 [자세히]에서만 보인다(제안).

| `op` | 라벨 | 전·후 표시 |
|---|---|---|
| `set_duration` | 길이 바꾸기 | "8.0초 → 6.0초". 길이 게이지 변화 "09:42 → 09:40" |
| `move_scene` | 순서 옮기기 | "5번째 → 6번째". 여러 개면 서버가 계산한 최종 순서 한 줄 |
| `delete_scene` | 장면 삭제 | 전 카드 + "삭제" 글자와 취소선 |
| `add_scene` | 장면 추가 | "4번 뒤에 새 장면(글자 카드, 6.0초)" + "소재 없음" |
| `set_text` | 글 바꾸기(내레이션 / 화면 문구 / 시각 설명 / 챕터) | 줄 단위 비교: 지운 글자는 취소선 + "삭제", 더한 글자는 밑줄 + "추가". 내레이션이 바뀌면 "내레이션 소재를 다시 만들어야 합니다" |
| `set_motion` | 모션 바꾸기 | "고정 → 확대" |
| `set_transition` | 전환 넣기 | "컷 → 페이드 500ms" |
| `set_focus` | 크롭 초점 옮기기 | 작은 썸네일 두 장에 점, "50% / 50% → 30% / 40%" |
| `set_music_cue` | 음악 큐 바꾸기 | "없음 → 긴장감" |
| `set_caption_emphasis` | 자막 강조어 | 칩 전·후(빠진 칩 취소선, 더한 칩 "추가") |
| `set_clip_trim` | 클립 앞뒤 자르기 | "0:03.2~0:41.0 → 0:04.0~0:38.5" |
| `remove_ranges` | 구간 잘라내기 | "구간 14개, 합계 12.6초(무음 9 · 군더더기 말 5)" + [구간 보기] |
| `set_shorts_candidate` | 쇼츠 후보 표시 / 해제 | 배지 전·후 |
| `propose_short` | 쇼츠 묶음 제안 | "장면 12~15, 48초" + 훅 문구 |
| `set_render` | 렌더 설정 바꾸기 | "9:16 1080p30 → 9:16 1440p30" + "렌더 크레딧 1배 → 1.5배" |
| `set_style` | 자막·음량 스타일 | "자막 clean → word_pop, 한자 병기 켬" |
| `regenerate` | 다시 만들기(이미지 / 내레이션 / 문장) | 전: 지금 소재. 후: "적용 뒤 생성"(미리 만들지 않는다) |

비용 표시: `regenerate`만 비용이 있다(이미지 3, 내레이션 1, 문장 1). 그 행에 단가 배지를 붙이고, 시트 머리 합계와 적용 버튼에 고른 `regenerate` 단가 합만 넣는다. 0인 명령에는 "0크레딧"을 쓴다(8.5절 규칙). 편집안을 만든 1크레딧은 이미 정산되어 합계에 넣지 않고 거절해도 돌려주지 않는다(`1200_video.sql:3995` 주석). 잔액이 합계보다 적으면 적용 버튼 대신 "크레딧이 n 부족합니다" + [충전] + [다시 만들기 빼고 적용].

렌더 설정 크레딧 배수(01장 11.5절, 제안, D-41 측정 전): 1080p30 = 1배, 1440p 1.5배, 2160p 2배, 60fps 1.5배(곱하고 올림). 패널은 "마스터 컷 렌더 10 → 20" 형태로 바뀐 값을 보이고, 1440p 이상이면 "AI 이미지 n장 업스케일 +n"(장당 1, D-39)을 따로 적는다. 4K는 렌더 전에 합계를 꼭 보인다(`01_PRD.md:664`).

일부 선택 규칙: (1) 명령은 하나씩 해제할 수 있고, 고른 것만 `p_command_ids`로 보낸다. (2) 하나도 고르지 않으면 적용 버튼 비활성. (3) 비용 없는 명령은 한 트랜잭션이라 하나라도 실패하면 아무것도 적용되지 않는다(시트에 그대로 남음). (4) `regenerate`는 비용 없는 명령 적용 뒤 선차감되므로, 선차감이 실패하면 "비용 없는 명령 n개는 적용했고, 다시 만들기 m개는 실행하지 않았습니다"로 알린다(제안). (5) 장면 삭제를 해제하면 같은 장면의 다른 명령은 남는다. 같은 장면을 대상으로 한 `delete_scene`과 다른 명령을 함께 고르면 "삭제할 장면의 다른 명령은 적용되지 않습니다" 안내(제안). (6) 고른 명령으로 바뀐 길이 합계·장면 수를 시트 머리에 다시 보인다(표시만, 판정은 서버).

### 9.6 접근성 (8.7절에 더한다)

| 항목 | 기준 |
|---|---|
| 명령 체크박스 | 장면 묶음마다 `fieldset` + `legend`("장면 5 · 이미지"). 네이티브 Checkbox, Space로 토글, Tab으로 다음 체크박스. "모두 선택"은 일부 선택이면 `aria-checked="mixed"`. 체크 이름에 라벨과 전·후를 포함("길이 바꾸기, 8.0초에서 6.0초로, 0크레딧") |
| 전·후 비교 | 색만 쓰지 않는다: `del`/`ins` 요소 + "삭제"/"추가" 글자. 스크린 리더 이름 "전", "후" |
| 적용 결과 알림 | `aria-live="polite"`: "명령 6개를 적용했습니다. 이미지 다시 만들기 1개를 시작했습니다." 실패는 `role="alert"`. 적용 뒤 포커스는 편집기 AI 편집 패널의 그 편집안 행으로 |
| 생성 진행 | 단계 이름 바뀔 때 `aria-live="polite"`. 시트가 열리면 포커스는 시트 제목, Esc로 닫기, 닫으면 [검토] 버튼으로 복귀 |
| 크롭 초점 선택 | 점은 포커스 가능한 요소(`role="slider"` 2개 묶음 또는 `role="application"` + 설명, 제안). ←/→ 가로 1%, ↑/↓ 세로 1%, Shift+화살표 10%, Home 가운데로. `aria-valuetext`("가로 30%, 세로 40%"). 숫자 입력 칸 2개를 대체 수단으로 함께 둔다 |
| 세이프존 토글 | 버튼 `aria-pressed`, 플랫폼 선택은 라디오 그룹. 겹침 영역은 무늬 + 글자 라벨(색만 아님) |
| 무음 구간 목록 | 행마다 [듣기] 버튼 이름 "구간 3 듣기, 0:12.4부터 0:13.1까지, 무음". 강도는 라디오 그룹, 최소 무음·여유는 숫자 입력(ms 단위 표시) |
| 마이크 | 녹음 버튼 `aria-pressed`, 받아쓴 글은 편집 가능한 입력칸으로 들어가 확인 전 전송 없음(VOICE_ARCHITECTURE 규칙) |
| 단축키 | 입력 칸 밖에서 E: AI 편집 지시 칸으로 포커스(제안). [단축키] 도움말에 적는다 |
