## 4. 메인페이지(랜딩) 디자인 방향

### 4.5 광고 슬롯 지도 (NW-F-030, 031, 032)

크기는 IAB 고정 크기 규격(https://www.iab.com/wp-content/uploads/2019/04/IABNewAdPortfolio_LW_FixedSizeSpec.pdf)과 AdSense 권장 크기(https://support.google.com/adsense/answer/6002621)에서만 고른다. 모든 슬롯은 서버가 크기를 알고 `min-height`(또는 `aspect-ratio`)로 공간을 먼저 잡는다. 소재가 없으면 하우스 광고(신문사 자체 알림: 뉴스레터, 제보, 구독)로 채우고 **접지 않는다**(web.dev: 광고가 CLS의 가장 큰 원인, https://web.dev/articles/optimize-cls). 슬롯 크기는 테넌트가 바꿀 수 없다.

### 4.6 그리드와 브레이크포인트

### 7.1 편집국 로그인 `/login`

| 단계 | 구성 | 렌더 조건 |
|---|---|---|
| A(Mock, 로컬 전용) | "개발용 로그인" 패널: 페르소나 버튼 `owner`(발행인 publisher), `admin`(편집인 editor), `desk`, `member`(기자 reporter), `contributor`, `ad_manager`, `viewer`, `outsider`(다른 신문사 발행인), `no_app`(개설 신청 전), `suspended`, `ops`(05장 10절), 현재 페르소나, 로그아웃. 모든 화면(독자 사이트 포함) 상단 고정 배지 `MOCK AUTH · 로컬 전용`(대비 4.5:1, 닫기 없음). 제공자 버튼·이메일 폼 없음 | `isMockAuthAllowed()`가 참일 때만 서버에서 분기. 거짓이면 코드가 렌더되지 않는다 |
| B(Google + 이메일) | "Google로 계속하기"(`prompt=select_account`) + 구분선 + 이메일·비밀번호 폼 + 비밀번호 재설정 링크. `/signup`은 개설 신청자용 이메일 가입(엔타이틀먼트를 만들지 않음, 가입 뒤 `/no-access` → `/apply`). 초대받은 기자는 `/accept-invite`에서 비밀번호 설정 또는 Google 연결 | `AUTH_PROVIDERS`에 `google`, `email` |
| C1·C2 | P2 선택. 결정 전에는 버튼을 렌더하지 않는다 | `AUTH_PROVIDERS`에 있을 때만 |

엔타이틀먼트가 없는 로그인 사용자는 `/no-access`로 간다. 문구: "초대받은 이메일로 로그인하세요. 신문사를 새로 개설하려면 개설 신청을 하세요. [개설 신청] [로그아웃]". 신청이 진행 중이면 `/pending`, 반려면 사유 표시. 첫 로그인 약관 동의는 개설 신청 3단계(서비스 약관)와 초대 수락 화면(구성원 약관·개인정보 처리 안내)에서 받는다.

### 7.2 독자 로그인 `/login` (테넌트 도메인)

| 단계 | 구성 | 렌더 조건 |
|---|---|---|
| A(Mock, 로컬 전용) | "개발용 독자 로그인" 패널: `reader`(독자), `reader_member`(유료 멤버), `reader_other`(다른 신문 독자 = 이 신문 `readers` 행 없음, 첫 진입 `ensure_reader` 확인), 로그아웃 상태로 `anon` 시나리오. 로컬 테넌트 해석은 `<slug>.localhost:3000`(예: `acme.localhost:3000`, 02장 인증 단계 절) | 같음 |
| B(이메일 매직 링크 + Google) | 신문사 제호 + "로그인은 <플랫폼> 공통 계정으로 합니다. 다른 신문사에서 쓰던 계정으로도 로그인할 수 있습니다" 한 줄 + "Google로 계속하기" + 이메일 입력 → "로그인 링크 보내기" → 메일 확인 안내 화면. 가입·로그인이 같은 흐름(비밀번호 없음) | `AUTH_PROVIDERS` |
| C1 카카오(P1) / C2 네이버(P1) | B 위에 "카카오로 계속하기"(C1), "네이버로 계속하기"(C2). 순서: 카카오 → 네이버 → Google → 이메일(제안: 지역 독자는 카카오가 주 경로라 맨 위, 독자 화면만 편집국과 순서가 다름). 색·문구는 각 사 디자인 가이드(최신판 미확인) | G2 뒤, `AUTH_PROVIDERS`에 있을 때 |

| 콜백 방식(D-3) | 화면 차이 |
|---|---|
| (a) 테넌트 도메인 콜백(권고) | 제공자 → `https://<테넌트 호스트>/auth/callback` → 원래 기사. 커스텀 도메인 활성화 때 관리 API로 Redirect URL 자동 등록(허용 목록 상한 미확인) |
| (b) 중앙 로그인 도메인 | `/login`이 `login.<플랫폼>/?tenant=<slug>&next=`로 이동(신문사 제호를 같이 표시) → 로그인 → 일회용 코드(60초, 1회, 02장)로 테넌트 `/auth/handoff` → 세션. 주소창 도메인이 바뀐다는 안내 한 줄 |

OAuth 동의 화면의 앱 이름은 플랫폼 브랜드다(독자 계정은 플랫폼 공통, `develop/_shared/auth/README.md` AUTH-D1과 같은 이유). 전용 DB(판매 모델 B) 신문사만 자기 브랜드. 첫 로그인 뒤 `news.ensure_reader` → 동의 기록이 없으면 `/account/consent`(약관·개인정보 필수, 만 14세 이상 확인, 뉴스레터·광고성 정보 선택) → 원래 페이지(`next`는 같은 테넌트 경로만 허용).

### 7.3 오류 상태 (두 로그인 화면 공통)

| 쿼리·상황 | 단계 | 표시 위치 | 문구 |
|---|---|---|---|
| `?error=callback` | B·C | 로그인 폼 위 오류 띠 | 로그인을 끝내지 못했습니다. 다시 시도해 주세요 |
| `?error=state` | C2 브리지(채택 시), D-3 (b) 코드 만료 | 같음 | 로그인 요청이 만료되었거나 올바르지 않습니다. 처음부터 다시 시도해 주세요 |
| `?error=email_in_use` | C2 브리지, C1 자동 연결 실패 | 같음 | 이미 다른 방법으로 가입한 이메일입니다. 그 방법으로 로그인한 뒤 내 정보에서 이 로그인 방법을 연결하세요 |
| `?error=provider` | B·C(제공자 동의 취소, 제공자 장애, 비활성 제공자) | 같음 | 카카오 로그인을 완료하지 못했습니다. 동의를 취소했다면 다시 시도하거나 다른 방법으로 로그인하세요 |
| 매직 링크 만료 | B | 메일 확인 화면 | 로그인 링크가 만료되었습니다(유효 시간 미확인, 구현 시 Supabase 설정). 새 링크를 받으세요 |
| 프로필 없음 | 전 단계 | 로그아웃 후 `/login` | 계정 정보를 불러오지 못했습니다. 다시 로그인해 주세요 |
| `status=suspended` | 전 단계 | `/suspended`(편집국), 독자는 로그인 화면 띠 | 이용이 정지된 계정입니다. 신문사(또는 운영팀)에 문의하세요 |
| 엔타이틀먼트 없음 | 편집국 | `/no-access` | 7.1절 문구 |
| 신문사 공개 차단 중 독자 로그인 | 독자 | `/unavailable` | 이 신문사 홈페이지는 준비 중입니다 |

코드·토큰·제공자 원문 오류는 화면에 보이지 않는다. 쿠키·localStorage에 역할·플랜을 두지 않는다(`AUTH_ROADMAP.md` 2.4절).

### 7.4 설정 → 로그인 방법 (C단계)

| 항목 | 독자 `/account`의 "로그인 방법" | 편집국 `/settings/account`의 "로그인 방법" |
|---|---|---|
| 단계 | C1(P1)이 만들고 C2가 네이버 행을 더한다. A·B에서는 렌더하지 않는다 | C가 P2 선택이라 결정 전에는 렌더하지 않는다 |
| 구성 | 연결된 제공자(이메일, Google, 카카오, 네이버)와 연결 시각, 연결·해제 버튼 | 같음 |
| 연결 | 로그인 상태에서 `linkIdentity({ provider })`(`enable_manual_linking = true`). 네이버 브리지면 `/auth/naver/start?link=1`(다른 사용자에 연결된 id면 거부) | 같음 |
| 해제 | 남는 로그인 수단이 1개 이상일 때만. 마지막이면 "다른 로그인 방법을 먼저 연결하세요" | 같음 |
| 감사 | `auth.identity_link`, `auth.identity_unlink` | 같음 |
| 범위 안내 | "로그인 방법은 <플랫폼> 공통 계정에 적용되어 다른 신문사 사이트에서도 같습니다" 한 줄 | - |
