# 07_SALES_AND_OPERATIONS — 판매, 고객 온보딩, 운영

작성일 2026-10-14. 금액은 모두 **제안**이며 정본은 `Price_Plans/`(공용 규칙 `Price_Plans/_common/PRICING_PRINCIPLES.md`)다. 가격을 정하면 각 플랫폼 `PRICE_PLAN.md`에 옮기고 이 문서는 링크만 남긴다.

## 1. 상품 구조 (단계 = 상품)

| 상품(코드 제안) | 단계 | 포함 | 판매 모델 | 과금 구조(제안) |
|---|---|---|---|---|
| `<플랫폼>-WL-BASIC` | L1 | 로고 6슬롯, 색·서체·라운드, 사업자 정보 푸터, 서브도메인(`acme.<플랫폼>`), 셀프서비스 브랜딩 화면, "Powered by" 표시 | C(공유) | 구독 + 화이트라벨 추가 요금 |
| `<플랫폼>-WL-PRO` | L2 | Basic + 커스텀 도메인 5개, 용어·메뉴, "Powered by" 숨김, 기능 예외 1건 | C 또는 B | 셋업 + 월 유지보수 |
| `<플랫폼>-WL-DEDICATED` | L2 + 전용 DB | Pro + 고객사 전용 Supabase·배포 | B | 공용 모델 B: 셋업 20만원 + 월 유지보수(`PRICING_PRINCIPLES.md` 5장) + 인프라 실비 |
| `<플랫폼>-WL-ENT` | L3/L4 | 슬롯 화면, 연동 훅 | B | 개발비(건별 견적) + 연 유지비 |
| 대행 세팅(옵션) | L1 | 브랜딩을 운영자가 대신 세팅(로고 정리, 색 결정, 검수) | 모두 | 건별(시간 한도 명시) |

| 규칙 | 내용 |
|---|---|
| 무제한 금지 | "무제한 커스터마이징·수정" 금지. 건수 또는 시간 한도로 쓴다(`PRICING_PRINCIPLES.md` 6장) |
| L5 | 포크 요청은 견적서에 넣지 않는다. 필요하면 "제품 로드맵 반영(전 고객 제공)"으로 제안하고 일정은 약속하지 않는다 |
| 원가 | B는 Supabase·Vercel 고객사별 실비를 원가표(`Price_Plans/_common/COST_BASELINE.md`)로 계산해 유지보수 금액 하한을 정한다 |
| VAT | B2B 상품은 "VAT 별도" 표기 |

## 2. 단계별 가격 결정 절차

1. 시장 비교: 같은 범주 SaaS의 화이트라벨 추가 요금·에이전시 플랜을 조사해 `Price_Plans/<플랫폼>/`에 기록(조사일 명시).
2. 원가: 셋업에 드는 운영자 시간(대행 세팅 포함) × 시간 단가 + 고객사별 인프라 실비.
3. 가치: 고객사가 같은 기능을 외주 개발할 때 비용과 비교.
4. 파일럿 1~3곳에 제안가로 판매 → 실제 소요 시간으로 보정 → 확정.

## 3. 고객 온보딩 체크리스트 (고객사에서 받을 것)

| 항목 | 형식 | 필수 | 메모 |
|---|---|---|---|
| 가로형 로고 | SVG(권장) 또는 AI·PDF 원본, 투명 PNG 높이 120px 이상 | 필수 | JPG만 있으면 배경 제거 대행(옵션) |
| 심볼(정사각) 로고 | SVG 또는 PNG 512×512 | 권장 | 없으면 첫 글자 마크 자동 |
| 어두운 배경용 로고 | 가로형과 같음 | 선택 | 다크 모드·어두운 사이드바 |
| 브랜드 색 | HEX 1~2개 또는 브랜드 가이드 PDF | 선택 | 없으면 로고에서 추출 |
| 서체 | 레지스트리 목록에서 선택 | 선택 | 전용 서체는 웹 라이선스 증빙(L3) |
| 사업자 정보 | 상호, 대표자, 사업자등록번호, 통신판매업 신고번호(해당 시), 주소, 전화 | 필수 | 푸터·메일 표시 |
| 고객센터 | 이메일, URL | 필수 | |
| 약관·개인정보처리방침 URL | https URL | 필수 | 고객사가 개인정보 처리자인 경우 위탁 관계를 계약서에 명시 |
| 서브도메인 이름 | 영문 소문자·숫자·하이픈 | 필수 | 예약어 불가(05장 4.2절) |
| 커스텀 도메인 | `app.회사.com` + DNS 관리 담당자 연락처 | Pro 이상 | 루트 도메인 연결은 A 레코드 필요 |
| 용어 목록 | 기본 문구 → 바꿀 문구 표 | Pro 이상 | 라벨 키 목록을 엑셀로 보내 채워 받기 |
| 관리자 계정 | owner 1명, admin 이메일 | 필수 | owner는 조직당 1명 |

## 4. 운영 SOP

| 단계 | 할 일 | 도구 | 완료 확인 |
|---|---|---|---|
| 1 계약 | 상품·단계·한도·유지보수 범위 확정, 계약서(nomad-docs로 생성) | nomad-docs | 서명 |
| 2 조직 | 회사 조직 생성(`is_personal=false`), slug 지정, owner 초대 | 운영자 화면(service_role) | owner 로그인 |
| 3 단계 부여 | 화이트라벨 플랜으로 엔타이틀먼트 변경, 예외는 `tenant_feature_overrides`(사유·만료) | 운영자 화면 | `theming_level` 확인 |
| 4 배포 기록 | `tenant_deployments`(모델·프로젝트 ref·채널) | 운영자 화면 | 모델 B면 전용 프로젝트 생성·마이그레이션 적용 |
| 5 브랜딩 | 고객 셀프 또는 대행: 로고 업로드 → 색 추출 → 대비 통과 → 게시 | 브랜딩 화면 | 버전 1 게시 |
| 6 도메인 | 도메인 요청 → DNS 안내 메일 → `active` | 도메인 화면, 검증 크론 | 인증서 발급, 301 이동 |
| 7 검수 | 시험 계정으로 로그인·메일·PDF·OG·다크 모드·모바일 확인(검수표) | E2E 스크린샷 | 고객 승인 |
| 8 운영 | 요청 접수 → 단계 판정(01장 2절) → L1·L2는 설정, L3·L4는 견적 | 요청 기록표 | 같은 요청 2회 → 공통 기능 승격 검토 |
| 9 해지 | 엔타이틀먼트 만료 → 기본 브랜드 복귀, 도메인 `removed`, 데이터 보관 기간 안내 | 운영자 화면 | 감사 기록 |

## 5. 자동화

| 자동화 | 효과 | 도구 |
|---|---|---|
| 로고 → 브랜드 미리보기 링크 | 영업 데모: "로고만 주시면 5분 안에 귀사 버전 미리보기" | `core-tenancy` 팔레트 + 미리보기 전용 공개 페이지(만료 링크) |
| 온보딩 플로우 | 계약 서명 → 조직 생성·초대 → 체크리스트 메일 → 미제출 항목 리마인드 | n8n(코어 웹훅) |
| 도메인 상태 알림 | DNS 안내·완료·실패 메일 자동 발송 | 검증 크론 |
| 요청 분류 | 고객 요청 문장 → 단계(L1~L5) 자동 제안 → 운영자 확인 | AI 분류(제품 AI 계층) |
| 월간 리포트 | 고객사별 사용량·게시 이력·도메인 상태 | 크론 + 메일 |
