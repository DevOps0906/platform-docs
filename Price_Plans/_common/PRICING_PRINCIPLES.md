# 공용 가격 결정 원칙 (모든 플랫폼)

작성일 2026-10-14. 제품 SaaS와 서비스 사업 모두 이 문서의 절차와 공식으로 가격을 정한다. 근거가 없는 수치는 "제안"으로 표시했다.

## 1. 범위와 정본 관계

| 대상 | 가격 정본 | 이 폴더의 역할 |
|---|---|---|
| 제품 SaaS(13개) | 각 제품 `01_PRD.md` 4장 + `seed.sql`(확정 결정 8, `products/00_MERGE_ANALYSIS.md:16`) | 단계별 계획, 원가, 경쟁 가격, 판매 모델, 인상 시점 |
| 서비스 사업(대행) | `Price_Plans/<플랫폼>/PRICE_PLAN.md` | 정본 그 자체 |

## 2. 단계 정의 (초기·중기·장기)

모든 플랫폼은 같은 세 단계로 가격을 계획한다. 기간보다 **전환 조건(게이트)** 을 우선한다. 기간이 지나도 게이트를 넘지 못하면 다음 단계로 가지 않는다.

| 단계 | 기간(제안) | 목표 | 가격 성격 | 다음 단계 게이트(제안) |
|---|---|---|---|---|
| 초기 | 0~3개월 | 시장 검증, 리뷰·사례 확보, 첫 매출 | 시장 하단~중간, 런칭 할인 | 서비스: 리뷰 20건 또는 납품 10건. SaaS: 유료 고객 30명, 첫 달 해지율 10% 이하 |
| 중기 | 4~12개월 | 단가 인상, 패키지화, 반복 매출 | 시장 중간~상단, 구독·패키지 | 서비스: 반복 매출 비중 30% 이상. SaaS: MRR 손익분기, 순 매출 유지율 100% 이상 |
| 장기 | 1~3년 | 제품화, 자동화, 화이트라벨 | 가치 기반, 제품 매출 확대 | 해당 없음(분기마다 재검토) |

## 3. 가격 결정 절차 (6단계)

| 단계 | 할 일 | 산출물 |
|---|---|---|
| 1 원가 | 인프라·AI·외부 서비스·작업 시간 원가를 계산한다(4장 공식, `COST_BASELINE.md`) | 단위 원가 |
| 2 기준 가격 | 경쟁 상품 3개 이상의 공개 가격을 확인일과 함께 적는다 | 시장 하단·평균·상단 |
| 3 가치 | 고객이 얻는 결과(문의 수, 절약 시간, 매출)를 수치로 적는다 | 가치 상한 |
| 4 등급 | 3단 구성(라이트·스탠다드·프리미엄 또는 Free·Basic·Pro). 가운데 등급을 주력으로 두고 위 등급은 앵커로 쓴다 | 등급표 |
| 5 검증 | 초기 단계 가격으로 판매해 전환율·문의 반응을 본다 | 검증 기록 |
| 6 반영 | 확정되면 SaaS는 PRD 4장·seed 수정 task, 서비스는 `PRICE_PLAN.md` 상태를 "확정"으로 | 변경 기록 |

## 4. 가격 공식

### 4.1 서비스형(대행·제작)

```
가격 = 실작업 시간 x 내부 시간 단가 + 외부 비용(에셋·폰트·유료 이미지) + 리스크 버퍼(15~20%)
```

| 단계 | 내부 시간 단가(제안) | 이유 |
|---|---|---|
| 초기 | 5만원 | 리뷰 확보 단계. 크몽 앱 개발 평균 견적 150만원 수준의 시장과 맞춘다(`Web-App-Agency/01_MARKET_BENCHMARK.md` 1장) |
| 중기 | 8만원 | 리뷰 20건 이후, 패키지·업종 특화로 비교 대상이 줄어든다 |
| 장기 | 12만원 이상 | 고단가 MVP·정부지원 집행 프로젝트 |

- 진입 상품(예: 네이버 블로그 스킨)은 공식보다 낮게 받을 수 있다. 이때 문서에 "진입 상품, 공식 미달"이라고 적고 업셀 경로를 함께 적는다.
- AI 에이전트로 줄어든 시간은 가격을 내리는 데 쓰지 않고 마진과 납기 단축에 쓴다(제안).

### 4.2 SaaS형(구독·크레딧)

```
크레딧 단가 >= 작업당 원가(원가 지표 x 환율) / (1 - 목표 매출총이익률)
월 구독가 >= (월 포함 크레딧 x 크레딧 원가) + 고객당 고정 인프라 원가 + 결제 수수료
```

| 항목 | 값(제안) | 근거 |
|---|---|---|
| 목표 매출총이익률 | 70% 이상 | SaaS 일반 기준(제안) |
| AI 원가 지표 | 코어 seed 단가 사용 | `products/_supabase-modular/seed.sql:228-246` |
| 원화 환산 | 미확인(구현 시 측정) | `products/website-floria/01_PRD.md` 4.1절과 같은 처리 |

## 5. 판매 모델 (모든 플랫폼 공용)

| 코드 | 모델 | 과금 | 적합 | 근거 |
|---|---|---|---|---|
| S | 서비스(대행·제작) | 건별 + 유지보수 월정액 | 에이전시, 쇼츠 대행, 청첩장 대행 | 이 문서 |
| A | 설치형 | 1회 + 연간 30만원, 고객 API 키, 로컬 저장 | 데이터를 밖에 두기 싫은 고객 | 사용자 결정(3-판매모델 구조) |
| B | 호스팅 화이트라벨 | 셋업 20만원 + 월 유지보수, 고객별 전용 Supabase | 대행사·브랜드 리셀 | 사용자 결정(3-판매모델 구조) |
| C | 표준 SaaS | 구독 + 크레딧팩, 모놀리스 RLS | 개인·소규모 사업자 | 확정 결정 8 |

플랫폼 문서는 이 중 어떤 모델을 쓰는지 표로 밝힌다. 한 플랫폼이 여러 모델을 쓸 수 있다(예: 에이전시 S로 납품 → 고객을 C로 전환).

## 6. 할인·인상 규칙

| 규칙 | 내용(제안) |
|---|---|
| 런칭 할인 | 정가 대비 최대 40%, 기간 또는 선착순 수량을 반드시 명시 |
| 연간 결제 | 월 구독의 15~20% 할인 |
| 인상 | 신규 고객부터 적용. 기존 구독 고객은 3개월 유예 후 적용하고 30일 전에 알린다 |
| 무제한 금지 | "무제한 수정", "무제한 요청"은 쓰지 않는다. 시간 한도 또는 횟수 한도로 표기 |
| 묶음 | 두 플랫폼 이상 묶음은 합계의 10~15% 할인까지 |

## 7. 표기 규칙

| 항목 | 규칙 |
|---|---|
| 통화 | 원화. 외부 원가가 달러면 달러 원문 + 확인일 |
| 부가세 | 가격표마다 "VAT 별도" 또는 "VAT 포함"을 명시(제안: 서비스 사업은 VAT 별도, B2C SaaS는 VAT 포함) |
| 범위 가격 | "99만원~" 처럼 시작가 표기를 허용하되 포함 범위를 같은 표에 적는다 |
| 상품 코드 | `<플랫폼약어>-<등급>` 형태. 예 `AG-ML-STD`(에이전시 모션 랜딩 스탠다드) |
