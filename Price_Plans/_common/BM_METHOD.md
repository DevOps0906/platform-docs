# 공용 BM(사업모델) 설계·평가 방법

작성일 2026-11-11. 어떤 제품·서비스든 `Price_Plans/<플랫폼>/PRICE_PLAN.md`를 쓰기 전에 이 문서의 7단계 절차와 스코어 루브릭을 쓴다. 가격 공식·단계·판매 모델은 `PRICING_PRINCIPLES.md`가 정본이고 이 문서는 그 앞단(사업이 성립하는가)을 다룬다. 이 방법을 소프트웨어로 구현한 제품이 `products/bm-core/`다(`products/bm-core/01_PRD.md`). 출처는 사용자 제공 원본 자료(2026-11-11)이고, 아래 수치는 모두 제안이며 실제 데이터로 교체한다.

## 1. 7단계 절차

| 단계 | 할 일 | 산출물 | 이 문서 외 연결 |
|---|---|---|---|
| 1 고객·문제 | 타깃, 문제, 현재 대안, 검증 질문 | 고객 정의 표 | PRICE_PLAN 1장 |
| 2 가치 제안 | 한 문장 + 정량 표현(비용 절감률, 기간 단축) | 가치 문장 | PRICING_PRINCIPLES 3장 3단계(가치 상한) |
| 3 수익모델·가격 가설 | 요금제, 가격, 과금 단위, 가격 근거(경쟁 단가) | 가격 가설 표 | PRICING_PRINCIPLES 3~5장 |
| 4 단위경제 | ARPU, 변동비, 공헌이익, 이탈률, LTV, CAC 상한, 손익분기 | 2장 계산표 | PRICE_PLAN 3장 원가 구조 |
| 5 파트 분리·공통비 배분 | 파트별 역할과 수익모델, 공통비 배분 기준 | 파트 표 | PRICE_PLAN 5장 판매 모델 |
| 6 린 검증 설계 | 가설, 실험, 통과 기준(실험 전에 숫자로 확정) | 검증 계획 | PRICE_PLAN 8장 게이트 |
| 7 사업성 스코어 | 3장 루브릭으로 채점, 4장 판정 구간 적용 | 스코어카드 | PRICE_PLAN 8·10장 |

원칙: 개발 착수가 아니라 6단계 검증이 먼저다. 점수가 낮으면 가장 낮은 축을 올리는 검증으로 돌아간다(4장).

## 2. 단위경제 계산 (4단계)

| 지표 | 공식 |
|---|---|
| ARPU | 기간 매출 / 평균 유료 고객 수 |
| 공헌이익, 공헌이익률 | 매출 - 변동비, 공헌이익 / 매출 |
| 단순 LTV | 월 고객당 공헌이익 / 월 이탈률 (이탈률 일정 가정) |
| LTV/CAC | LTV / 실제 CAC |
| CAC 상한 | LTV / 목표 LTV/CAC 배수(예: 3배) |
| CAC 회수 기간 | CAC / 월 고객당 공헌이익 |
| 손익분기 고객 수 | 월 고정비 / 월 고객당 공헌이익 |
| MRR, ARR | 월 반복 매출, MRR x 12 |
| 월 영업손익 | 총공헌이익 - 월 고정비 |

- 실제 CAC(가정치)와 CAC 상한(목표 배수에서 역산)은 별개 값이다. 한 칸에 섞어 쓰지 않는다.
- 단순 LTV는 이탈률이 일정하다는 가정이다. 데이터가 쌓이면 코호트 LTV로 바꾼다.
- 정교화 대상: 고객군별 이탈률, 무료 사용자 운영비, 환불, 세금(VAT), 결제 수수료(제안).
- 공통비 배분은 원인 기준을 우선한다: 서버·API는 사용량, 인건비는 투입 시간 또는 매출 비중, 마케팅은 캠페인 귀속. 배분 합계는 원 총비용과 같아야 한다.

## 3. 예시: BookForge (1인 작가용 AI 전자책 제작 SaaS, 가칭)

모든 값은 가정치(제안)다. 실제 제품 수치가 아니다.

| 단계 | 예시 값 |
|---|---|
| 1 고객·문제 | 책을 내고 싶은 직장인·강사·전문가. 원고 정리, 표지, 편집, 유통 등록이 각각 다른 도구와 외주라 한 권에 수십만 원, 수 주. 대안: 크몽 외주, 한글·캔바, 출판 대행. 검증 질문 "지금 전자책 한 권에 얼마를 쓰고 있나요?" |
| 2 가치 | "원고 초안만 올리면 하루 만에 유통 가능한 전자책 파일을 만든다." 비용 80% 절감, 기간 2주에서 1일 |
| 3 가격 | Free 0원(1권 체험, 워터마크) / Pro 월 29,000원(월 3권) / 크레딧 권당 9,900원 / 구축(B2B) 건당 300만원. 근거: 외주 단가 권당 30~50만원 |
| 4 단위경제(Pro) | ARPU 29,000 / 변동비 8,700(AI API 5,500 + 결제 1,000 + CS 2,200) / 공헌이익 20,300(70%) / 이탈 5% / LTV 406,000 / CAC 상한 약 135,000 / 손익분기 월 고정비 300만원 기준 약 148명 |
| 5 파트 | A SaaS(핵심 수익, 서버·API는 사용량 배분), B 전자책(유입, 인건비는 매출 비중), C 교육(성장, 매출 비중), D 구축(현금흐름, 투입 시간) |
| 6 검증 | 인터뷰 20명(문제 공감 70%) -> 랜딩 사전예약 전환 5% -> 노코드 데모 유료 의향 10명 -> 첫 결제 5건 -> MVP 착수. 퍼널 가정: 방문 2,000 -> 사전예약 100 -> 유료 20(20%) |
| 7 스코어 | 시장성 14 / 수익성 16 / 검증도 4 / 실행가능성 17 / 확장성 16 = 67점. 60~79 구간이라 검증도 보강이 우선(4에서 14 이상이면 80점대) |

시나리오 예(월 29,000원 공통): 보수(변동비 11,000, 이탈 9%, 고정비 400만원) 손익분기 223명, LTV 200,000 / 기준(8,700, 5%, 300만원) 148명, 406,000 / 낙관(7,000, 3%, 250만원) 114명, 약 733,333. 실제 CAC 90,000 가정이면 LTV/CAC 약 4.51.

## 4. 스코어 루브릭 (7단계)

5축 x 지표 4개 x 0~5점 = 축당 20점, 합계 100점. 루브릭은 `rubric_version`으로 버전 관리하고, 채점 때 어떤 버전을 썼는지 남긴다.

| 축 | 지표 1 | 지표 2 | 지표 3 | 지표 4 |
|---|---|---|---|---|
| 시장성 | 고객 명확성 | 문제 강도 | 시장 접근성 | 경쟁 차별성 |
| 수익성 | 공헌이익 | CAC/LTV | 현금흐름 | 가격 수용성 |
| 검증도 | 인터뷰 | 행동 데이터 | 유료 결제 | 반복 사용 |
| 실행가능성 | 기술 | 인력 | 자본 | 운영·규제 |
| 확장성 | 반복 판매 | 자동화 | 고객 확장 | B2B 확장 |

- 0~5점의 앵커 문장(각 점수의 정의)은 미확정이다. `rubric_version` 1에서 팀장이 정한다(팀장 결정 필요).
- 점수와 승인은 분리한다. 차단 조건(blocking_conditions: 법적 문제, 실결제 검증 0건 등)이 하나라도 있으면 85점이어도 보류다.

### 4.1 판정 구간

| 합계 | 판정 | 다음 행동 |
|---|---|---|
| 80 이상 | 개발·신청 | MVP 개발 착수, 지원사업 신청 |
| 60~79 | 추가 검증 | 부족한 축을 올리는 실험 후 6단계로 복귀 |
| 40~59 | 축소 | 노코드 MVP로 줄여 6단계부터 다시 |
| 40 미만 | 보류·폐기 | 재정의 또는 중단 |

### 4.2 증거 등급

| 등급 | 증거 | 예 |
|---|---|---|
| A | 실결제, 계약, 사용 로그 | 결제 내역, 서명 계약 |
| B | 고객 행동, 사전예약 | 랜딩 전환, 대기자 등록 |
| C | 인터뷰, 설문 | 인터뷰 기록 |
| D | 경쟁사·시장 조사 | 공개 가격, 보고서 |
| E | AI 추정, 창업자 가정 (미검증) | 가정치, AI 생성 수치 |

- A 등급도 통계적 타당성을 자동 보장하지 않는다(표본·기간을 같이 적는다).
- E 등급은 검증 데이터처럼 채점하지 않는다. 모든 증거에 출처와 측정 방법을 적는다.
- 등급별 점수 상한(예: E 등급 근거만이면 최대 몇 점)은 미확정이다(팀장 결정 필요).

## 5. 다른 문서에서 쓰는 법

| 위치 | 쓰는 방법 |
|---|---|
| `Price_Plans/<플랫폼>/PRICE_PLAN.md` 1장 | 1~2단계 표를 그대로 쓴다 |
| PRICE_PLAN 3장(원가 구조) | 2장 공식으로 계산하고 값은 "제안" 또는 측정일을 붙인다 |
| PRICE_PLAN 8장(게이트) | 6단계 통과 기준을 숫자로 옮긴다. 7단계 점수와 판정 구간을 함께 적는다 |
| 제품 `01_PRD.md` 7장(KPI) | 통과 기준과 같은 값을 쓰고 새 수치를 만들지 않는다 |
| 소프트웨어 구현 | `products/bm-core/`가 이 절차를 7단계 Wizard·계산 엔진·스코어카드로 구현한다 |
