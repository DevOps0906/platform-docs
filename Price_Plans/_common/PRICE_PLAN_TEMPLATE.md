# PRICE_PLAN_TEMPLATE: 플랫폼별 가격 플랜 장 구조

작성일 2026-10-14. 모든 플랫폼 폴더의 `PRICE_PLAN.md`는 아래 장 제목과 순서를 그대로 쓴다. 해당 없는 장은 "해당 없음"과 이유 한 줄을 적는다. 서비스 사업은 상세 문서(`01_`~`05_`)를 추가할 수 있지만 `PRICE_PLAN.md`의 장 구조는 같다.

## 장 구조

```
# 가격 플랜: <플랫폼명> (<폴더명>)
상태: 미작성 / 초안 / 검토 / 확정 · 작성일 · 최종 수정일

## 1. 한 줄 정의와 고객
## 2. 현재 정본
## 3. 원가 구조
## 4. 시장 기준 가격
## 5. 판매 모델
## 6. 단계별 가격 계획
### 6.1 초기 (0~3개월)
### 6.2 중기 (4~12개월)
### 6.3 장기 (1~3년)
## 7. 추가 옵션과 반복 매출
## 8. 매출 목표와 게이트
## 9. 정본 반영 기록
## 10. 열린 결정
```

## 장별 필수 내용

| 장 | 필수 내용 |
|---|---|
| 1 | 플랫폼을 한 문장으로. 주 고객 2~3유형 |
| 2 | SaaS: `products/<제품>/01_PRD.md` 4장 위치와 현재 플랜 요약. 서비스: "이 문서가 정본" |
| 3 | 단위 원가 표(항목 \| 원가 \| 근거). 공용 원가는 `_common/COST_BASELINE.md` 인용 |
| 4 | 경쟁 상품 3개 이상(상품 \| 가격 \| 출처 URL \| 확인일) |
| 5 | `_common/PRICING_PRINCIPLES.md` 5장의 S/A/B/C 중 사용 모델과 이유 |
| 6 | 단계마다 가격표(코드 \| 상품 \| 등급별 가격 \| 포함 범위). 단계 전환 시 바뀌는 점 |
| 7 | 추가 옵션, 유지보수·구독, 크레딧팩 |
| 8 | 단계별 월 매출 목표, 다음 단계 게이트(`PRICING_PRINCIPLES.md` 2장) |
| 9 | 표: 날짜 \| 변경 \| 반영 위치(PRD 4장, seed, 판매 페이지) \| PR |
| 10 | 대표님이 결정할 항목, 선택지, 권고 |
