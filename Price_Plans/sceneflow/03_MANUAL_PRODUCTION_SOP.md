## 1. 단계와 목표 시간 (제안)

목표 시간은 DLX(롱폼 10분 + 쇼츠 3편) 6시간 기준이다. 본인 채널(쇼츠 5편)은 7단계에 30분, 9단계에 10분을 더해 약 6시간 40분이다(`01_VALIDATION_PLAN.md` H1 기준 7시간 이하).

| # | 단계 | 도구 | 목표 시간 | 산출물 | 제품 기능 |
|---|---|---|---|---|---|
| 0 | 접수·주제 점검 | 체크리스트(2장) | 10분 | 주제 점수, 권리 동의, 템플릿 선택 | VD-F-130, VD-F-013 |
| 1 | 대본 | Claude | 40분 | 롱폼 대본(약 3,300자, 챕터 표시) | `video.script` |
| 2 | 스토리보드 시트 | Claude → 스프레드시트 | 40분 | 시트(장면 30~50행) | VD-F-131, VD-F-141 |
| 3 | 출처 확인 | 검색 + 시트 `sources` 열 | 40분 | 출처 채운 시트, 경고 목록 | VD-F-138 |
| 4 | 이미지 | 이미지 생성 도구 | 55분 | 장면 이미지(새로 약 30장 + 재사용) | VD-F-134 |
| 5 | 내레이션 | TTS 도구 | 20분 | 장면별 음성 파일(같은 목소리) | VD-F-134 |
| 6 | 편집·렌더(마스터 컷) | 편집 도구 또는 FFmpeg | 80분 | 16:9 1080p 롱폼, SRT | VD-F-136 |
| 7 | 쇼츠 추출 | Claude + 편집 도구 | 45분(3편, 편당 15분) | 9:16 쇼츠, 훅 문구 | VD-F-137 |

| | 합계 | | 6시간 | | |

STD(시트만)는 0~3단계 + 전달 10분 = 약 2시간 20분, PRM은 DLX + 쇼츠 2편 30분 + 언어판 60분 + 메타데이터 15분 + 점검 15분 = 약 8시간이다(`PRICE_PLAN.md` 11.6절 공식 검증에 쓴 값).

매 영상마다 11장 작업 기록표에 단계별 실제 시간을 적는다. 가장 오래 걸린 단계가 개발 1순위다.

## 2. 0단계: 접수·주제 점검

- [ ] 주제 점수 60점 이상(제안 배점: 채널 지난 성과와 비슷한 주제 40, 검색·관심도 30, 자료 구하기 쉬움 30. 레이더 VD-F-013의 수작업판)
- [ ] 형식과 길이: 롱폼 10분(기본) / 쇼츠 길이. 롱폼 장면 수는 분당 3~8, 합계 최대 240
- [ ] 템플릿: `history_documentary`(역사 다큐), `knowledge_explainer`(지식 해설), `list_topn`(TOP N), `story_radio`(사연 라디오), `product_review`(리뷰형 구성)
- [ ] (주문) 권리 확인 동의가 있다. 없으면 작업을 시작하지 않는다
- [ ] (주문) 고객이 보낸 사진·영상·녹음의 권리 근거를 기록했다(clip 장면은 권리 근거 없이 쓰지 않는다)
- [ ] 정치·종교·민족 감정처럼 해석이 크게 갈리는 주제면 "여러 견해" 장면을 넣기로 정했다

## 3. 스토리보드 시트 열 정의

한 영상 = 한 스프레드시트 파일, 탭 3개. 열 이름은 제품 테이블 열 이름과 같게 쓴다(나중에 CSV로 그대로 옮기기 위해).

장면 탭(`video.scenes`와 같은 열):

| 열 | 값 | 규칙 |
|---|---|---|
| `id`, `storyboard_id`, `org_id` | 시트에서는 비워 둔다 | 시스템이 채우는 열 |
| `ord` | 1부터 순서 | 끌어 옮기면 다시 매긴다 |
| `chapter` | 챕터 이름(없으면 빈칸) | 설명란 챕터 타임스탬프에 쓴다 |
| `kind` | `image` / `clip` / `text_card` / `title` | 엔드카드는 만들지 않는다(YouTube 끝화면 사용) |
| `duration_ms` | 장면 길이(밀리초) | 합계 = 목표 길이 ±10% |
| `narration` | 내레이션 문장 | 600자 이하 |
| `on_screen_text` | 화면 문구 | 160자 이하 |
| `visual_prompt` | 그림 설명(한국어) | 600자 이하. 실존 인물 얼굴 묘사 금지 |
| `motion_preset` | `zoom_in` / `zoom_out` / `pan_left` / `pan_right` / `static` | 같은 이미지를 다시 쓸 때는 모션을 바꾼다 |
| `music_cue` | 음악 큐(예: intro, build, calm, outro) 또는 빈칸 | |
| `shorts_candidate` | TRUE / FALSE | 쇼츠로 뽑을 장면. 연속 장면으로 묶일 수 있게 표시 |
| `sources` | `제목 | URL | 메모`를 줄바꿈으로 최대 5개 | 사실을 말하는 장면은 1개 이상 |
| `source_required` | TRUE / FALSE | 연도·인물·수치·인과 같은 사실 주장이면 TRUE |
| `revision` | 고친 횟수(0부터) | 수정 요청 분류에 쓴다 |

소재 탭(`video.scene_assets`와 같은 뜻): `ord`(장면), `kind`(`image` / `narration` / `clip`), `lang`(내레이션만, KO/JA/EN), `status`(`ready` / `superseded`, 다시 만들면 이전 것을 superseded로 남긴다), `storage_path`(파일 이름), `rights_basis`(clip과 외부 자료는 필수: 본인 촬영, 고객 제공(권리 동의), 공공누리 유형 등), `ai_generated`(TRUE/FALSE), `reused_from_asset_id`(다시 쓴 이미지면 원래 파일 이름).

컷 탭(`video.storyboard_cuts`와 같은 뜻): `ord`, `kind`(`master` / `short`), `aspect`(`16:9` / `9:16`), `scene_ids`(연속 장면의 `ord` 범위, 예: 12~15), `hook_text`(쇼츠만), `status`. 쇼츠 컷은 최대 10개.

## 4. 1단계: 대본 프롬프트

Claude 프로젝트를 영상마다 하나 만든다(다른 주문과 섞지 않는다).

```
{채널 이름} 채널의 {길이}분 롱폼 대본을 써 줘. 주제: {주제}. 템플릿: {템플릿 코드}.
시청자: {대상}. 톤: {톤, 예: 차분한 다큐 내레이션}.

구성(템플릿 비트, 제안): {아래 비트 표에서 고른 행}
분량: 한국어 약 {길이 x 330}자. 챕터마다 [챕터: 이름]으로 표시.

규칙:
- 연도, 인물, 수치, 원인과 결과를 말하는 문장 끝에 [출처 필요]를 붙인다.
- 확실하지 않은 내용은 단정하지 않고 "~라는 기록이 있다", "견해가 갈린다"로 쓴다.
- 지어낸 일화, 가상의 인용, 근거 없는 수치를 쓰지 않는다.
- "충격", "소름", "아무도 모르는" 같은 과장 표현, 조회수·구독 요청 문구 반복을 쓰지 않는다.
```

템플릿 비트(제안, 정본은 01장 10장 `storyboard_templates` seed):

| 템플릿 | 비트 |
|---|---|
| `history_documentary` | 오프닝 질문 → 시대 배경 → 사건 전개 1·2·3 → 전환점 → 결과와 영향 → 오늘과의 연결 → 마무리 질문 |
| `knowledge_explainer` | 질문 → 한 줄 답 → 설명 3단계 → 흔한 오해 바로잡기 → 정리 |
| `list_topn` | 기준 소개 → N위부터 1위까지(항목마다 근거 1개) → 정리 |

## 5. 2단계: 스토리보드 시트 프롬프트

```
위 대본으로 스토리보드를 만들어 줘. 형식: 롱폼 {길이}분, 16:9. 장면 수: {길이 x 4}개 안팎(분당 3~8).
아래 열 순서로 CSV를 출력한다(첫 줄 머리글, 쉼표가 들어간 칸은 큰따옴표로).

ord,chapter,kind,duration_ms,narration,on_screen_text,visual_prompt,motion_preset,music_cue,shorts_candidate,sources,source_required

규칙:
- kind: image | clip | text_card | title. 챕터 시작은 title, 연도·숫자·인용은 text_card를 쓴다.
- duration_ms 합계는 {길이 x 60000}의 ±10%. 내레이션 길이(한국어 초당 약 5.5자)와 맞춘다.
- narration 600자, on_screen_text 160자, visual_prompt 600자 이하.
- motion_preset: zoom_in | zoom_out | pan_left | pan_right | static.
- 같은 장소·사물이 다시 나오면 visual_prompt를 "재사용: ord {번호}"로 쓴다.
- 대본의 [출처 필요] 문장이 들어간 장면은 source_required=TRUE, sources는 비워 둔다(다음 단계에서 사람이 채운다).
- 쇼츠로 따로 봐도 이해되는 연속 장면 묶음 5개를 골라 shorts_candidate=TRUE.
- visual_prompt에 실존 인물의 얼굴·외모 묘사를 쓰지 않는다. 인물은 실루엣, 뒷모습, 손, 옷, 소품으로.
```

CSV를 시트 장면 탭에 붙여 넣고, 길이 합계 칸(`=SUM(duration_ms)/60000`)으로 ±10% 안인지 확인한다.

## 6. 3단계: 출처 확인

| 순서 | 방법 |
|---|---|
| 1 | `source_required=TRUE` 행만 거른다 |
| 2 | 공공 데이터베이스·기관 자료·문헌에서 찾는다. 예: 국사편찬위원회 한국사데이터베이스, 조선왕조실록(국사편찬위원회), 한국민족문화대백과사전. 블로그·커뮤니티 글은 출처로 쓰지 않는다 |
| 3 | `sources`에 `제목 | URL | 메모(쪽수·연도·확인한 문장)`로 적는다. 장면당 최대 5개 |
| 4 | 출처와 다르면 내레이션·화면 문구를 고친다. 출처를 못 찾으면 문장을 지우거나 "~라는 이야기가 전한다"처럼 바꾸고, 그래도 남기면 경고 목록에 올린다 |
| 5 | 경고 목록(출처 없는 사실 장면)을 주문 고객에게 시트와 함께 보낸다. 본인 채널은 업로드 전에 0개로 만든다 |

AI로 출처를 찾게 할 때는 아래 프롬프트를 쓰되, 결과의 URL은 사람이 직접 열어 확인하기 전에는 시트에 넣지 않는다(AI가 만든 URL을 그대로 쓰지 않는다).

```
아래 문장들의 사실 여부를 확인할 수 있는 1차 자료나 공공 기관 자료의 이름을 알려 줘.
모르면 "모름"이라고 답하고, URL을 지어내지 마.
{source_required=TRUE 행의 narration 목록}
```

제품에서는 출처 점검 LLM(1크레딧)과 경고 수 표시(VD-F-138)가 이 단계를 돕는다. 영상마다 "출처 확인에 걸린 시간"과 "AI가 낸 출처 중 틀린 수"를 작업 기록표에 적으면 그 기능의 우선순위 근거가 된다.

## 7. 4~5단계: 이미지와 내레이션

이미지 프롬프트 만들기:

```
아래 장면 그림 설명을 영어 이미지 프롬프트로 바꿔 줘. 장면마다 한 줄, ord를 앞에 붙인다.
"재사용"이라고 적힌 장면은 건너뛴다.
끝에 스타일 접미어와 금지 접미어를 그대로 붙인다.

스타일 접미어: {채널 고정 스타일, 예: muted documentary illustration, ink and watercolor, Joseon era setting}
금지 접미어: no text, no letters, no watermark, no logo, no real person likeness, no celebrity, no specific artist style

{장면별 visual_prompt 목록}
```

| 규칙 | 내용 |
|---|---|
| 스타일 고정 | 한 영상(롱폼 + 쇼츠) 안에서 도구·모델·스타일 접미어·seed를 바꾸지 않는다 |
| 해상도 | 약 1MP(예: 1344x768)로 만들고 편집 단계에서 1080p로 확대한다(`PRICE_PLAN.md` SF-P-5). 확대 화질이 거슬린 장면 수를 기록한다 |
| 재사용 | 같은 장소·사물은 다시 만들지 않고 이전 이미지를 쓰고 모션만 바꾼다. 소재 탭 `reused_from_asset_id`에 기록 |
| 모델 비교(검증 1주차) | 같은 장면 10개를 두 모델(고품질 Flux 3급, 저가 오픈소스급)로 만들어 나란히 놓고 고른 쪽을 기록(D-31, SF-P-2) |
| 글자 | 이미지 안에 글자를 만들지 않는다. 글자는 편집 단계에서 넣는다 |
| 인물 | 실존 인물(역사 인물 포함) 얼굴을 AI로 만들지 않는다. 초상화·사진은 이용 조건을 확인한 자료만 `clip` 또는 업로드 이미지로 쓰고 `rights_basis` 기록 |
| 기록 | 장면별 도구·모델·seed·프롬프트를 소재 탭에 남긴다 |

내레이션:

| 규칙 | 내용 |
|---|---|
| 같은 목소리 | 한 영상(롱폼 + 쇼츠, 언어별)에 TTS 도구·보이스·속도 설정 하나만 쓴다. 장면 하나를 다시 만들 때도 같은 설정 |
| 장면 단위 | 장면마다 파일 하나(`<ord>_<lang>.mp3`). 고친 장면만 다시 만들고 이전 파일은 superseded로 남긴다 |
| 고객 목소리 | 고객이 보낸 녹음만 쓴다. 목소리 복제는 하지 않는다 |
| 라이선스 | TTS 도구의 상업 이용 조건을 확인하고 도구·플랜을 기록 |
| 글자 수 | 언어별 내레이션 글자 수를 기록한다(`PRICE_PLAN.md` SF-P-1 롱폼 TTS 과금 근거) |

## 8. 6단계: 편집·렌더(마스터 컷)

| 항목 | 값 |
|---|---|
| 규격 | 롱폼 16:9 1920x1080, 쇼츠 9:16 1080x1920. 30fps, H.264, AAC 48kHz |
| 화면 이동 | 시트 `motion_preset`대로(FFmpeg는 `zoompan` 필터로 zoom_in·zoom_out·pan을 만들 수 있다). 제품은 FFmpeg 하나로 렌더하므로(SF-2), 편집 도구를 쓰더라도 FFmpeg로 재현할 수 없는 효과(복잡한 모션 그래픽, 3D 전환)는 쓰지 않는다 |
| 글자 카드 | `text_card`·`title`은 단색 또는 흐린 배경 + 화면 문구. 노출 시간은 1.2초 + 글자당 0.06초 이상(제안, `book-trailer/03_MANUAL_PRODUCTION_SOP.md` 8장과 같은 기준) |
| 자막 | 내레이션으로 SRT를 만들고 원문과 대조해 고친다. 자막 레이어 규칙은 VD-F-033 |
| 음악 | 상업 이용 라이선스를 확인한 곡. 곡명·출처·라이선스 링크 기록. 내레이션 구간은 음악을 약 12dB 낮춘다 |
| 소리 크기 | 약 -14 LUFS(제안) |
| AI 표시 | 영상 첫 장면 또는 끝 3초에 "AI 생성 이미지·음성 포함" 작은 글자(제안), 설명란에도 같은 문장 |
| 파일 | `<주제>_master_16x9_v<번호>.mp4`, `<주제>_KO.srt` |

편집 도구는 무료 편집기나 FFmpeg 스크립트를 쓴다. 같은 템플릿으로 2편 이상 만들면 그 구성을 프로젝트 템플릿으로 저장하고 재사용 횟수를 기록한다. 이것이 제품 템플릿 5종의 비트 근거가 된다.

## 9. 7단계: 쇼츠 추출

```

```

## 10. 8~9단계: 점검, 업로드·납품

납품·업로드 전 점검표:

- [ ] 장면 길이 합계가 목표 ±10% 안, 쇼츠는 60초 이하(또는 고른 길이)
- [ ] 출처 없는 사실 장면 0개(주문은 경고 목록을 고객에게 전달했음)
- [ ] 출처와 다른 내용 없음, 해석이 갈리는 내용은 "견해가 갈린다"로 표시
- [ ] 실존 인물 얼굴 AI 생성 없음, 다른 채널·방송 화면 없음, 외부 자료는 `rights_basis` 기록
- [ ] 모든 장면이 같은 목소리, 같은 이미지 스타일
- [ ] 근거 없는 수치·과장 표현·보장 표현 없음
- [ ] AI 표시(영상 + 설명란)
- [ ] 음악·서체·TTS·이미지 도구 라이선스 기록

설명란 메타데이터 프롬프트:

```
아래 롱폼과 쇼츠의 YouTube 게시 문구를 만들어 줘.
롱폼: 제목(50자 이하), 설명 3줄, 챕터 타임스탬프(시트 chapter와 장면 시작 시각으로), 해시태그 3개.
쇼츠: 편마다 제목(40자 이하), 설명 1줄, 해시태그 3개.
설명란 끝에 "참고 자료" 목록(시트 sources의 제목과 URL, 중복 제거)과 "이 영상은 AI 생성 이미지·음성을 포함합니다"를 넣는다.
과장 표현, 근거 없는 수치, 구독·좋아요 요청 반복을 쓰지 않는다.
{시트 장면 탭 CSV}
```

| 항목 | 내용 |
|---|---|
| 본인 채널 업로드 | 롱폼 먼저, 쇼츠는 이틀에 1편. 쇼츠마다 관련 동영상으로 롱폼 연결. AI로 만든 사실적인 재현 장면이 있으면 YouTube "변경되거나 합성된 콘텐츠" 항목을 확인. 제휴 링크가 있으면 대가성 문구를 설명란 첫 줄에 넣고 "참고 자료"는 그 뒤에 |
| 주문 납품 | 영상(롱폼, 쇼츠), SRT, 스토리보드 시트(xlsx와 CSV), 설명란 문구(txt), 경고 목록 |
| 인터뷰 요청 | 납품 메시지에 15분 인터뷰 요청(`04_INTAKE_AND_INTERVIEW.md` 3장)과 평가셋 사용 동의 질문을 함께 보낸다 |
