# 02 서비스 카탈로그: 상품 등급, 기술, 제작기간

작성일 2026-10-14. 제작기간은 숙련 개발자가 AI 에이전트를 쓰는 경우의 추정치(제안)이며, 첫 납품 5건의 실측으로 고친다.

## 1. 개발 범위 구분: 어디서부터 "개발"인가

기준은 **백엔드(DB·로그인·비즈니스 로직)가 있느냐**다.

```
[정적 사이트]          [정적 + 연동]            [웹앱]
Next.js 정적 생성  →  폼·자동화·리드 저장  →  DB·로그인·권한·결제·관리자 화면
(프론트 개발)          (경량 개발·자동화)        (본격 개발)
 T1~T5                 리드 옵션 L0~L2           T6~T7, 리드 옵션 L3
```

| 제작 방식 | 기술 | 시장 단가 | 특징 | 에이전시 사용 |
|---|---|---|---|---|
| 빌더형 | 아임웹, 카페24, 워드프레스 | 저가~중가 | 고객이 직접 수정 가능, 디자인·모션 한계 | 고객이 직접 관리를 원할 때만 |
| 정적 HTML | HTML/CSS/JS | 저가~중가 | 가볍지만 유지보수·확장 불편 | 쓰지 않음 |
| 프레임워크형 | Next.js(정적 생성) + Vercel | 중가~고가 | 모션·SEO·확장성 우수 | **기본 방식** |

## 2. 모션 레벨 (상품 등급의 기술 기준)

| 레벨 | 기술 | 예시 | 난이도 |
|---|---|---|---|
| Lv1 모션 | Motion(Framer Motion), CSS 애니메이션 | 텍스트 등장, 패럴랙스 | 낮음 |
| Lv2 스크롤 연출 | GSAP + ScrollTrigger, Lenis | 스크롤에 따라 장면이 전환되는 스토리텔링 | 중간 |
| Lv3 3D·WebGL | React Three Fiber, Spline | 3D 제품 회전, 마우스 반응 오브젝트 | 높음 |
| Lv4 셰이더 | 커스텀 GLSL 셰이더, 파티클 | 유체·노이즈 배경, 몰입형 브랜드 사이트 | 매우 높음 |

품질 기준: Lv3 이상은 `design-module/_design-guide/HERO_3D.md`의 기기별 구성(1장), 저사양 판정(1.1절), 성능 예산(2장: 3D 번들 PC 1MB·모바일 300KB 이하, LCP 2.5초 이하)을 그대로 적용한다. `prefers-reduced-motion`과 저사양 기기는 정지 이미지로 대체한다.

## 3. 상품 등급과 제작기간

| 등급 | 상품 | 개발도구 | 실작업 | 납기(고객 일정 포함) |
|---|---|---|---|---|
| T1 | 네이버 블로그 스킨 | Figma, 구글 Stitch, 이미지 생성 AI | 4~8시간 | 2~4일 |
| T2 | 템플릿 랜딩 | Next.js 템플릿 + shadcn/ui 또는 아임웹 | 8~16시간 | 4~7일 |
| HR | 히어로 섹션 단품 | GSAP 또는 R3F/Spline, 기존 사이트에 삽입 | 8~24시간 | 3~7일 |
| T3 | 모션 랜딩(Lv1~2) | Next.js + Motion + GSAP/ScrollTrigger + Lenis | 20~40시간 | 1~2주 |
| T4 | 인터랙티브 브랜드 사이트(Lv2~3) | 위 + React Three Fiber 또는 Spline, 5~7페이지 | 40~100시간 | 2~4주 |
| T5 | 몰입형 프리미엄(Lv4) | 위 + 커스텀 GLSL, 3D 에셋 최적화 | 100~200시간 | 4~8주 |
| L0~L2 | 리드 수집 옵션 | Make/n8n, Supabase, Resend | 2~16시간 | +2~5일 |
| T6 | 웹앱 MVP | Next.js + Supabase + 인증·결제 | 120~300시간 | 4~8주 |
| T7 | 모바일 앱 MVP | Flutter 또는 React Native | 200~400시간 | 6~12주(스토어 심사 포함) |

납기를 늘리는 것은 코딩보다 **고객 자료 수급과 시안 확인 대기**다. AI는 코딩 시간을 줄이지만 대기 시간은 줄이지 못하므로, 계약서에 "자료 지연 시 납기 자동 연장"을 넣는다(`04_OPERATIONS.md` 2장).

## 4. AI 에이전트 배치

모델 등급 기준은 `products/_platform-core/DOC_TEMPLATE.md` 1장과 같다(가장 낮은 등급을 쓰되 실수 비용이 큰 작업은 상위 모델).

| 역할 | 모델 | 에이전시 업무 |
|---|---|---|
| 고문 | Fable 5.1 | 견적·아키텍처 검토, 고난도 셰이더·3D 성능 문제, 리드 DB RLS·결제 |
| 주에이전트 | Opus 5.5 | Claude Code로 메인 개발, 히어로 섹션 구현, 외부 API 연동 |
| 대리 | Sonnet 5.5 | 섹션 컴포넌트 양산, 카피라이팅, 반응형, 블로그 스킨 시안 문구 |
| 사원 | Haiku 5.5 | 메타태그·alt 텍스트, QA 체크리스트 반복, 단순 수정 요청 처리 |

## 6. 설득형 랜딩 패키지 (2026-10-17, 제안)

설득형 랜딩 공용 규칙의 "문제 → 원인 → 근거 → 해결 → 왜 우리인가 → 비용 비교" 설득 구조를 B2B 고객용 상품으로 만든다. 제작 규칙은 `design-module/_design-guide/LANDING_PERSUASION.md`(아래 LP)를 그대로 쓴다. 가격은 `PRICE_PLAN.md` 11장.

| 항목 | 내용 |
|---|---|
| 대상 | 설명이 필요한 B2B SaaS, 설치형 소프트웨어, 전문 서비스(세무·노무·설계 등). 고객이 "왜 다른 방법이 아니라 이것인가"를 묻는 업종 |
| 차별점 | 예쁜 랜딩이 아니라 검증 가능한 주장만 싣는 랜딩. 판정표(LP 3.2절), 증거 등급(LP 3.3절), 주장 장부(LP 3.4절)를 납품물에 포함 |
| 하지 않는 것 | 레퍼런스 사이트 문구·통계·연출 복제, 고객이 근거를 주지 않은 수치·후기, 경쟁사 실명 비교(고객 법무 확인 전) |
| 기술 | T3 모션 랜딩 기반(Next.js 정적 생성 + Motion). 연출 순간은 히어로 하나, 추가 섹션은 정지(LP 2장) |

| 등급 | 납품물 | 실작업(추정) | 납기 |
|---|---|---|---|
| PL-L 라이트 | 설득형 메인 1장(7칸: 히어로, 막히는 지점과 원인, 방식, 왜 우리인가 판정표, 비용 비교 안내, 요금, 행동), 주장 장부, V0 인터뷰 질문지 | 30~50시간 | 2~3주 |
| PL-S 스탠다드 | 라이트 + 비교 계산기 1개(LP 6장) + 인사이트 글 1편 + 증거 파일 게시 구조 | 50~80시간 | 3~4주 |
| PL-P 프리미엄 | 스탠다드 + 인사이트 3편 시리즈 + "왜 우리인가" 칸 유무 교대 실험 2주 운영과 결과 리포트 | 80~120시간 | 5~7주 |

제작 절차(고객 자료 대기 시간이 납기를 정한다, 3장):

| 순서 | 할 일 | 고객이 줄 것 |
|---|---|---|
| 1 | 대안 지도와 판정 기준 초안, V0 인터뷰 질문지 | 고객 3~5명 연락처(인터뷰는 고객이 직접 해도 된다) |
| 2 | 주장 장부: 고객이 하고 싶은 말을 모두 적고 증거가 있는 것만 "검증" | 증거 자료(샘플 결과물, 화면, 측정 기록) |
| 3 | 판정표와 비교 1쌍 카피 | 판정표 검토(우리 열 약점 1개 이상 합의) |
| 4 | 디자인·구현(T3 기준) | 브랜드 자료 |
| 5 | 게시 전 LP 7장 점검표 | 최종 승인 |

린 검증: 이 상품은 먼저 자사 제품 3개(flora-publishing, nomad-docs, arch-studio)의 랜딩에 같은 구조를 적용해 포트폴리오로 만들고, 포트폴리오 게시 뒤 4주 동안 문의 수를 본다. 문의가 3건 미만이면(제안) 상품으로 따로 팔지 않고 AG-ML·AG-BR의 선택 옵션으로만 둔다.
