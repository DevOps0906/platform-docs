# 03 호스팅과 데이터(리드) 저장

확인일 2026-10-14. 외부 가격과 출처는 `../_common/COST_BASELINE.md`에 모았다.

## 1. 호스팅 방식 비교

| 방식 | 비용 | 장점 | 단점 | 적합 고객 |
|---|---|---|---|---|
| 아임웹 | Starter 1개월 결제 월 2만원, 12개월 결제 월 16,000원 | 고객이 직접 수정, 쇼핑몰 기능 | 모션·커스텀 한계 | 직접 관리하려는 소상공인 |
| 워드프레스 | 웹호스팅 + 테마·플러그인 | 블로그·게시판 강함, 생태계 큼 | 플러그인 보안 업데이트 부담 | 콘텐츠가 많은 기업 |
| 자체 웹호스팅(VPS) | 서버 월 이용료 | 완전한 통제 | 서버 관리·보안·장애 대응을 직접 해야 함 | 쓰지 않음(1인 운영에 부담) |
| Vercel | Hobby 무료(비상업만), Pro 좌석당 월 $20 + 사용량 | Next.js 최적화, 미리보기 배포 | 사용량 초과 과금 | **모션 사이트 기본** |
| Netlify | Pro 월 $19 | Vercel과 유사, 폼 기능 내장 | Next.js 최적화는 Vercel보다 약함 | 정적 사이트 대안 |
| Cloudflare Pages | 무료부터 | 무료 티어에 개인용 제한 없음 | Next.js 일부 기능 제약 | 트래픽 큰 정적 랜딩 원가 절감 |

## 2. 운영 규칙

| 규칙 | 내용 |
|---|---|
| 무료 플랜 금지 | Vercel Hobby는 상업 이용 금지. 고객 사이트를 Hobby에 올리지 않는다 |
| 에이전시 팀 1개 | 에이전시 명의 Vercel Pro 팀 1개에 고객 사이트를 모은다. 배포 좌석 1개면 월 $20 수준(트래픽 큰 사이트는 사용량 과금, 지출 한도 설정) |
| 비용 회수 | 호스팅·도메인·SSL은 유지보수 구독에 포함해 받는다(`PRICE_PLAN.md` 7장) |
| 이전 보장 | 유지보수 해지 시 소스코드·도메인 이전을 지원한다고 계약서에 명시(종속 불안 제거) |
| 상담 분기 | "직접 글을 고치고 싶다" → 아임웹. "모션이 핵심" → Next.js + Vercel. 상담 첫 단계에서 정한다 |

## 3. DB가 들어가면 비싸지는 이유

DB 자체보다 **DB와 함께 따라오는 것들** 때문에 비싸진다.

| 구성 요소 | 공수 | 가격 영향 |
|---|---|---|
| 테이블 1개에 데이터 저장(리드 저장) | 매우 작음 | 거의 없음 |
| 로그인·회원가입 | 중간 | 큼 |
| 권한 관리(누가 무엇을 보나, RLS) | 중간 | 큼 |
| 관리자 화면(조회·수정·삭제·검색·엑셀 다운로드) | 큼 | 가장 큼 |
| 비즈니스 로직(예약, 결제, 상태 변경) | 큼 | 큼 |
| 개인정보 보호 책임, 백업, 장애 대응 | 지속 | 유지보수비 상승 |

견적서에서 "문의를 DB에 저장"(리드 옵션)과 "고객이 로그인해 문의를 관리하는 화면"(T6 웹앱)을 반드시 분리한다.

## 4. 리드 저장: 구글시트 vs Supabase

| 항목 | 구글시트 | Supabase |
|---|---|---|
| 구현 | 폼 → Make/n8n 또는 Apps Script → 시트 | Next.js Server Action → Supabase 테이블 + 알림 메일 |
| 구현 시간 | 1~2시간 | 2~4시간(테이블, RLS, 알림 포함) |
| 기술 | 노코드 자동화 | 경량 개발(보유 스택) |
| 비용 | 사실상 무료(자동화 도구 사용량만) | Free는 7일 활동 없으면 일시정지되어 고객용으로 위험. Pro 조직당 월 $25 |
| 고객 사용성 | 매우 좋음(익숙한 표) | 관리자 화면이 없으면 고객이 못 봄 |
| 보안 | 링크 공유 실수 시 개인정보 유출 위험 | RLS로 행 단위 통제 |
| 확장 | 수천 건 수준, API 호출 한도 | 대량 데이터, 리드 점수화, AI 분석 |
| SaaS 전환 | 불가 | 가능 |

결론: 기술·기간 차이는 작고(반나절 이내), 운영 가치 차이는 크다.

### 4.1 권장 구조: 멀티테넌트 리드 DB 1개 + 시트 동기화

고객마다 Supabase 프로젝트를 만들지 않는다. 프로젝트 1개에 `leads` 테이블을 두고 `client_id`로 구분한다. 고객이 50명이어도 원가는 월 $25~35 수준이다.

| 항목 | 설계(제안) |
|---|---|
| 테이블 | `clients`(에이전시 고객), `leads`(`client_id`, 이름, 연락처, 문의 내용, 유입 UTM, 동의 시각, 상태) |
| 보안 | RLS로 고객별 분리. 폼 입력은 서버(Server Action)에서만 쓰기, 공개 anon 쓰기 금지 |
| 고객 보기 | n8n이 고객별 구글시트로 동기화. 고객은 시트로 확인 |
| 알림 | 신규 리드 → 이메일(Resend) 또는 카카오 알림 |
| 보존 | 동의 문구에 적은 보존 기간 이후 자동 삭제(기간은 열린 결정) |
| 확장 | 리드 대시보드를 붙이면 퍼널·CRM SaaS의 초기 버전이 된다(장기 제품화) |

### 4.2 리드 옵션 레벨

| 레벨 | 구현 | 개발 여부 | 대상 |
|---|---|---|---|
| L0 기본 | Tally·구글폼 삽입 → Make/n8n → 시트 + 이메일 알림 | 노코드 자동화 | 저가 상품(T1~T2) |
| L1 자체 폼 | Next.js 폼 + Supabase(멀티테넌트) + 시트 동기화 + 알림 | 경량 개발 | 중가 상품(T3~T4) |
| L2 퍼널 | UTM 추적, 단계별 폼, 리드 점수화, 자동 응답 메일 시퀀스 | 개발 + 자동화 | 광고를 돌리는 고객 |
| L3 CRM | 관리자 대시보드, AI 챗봇 상담·분류, 영업 파이프라인 | 본격 개발(웹앱) | 별도 견적 또는 SaaS 구독 |

가격은 `PRICE_PLAN.md` 7.2절.
