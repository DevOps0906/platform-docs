# 04 운영: 계약·견적·범위·결제·납품

작성일 2026-10-14. 에이전시 운영 경험이 없다는 약점을 템플릿과 규칙으로 메우는 문서다. 계약서 문구는 법무 검토 전 초안(미확인)이다.

## 1. 초보 에이전시가 망하는 지점과 대응

| 리스크 | 대응 |
|---|---|
| 무한 수정 | 등급별 수정 횟수 명시(1/2/3회), 초과 시 회당 추가 요금(`PRICE_PLAN.md` 7.3절) |
| 범위 확장 | 요구사항 정의서에 "포함 / 불포함" 목록을 명시하고 서명받는다 |
| 수금 실패 | 착수금 50% → 잔금 50%. 300만원 이상은 30% / 40%(시안 확정) / 30%(납품) |
| 소스 소유권 분쟁 | 잔금 완납 시 결과물 저작권·소스 고객 귀속. 오픈소스·유료 에셋 라이선스는 별도 고지 |
| 납기 지연 책임 | "고객 자료 수급·시안 확인 지연 시 그 기간만큼 납기 자동 연장" |
| 납품 후 연락 두절 이미지 | 무상 하자보수 1개월 → 유지보수 구독으로 전환 제안 |
| 종속 불안 | 유지보수 해지 시 소스코드·도메인 이전 지원 |

## 2. 계약서에 넣을 조항 (체크리스트)

| 조항 | 내용 |
|---|---|
| 작업 범위 | 요구사항 정의서 첨부, 포함·불포함 목록 |
| 수정 | 횟수, 수정의 정의(범위 내 변경)와 신규 요청의 구분 |
| 일정 | 단계별 일정, 자료 지연 시 자동 연장 |
| 대금 | 지급 비율, 지급 시점, VAT 별도 |
| 저작권 | 잔금 완납 시 귀속, 포트폴리오 게시 허용 여부 |
| 하자보수 | 무상 1개월, 범위(버그 수정만) |
| 유지보수 | 별도 계약, 해지 시 이전 지원 |
| 개인정보 | 리드 수집 시 처리 위탁 관계, 보존 기간, 파기 |
| 해지·환불 | 착수 전 전액, 시안 전 착수금 제외, 시안 확정 후 환불 불가 |

## 3. 납품 워크플로우

```
상담 신청(폼) → AI가 요구사항 정의서 초안 생성 → 견적서 자동 산출 → 전자계약 + 착수금
→ 레퍼런스·브리프 확정 → 시안(히어로 먼저) → 개발(보일러플레이트) → 검수(QA 체크리스트)
→ 배포(Vercel) → 잔금 → 하자보수 1개월 → 유지보수·운영 구독 제안
```

| 단계 | 도구(제안) | 담당 모델 |
|---|---|---|
| 상담 신청 | Tally 또는 자체 L1 폼 → Supabase `leads`(자기 자신도 고객 1번) | - |
| 요구사항 정의서·견적서·계약서 | nomad-docs(`products/nomad-docs/`)로 생성해 제품 실사용 검증 | Sonnet 5.5, 검토 Fable 5.1 |
| 디자인 브리프 | `products/_design-guide/DESIGN_PRINCIPLES.md` 절차(레퍼런스 → 브리프 → 토큰 → 기본값 회피 검토) | Sonnet 5.5 |
| 개발 | 모션 랜딩 보일러플레이트 + Claude Code | Opus 5.5 |
| 검수 | QA 체크리스트(아래 4장) | Haiku 5.5 |
| 배포 | Vercel Pro 팀 | - |

## 4. 납품 전 QA 체크리스트

| 항목 | 기준 |
|---|---|
| 성능 | LCP 2.5초 이하, 3D 번들 PC 1MB·모바일 300KB 이하(`products/_design-guide/HERO_3D.md` 2장) |
| 대체 화면 | `prefers-reduced-motion`, WebGL 미지원, 저사양에서 정지 이미지 표시 |
| 반응형 | 375px, 768px, 1280px, 1920px 확인 |
| SEO | title·description·OG 이미지, sitemap, robots, 네이버 서치어드바이저 등록 |
| 폼 | 필수값 검증, 동의 체크박스, 제출 후 알림 도착 |
| 접근성 | 대비, 키보드 이동, 이미지 alt |
| 분석 | 방문·문의 전환 측정 설정 |

## 5. 개인정보·법적 필수 사항 (리드 수집 시)

| 항목 | 내용 |
|---|---|
| 동의 | 수집 항목, 목적, 보존 기간을 적은 동의 체크박스(미체크 시 제출 불가) |
| 처리방침 | 개인정보처리방침 페이지 링크 |
| 위탁 | 에이전시가 리드를 저장·관리하면 고객(사업자)의 처리 위탁을 받는 관계. 계약서에 명시 |
| 알림톡 | 카카오 알림톡은 비즈니스 채널 등록과 템플릿 승인이 필요(미확인: 현행 절차) |
| 파기 | 보존 기간 경과 시 자동 삭제 작업 |

법무 검토 전 초안이다. 표준 문구는 nomad-docs의 계약서 법무 검토(D-3) 결과를 따른다.

## 6. 자동화

| 단계 | 자동화 | 도구 |
|---|---|---|
| 리드 수집 | 문의 → CRM 자동 등록 | Make / n8n → Notion 또는 Supabase |
| 견적 | 요구사항 → AI 견적 초안 | Claude API |
| 블로그 스킨 시안 | 업종 프롬프트 → 시안 3종 | Stitch / Figma 템플릿 / 장기적으로 자체 생성기 |
| 웹 개발 | 업종 보일러플레이트 + Claude Code | Next.js + Supabase |
| 유지보수 리포트 | 월간 리포트 자동 발송 | Vercel Analytics + n8n |
| 멀티에이전트 | 견적 → 기획 → 개발 → QA 에이전트 파이프라인 | 멀티에이전트 베이스 레포 |

## 7. 설득형 랜딩 패키지 계약 조항 (2026-10-17, 2장 체크리스트 추가분)

AG-PL(`PRICE_PLAN.md` 11장)을 팔 때 2장 체크리스트에 더하는 조항이다. 2장 표의 줄 번호를 바꾸지 않도록 여기에 둔다.

| 조항 | 내용 |
|---|---|
| 수치·후기 근거 | 랜딩에 싣는 수치·후기·비교는 고객이 준 근거 자료가 있는 것만 싣는다. 근거가 없는 문구 요청은 거절할 수 있고 그것은 하자가 아니다 |
| 비교 표시 책임 | 경쟁사 실명 비교는 고객이 법무 확인을 마친 경우에만 싣고, 그 책임은 고객에게 있다 |
| 레퍼런스 사용 범위 | 고객이 준 레퍼런스 사이트는 구조만 참고하고 문구·이미지·고유 연출은 복제하지 않는다 |
| 인터뷰·실험 데이터 | V0 인터뷰와 교대 실험 기록은 개인 식별 정보 없이 납품한다 |
| 실험 기간 | 프리미엄의 교대 실험 2주는 방문 수가 부족해도 연장 의무가 없고, 연장은 운영 구독(AG-OP-G)으로 한다 |
