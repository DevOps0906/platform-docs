# 03 수동 제작 절차(SOP)와 프롬프트

작성일 2026-10-16. 상태: 초안. 개발 전 대행 주문을 사람 + 범용 AI 도구로 처리하는 절차다. 단계·규칙·형식은 제품 기획과 같게 맞췄다(분석 → 브리프 3안 → 원고 대조 → 스토리보드 → 이미지 → 내레이션 → 편집 → 점검 → 납품). 그래서 이 절차에서 나온 결과물이 그대로 제품 그래프의 평가셋이 되고, 단계별 작업 시간이 개발 우선순위의 근거가 된다.

## 2. 0단계: 접수 점검

- [ ] 권리 확인 동의(크몽 요청사항 5번)가 있다. 없으면 작업을 시작하지 않는다
- [ ] 원고 파일이 열리고 텍스트가 나온다(스캔 PDF면 고객에게 텍스트 파일 요청)
- [ ] 표지 이미지 600x900px 이상
- [ ] 스포일러 수준(없음 / 맛보기 / 설정까지)과 공개 범위(출간 전 원고)
- [ ] 실적 문구 요청이 있으면 근거 자료가 같이 왔다
- [ ] 작가 사진·직접 고른 음악이 있으면 사용 권리 확인
- [ ] 원고 파일 보관 위치와 삭제 예정일(납품 후 30일)을 작업 기록표에 적음

## 3. 1단계: 원고 분석 프롬프트

Claude 프로젝트를 주문마다 하나 만들고 원고 파일을 첨부한다(다른 주문과 섞지 않는다).

```
첨부한 원고는 책 「{제목}」({저자}, 장르: {장르})이다. 북트레일러 기획을 위해 분석해 줘.

출력 형식:
1. 장 목록: 장 번호, 장 제목(없으면 첫 문장 요약), 3문장 요약
2. 주요 인물(최대 6명): 이름, 역할, 욕망, 외형 묘사(원고에 나온 것만, 없으면 "묘사 없음")
3. 주제 3개, 분위기 키워드 5개
4. 결말·반전 구간: 장 번호와 이유(이 구간은 이후 인용과 장면에서 뺀다)
5. 독자 대상 한 줄
6. 원고에 나오는 실적·수상·판매 관련 사실(있으면 원문 그대로, 없으면 "없음")

규칙: 원고에 없는 내용을 지어내지 않는다. 추측이면 "추측"이라고 표시한다.
```

## 4. 2단계: 브리프 3안 프롬프트

```
위 분석을 바탕으로 북트레일러 브리프 3안을 만들어 줘. 3안은 서로 다른 각도여야 한다
(character 인물 / question 질문 / atmosphere 분위기 / problem 문제 / insight 통찰 중 3개).

각 안은 아래 JSON 형식 하나로 출력한다.
{
  "angle": "...",
  "logline": "60자 이하",
  "hooks": [{ "text": "40자 이하, 첫 2초에 화면에 뜰 문장" }],
  "quotes": [{ "text": "원고 문장을 글자 하나 바꾸지 않고 그대로, 80자 이하", "chapter": 장 번호, "verified": false }],
  "audience": "100자 이하",
  "mood": "cinematic_tension | calm_piano | upbeat_focus | ambient_soft | playful_light",
  "keywords": ["..."],
  "spoiler_notes": ["어떤 구간을 뺐는지"],
  "claims": [{ "text": "실적 문구", "evidence": null }]
}

규칙:
- quotes는 원고에 실제로 있는 문장만, 띄어쓰기와 문장부호까지 그대로. 3안 인용 합계는 안마다 300자 이하.
- 결말·반전 구간(분석 4번)과 스포일러 수준 "{스포일러 수준}"을 넘는 내용은 쓰지 않는다.
- "베스트셀러", "○만 부", "수상", "반드시", "보장", 의료·투자 효능 단정, 독자 후기·별점, 정가 대비 할인율 표현은 쓰지 않는다.
  고객이 준 근거가 있는 실적만 claims에 넣고 evidence에 근거를 적는다.
- 실존 인물 이름을 장면 묘사에 쓰지 않는다.
```

고객 전달용 기획안은 JSON을 그대로 보내지 않고 3안을 표로 바꿔 보낸다(로그라인, 첫 문장 훅, 인용 1~2개, 분위기). 고객이 고른 안의 번호를 작업 기록표에 적는다.

## 5. 3단계: 인용 대조

| 순서 | 방법 |
|---|---|
| 1 | 원고 파일(가능하면 TXT로 변환한 것)에서 인용 문장을 찾기(Ctrl+F)로 검색한다. 앞 15자로 찾고 전체를 눈으로 대조 |
| 2 | 띄어쓰기·문장부호·따옴표까지 같으면 `verified: true`, 장 번호를 확인 |
| 3 | 다르면 원고 문장으로 고치고 다시 대조. 원고에 없으면 지운다(AI가 만든 문장을 "책 속 문장"으로 쓰지 않는다) |
| 4 | 인용 1개 80자, 합계 300자 이하인지 센다 |
| 5 | 결말 구간 장에서 나온 인용이면 스포일러 수준과 비교해 빼거나 고객 확인 |

이 단계가 수동으로 가장 실수하기 쉬운 곳이다. 제품에서는 `api/app/ai/products/trailer/quotes.py`(TR-06-023)가 자동으로 한다. 주문마다 "AI가 낸 인용 중 원고와 달랐던 수"를 작업 기록표에 적으면 그 기능의 우선순위 근거가 된다.

## 6. 4단계: 스토리보드 프롬프트

```
선택한 브리프(아래)로 {길이}초 {포맷} 북트레일러 스토리보드를 만들어 줘.
문법: {문법 코드}. 비트와 비중은 아래 표를 따른다.

{08_DESIGN_SYSTEM.md 6장에서 고른 문법 행 붙여넣기}

각 장면을 아래 JSON 배열로 출력한다. 마지막 장면은 엔드카드(kind "end_card": 표지, 제목, 저자, 구매 안내 한 줄)로 고정.
{
  "kind": "title_card | hook_text | quote_card | image_scene | character_scene | narration_card | cta_card | end_card",
  "duration_ms": 숫자,
  "text": "화면 문구 160자 이하",
  "narration": "내레이션 400자 이하(없으면 빈 문자열)",
  "quote_chapter": 인용이면 장 번호,
  "visual": { "prompt_ko": "그림 설명(한국어)", "motion": "ken_burns_in | ken_burns_out | pan_left | pan_right | parallax | still | type_reveal | page_turn" },
  "music_cue": "intro | build | drop | calm | outro"
}

규칙:
- 첫 장면은 2초 안에 글자 또는 인물이 보이게(hook_text 권장).
- 화면 문구 노출 시간 duration_ms ≥ 1200 + 글자 수 × 60.
- 장면 길이 합계는 {길이}초의 ±10% 안.
- 인용은 브리프의 검증된 quotes에서만 가져오고 글자를 바꾸지 않는다.
- 인물은 실루엣·뒷모습·손·소품으로 묘사하고 얼굴 클로즈업을 만들지 않는다.
- 내레이션은 한 사람 목소리로 읽는다고 가정하고 톤은 {문법의 내레이션 톤}.
```

같은 구성을 9:16과 16:9에 쓰고, 표지 루프는 표지 + 제목 문구 1개(5~8초)로 따로 만든다.

## 7. 5~6단계: 이미지와 내레이션

이미지 프롬프트 만들기:

```
아래 장면 그림 설명을 영어 이미지 프롬프트로 바꿔 줘. 장면마다 한 줄.
끝에 스타일 접미어와 색, 금지 접미어를 그대로 붙인다.

스타일 접미어: {08_DESIGN_SYSTEM.md 8.1절 문법의 프리셋 접미어}
색: color palette: {표지에서 고른 주조색 3개를 색 이름으로}
금지 접미어: no text, no letters, no watermark, no logo, no real person likeness, no celebrity, no specific artist style

{장면별 prompt_ko 목록}
```

| 규칙 | 내용 |
|---|---|
| 스타일 고정 | 한 트레일러 안에서 이미지 도구·모델·스타일 접미어·seed를 바꾸지 않는다(seed를 지원하는 도구면 고정) |
| 비율 | 9:16용은 세로, 16:9용은 가로로 따로 만들거나 넉넉한 크기로 만들어 잘라 쓴다. 글자 넣을 자리(안전 영역)를 비운다 |
| 글자 | 이미지 안에 글자를 만들지 않는다. 글자는 편집 단계에서 넣는다 |
| 검수 | `08_DESIGN_SYSTEM.md` 8.3절 기준표(팔레트, 질감, 인물 일관성, 글자 무늬, 실존 인물·상표) |
| 기록 | 장면별 도구·모델·seed·프롬프트를 작업 기록표에 남긴다(재현과 평가셋용) |

내레이션:

| 규칙 | 내용 |
|---|---|
| 같은 목소리 | 한 트레일러(모든 규격 포함)에 TTS 도구·보이스·속도 설정 하나만 쓴다. 장면 하나를 다시 만들 때도 같은 설정(`02_ARCHITECTURE.md` 5.3절) |
| 고객 목소리 | 고객이 보낸 녹음만 쓴다. 목소리 복제(클론)는 하지 않는다 |
| 라이선스 | TTS 도구의 상업 이용 조건을 확인하고 도구·플랜을 기록 |

## 8. 7단계: 편집·렌더

| 항목 | 값 |
|---|---|
| 규격 | 9:16 1080x1920, 16:9 1920x1080, 1:1 1080x1080, 4:5 1080x1350. 30fps, H.264, AAC 48kHz |
| 안전 영역(글자 위치) | 9:16 위 12%, 아래 22%, 왼쪽 6%, 오른쪽 14% / 16:9 사방 5% / 1:1·4:5 사방 6% |
| 서체 | 무료 상업용 한글 서체(OFL)만. 문법별 서체 짝은 `08_DESIGN_SYSTEM.md` 6장 |
| 음악 | 상업 이용 라이선스를 확인한 곡. 곡명·출처·라이선스 링크를 작업 기록표에 기록. 내레이션 구간은 음악을 약 12dB 낮춘다 |
| 소리 크기 | 약 -14 LUFS로 맞춘다(플랫폼 재생 기준, 제안) |
| 엔드카드 | 표지 + 제목 + 저자 + 구매 안내 한 줄 + "AI 생성 이미지·음성 포함"(이미지만이면 "AI 생성 이미지 포함"). 최소 2초, 배경과 대비가 뚜렷한 색 |
| 자막 | 내레이션을 SRT로 함께 납품(편집 도구의 자동 자막을 원문과 대조해 고침) |

편집 도구는 무엇을 써도 된다. 같은 문법을 2건 이상 만들면 그 구성을 템플릿으로 저장해 두고, 템플릿 수와 재사용 횟수를 작업 기록표에 적는다. 이것이 제품의 템플릿 6종(`trailer.templates`)을 정하는 근거가 된다.

## 9. 8단계: 납품 전 점검표

- [ ] 인용이 모두 원고와 글자 단위로 같다, 1개 80자·합계 300자 이하
- [ ] 결말·반전이 고객이 고른 스포일러 수준을 넘지 않는다
- [ ] 근거 없는 실적·순위·수상, 보장, 가상 후기, 효능 단정, 정가 15% 초과 할인 표현 없음
- [ ] 실존 인물 얼굴·특정 작가 화풍·타사 로고 없음
- [ ] 엔드카드 AI 표시가 있고 2초 이상 보인다
- [ ] 모든 장면이 같은 목소리, 같은 이미지 스타일
- [ ] 글자가 안전 영역 안, 첫 2초 안에 글자 또는 인물
- [ ] 화면 문구마다 노출 시간 = 1.2초 + 글자당 0.06초 이상
- [ ] 음악·서체·TTS 라이선스 기록 완료
- [ ] 파일 이름: `<책 제목>_<규격>_v<번호>.mp4`, 포스터 PNG, SRT

## 10. 9단계: 납품과 메타데이터

메타데이터 프롬프트:

```
아래 트레일러의 플랫폼별 게시 문구를 만들어 줘: 유튜브 쇼츠, 유튜브, 인스타그램, 네이버 클립.
각 플랫폼마다 제목(40자 이하), 설명(3줄), 해시태그 5개.
설명 끝줄에 "이 영상은 AI 도구로 제작되었습니다"를 넣는다.
구매 링크 자리는 {링크}로 둔다. 실적·할인·보장 표현은 쓰지 않는다.

책: {제목}, {저자}. 로그라인: {logline}. 훅: {hook}.
```

| 항목 | 내용 |
|---|---|
| 납품물 | 영상(규격별), 포스터 PNG(제목 장면), SRT, 게시 문구(txt), PREMIUM은 클릭 측정 링크 |
| 클릭 측정(PREMIUM) | 개발 전에는 무료 단축 링크 서비스의 클릭 통계를 쓴다. 영상·플랫폼마다 링크를 따로 만들어 1개월 뒤 리포트 |
| 인터뷰 요청 | 납품 메시지에 15분 인터뷰 요청(`04_INTAKE_AND_INTERVIEW.md` 3장)과 평가셋 사용 동의 질문을 함께 보낸다 |
